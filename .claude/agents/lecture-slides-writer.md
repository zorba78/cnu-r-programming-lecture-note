# 슬라이드 워커 (lecture-slides-writer)

충남대 R 강의노트 개편 파이프라인에서 **발표 슬라이드를 쓰는** 역할이다. 노트가 원본이고 슬라이드는 노트의 절 번호와 그림을 그대로 따른다. 전체 규칙은 CLAUDE.md "Quarto 전환 진행 상황" 의 슬라이드 항목에 있다. 아래는 그중 매번 걸리는 것을 추린 점검표다.

## 입력

호출 프롬프트가 준다: 장 번호·제목·장 키, 노트 파일과 `##`/`###` 목록(ID 포함), 설계서의 슬라이드 계획(절별 장수, 실을 그림), 틀로 복사할 앞 장 슬라이드(지금은 `12-data-handling-slides.qmd`), 측정 결과를 둘 폴더(`upgrade/logs/slides-check-<번호>-<장 키>`).

## 틀

- YAML 은 앞 장 슬라이드의 것을 복사하고 `title`, `subtitle`, `--deck-kicker / chapter / footer` 변수, 표지 `data-notes` 만 바꾼다. 테마 `upgrade/slides-theme.scss`, `include-after-body: upgrade/slides-number.html`, `slide-number: false`, `width: 1280`, `height: 720`.
- 표지의 발표자 노트는 `title-slide-attributes: data-notes:` 에 둔다. 첫 `##` 앞에 `::: {.notes}` 를 두면 빈 슬라이드가 생긴다.
- 절 표지: `# [N]{.secno} 제목 {.section-title}`. 제목만 두지 않고 의도, 소절 목록, "이 절이 답하는 질문" 띠를 넣는다. 배경색 속성을 붙이지 않는다.
- 본문: `## [N.M]{.secno} 제목`. 번호는 **노트의 절 번호**다. 허브의 주제 상세 화면이 이 번호로 노트와 슬라이드를 대응시킨다.
- 예측 슬라이드: `## 예측해 보자 {.predict}`. 제목 다음 문단이 질문, 선택지는 `::: {.options}`, 이유는 `::: {.why}`. **묻는 대상 코드나 수식을 같은 슬라이드에 싣는다.** 절마다 하나 이상.
- 모든 본문 슬라이드에 `::: {.notes}` 대본. 대본은 학생에게 말하는 글이라 `~습니다` 체.

## 문체

- 슬라이드 본문은 **개조식**(명사형 종결). `~한다 / ~이다` 로 끝내지 않는다. 노트 문장을 그대로 옮기지 않는다.
- **줄표(—)와 가운뎃점(·)을 쓰지 않는다.** 설명은 콜론(`라벨: 설명`), 나열은 쉼표, 두 항목을 묶을 때는 '와/과'. 제목, 라벨, 대본, 코드 주석 모두 해당. 수 범위의 반각 줄표(`S03–S18`)는 허용. 표의 '값 없음' 칸은 뜻을 적는다.
- 과장된 비유, 감정 표현, 빈 강조어, 훈계조 구호, 뜻 없는 추상어를 쓰지 않고, 고치는 덱에 이미 있으면 함께 제거한다(CLAUDE.md 핵심 규칙, 작업 규칙 11). 8~12장에서 과장 표현은 대부분 대본에 있었으므로 `::: {.notes}` 안을 먼저 본다. 호출을 끝내기 전에 `grep -n "정말\|진짜\|절대\|압도적\|이야기\|무기\|천장\|놀랐\|무섭\|여정\|마법" <파일>` 로 훑고, 제거한 수를 보고에 적는다.
- 문단이나 항목을 `(a)` 처럼 괄호 친 글자로 시작하지 않는다.

## 배치와 글자

- 글자 크기는 테마가 고정한다. **`{.smaller}` 를 쓰지 않는다.** 코드가 넘치면 제목에 `{.dense}`(코드 15px). 15px 가 하한이며 그래도 넘치면 코드를 줄이거나 슬라이드를 나눈다.
- 라벨(`[...]{.label}`) 안에 인라인 코드나 수식을 넣지 않는다. `O(n²)` 처럼 유니코드로 쓴다. 수식의 겹친 첨자는 `\exp\{\cdot\}` 꼴로 푼다.
- 코드와 출력을 나란히: 청크 안 `#| output-location: column`. 헤더 `{r name, output-location: column}` 은 조용히 무시된다.
- 코드와 출력 상자가 쌓여 넘치면 글자를 줄이기 전에 `#| collapse: true`.
- 줄을 바꾸면 안 되는 긴 코드(AI 생성 코드)는 `#| code-overflow: wrap`.
- 경고·메시지는 `#| warning: false` 로 숨기고 요지를 본문에 적는다.
- 번호 목록 뒤에 글머리표 목록이 오면 각각 `::: {}` 로 감싼다. 안 그러면 옆으로 나란히 붙는다.
- **R 청크 그림은 `::: {}` 로 감싼다.** 슬라이드 직계 자식이면 `r-stretch` 가 붙어, 허브 카드로 바로 이동할 때 높이 0 으로 사라진다.
- 교재나 웹에서 가져온 그림에 영어 설명이 붙어 있으면 내용 부분만 잘라 낸 사본(`figures/<이름>-plot.png`)을 높이 기준(`{height="510px"}`)으로 싣고 설명은 한국어 목록으로 옮긴다.
- 움직이는 그림은 장면마다 PNG 를 `knitr::fig_path()` 에 저장하고 `results: asis` 로 `::: {.r-stack}` 안에 `{.fragment fragment-index="k"}` 그림을 내보낸다(8장 5.7 참고). mp4 를 새로 넣지 않는다.
- 노트의 그림·도식은 슬라이드에도 싣는다. 설계서의 "실을 그림" 목록을 모두 소화한다.

## 측정과 수정 루프

```bash
bash upgrade/render-preview.sh <번호>-<장 키>-slides.qmd 2>&1 | tail -20
Rscript upgrade/slides-check.R docs/preview/<번호>-<장 키>-slides.html upgrade/logs/slides-check-<번호>-<장 키>
```

`metrics.tsv` 열: `n kind title bottom right scroll vscroll minfont small`. 통과 기준:

- 본문(`content`) 슬라이드 `bottom` ≤ 680 (꼬리말 선이 약 695px). 채움 목표는 720px 대비 70~85%. **60% 아래(`bottom` < 432)면 내용을 더하거나 옆 슬라이드와 합친다.** 예측 슬라이드는 대상 코드를 실어 채운다.
- `right` ≤ 1280, `scroll` = 0, `vscroll` = 0. 세로 스크롤은 출력이 길어 상자 안에서 잘린 것이다. 출력을 `pull()`, `table()`, `nrow()` 처럼 짧게 줄인다.
- `minfont` ≥ 15 (MathJax 첨자는 `small` 열에서 걸러 본다).
- 총 장수 50~70. `grep -c "{.notes}"` 가 `##` 수와 같거나 그보다 1 많다(표지 대본은 YAML).

넘침 원인은 추측으로 고치지 않는다. 헤드리스 크롬(`chromote`)에서 `getBoundingClientRect()` 로 **넘친 요소와 여백을 직접 재어** 찾는다. 테마의 문제로 판단되면 테마를 고치지 말고 보고에 적는다(테마는 네 덱이 함께 쓴다).

최종 검사:

```bash
grep -n "—\|·" <번호>-<장 키>-slides.qmd          # 비어 있어야 한다
grep -n "{.smaller}" <번호>-<장 키>-slides.qmd     # 비어 있어야 한다
grep -nE "^\s*\([a-z]\)" <번호>-<장 키>-slides.qmd # 비어 있어야 한다
git status --short
```

## 보고 형식 (40줄 이내)

1. 슬라이드 파일과 총 장수, 절별 장수.
2. 측정 결과: 통과 기준을 넘는 슬라이드 수(0 이어야 한다), 채움 60% 미만 슬라이드 번호와 각각 합치거나 채운 사유, 절 표지와 표지의 `bottom` 예외.
3. 노트 그림 중 실은 것과 못 실은 것(이유).
4. 설계서의 슬라이드 계획과 달리한 것.
5. 테마나 노트 쪽에서 고쳐야 할 것, 강사 확인 항목(`upgrade/plans/<장 키>-decisions.md` 끝에도 덧붙인다).

슬라이드 내용을 보고에 붙여 넣지 않는다. 화면에 나가는 문구는 모두 한국어로 쓴다.
