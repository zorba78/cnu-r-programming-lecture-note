# AI 시대 교과 설계 (ai-curriculum)

대상: 충남대 정보통계학과 **학부 2학년**. 선수과목 통계학개론. 학생 대부분이 ChatGPT/Claude/Copilot 를 이미 쓰고, **대부분이 이 강의로 프로그래밍에 입문한다.** 이 두 사실이 설계의 전제다.

전체 재구성안은 `upgrade/curriculum-plan.md` 에 있다. 장 구성을 건드리기 전에 읽는다.

## 1. 학습 목표 재정의

기존 목표(문법 습득, 프로그래밍 능력, 시뮬레이션, 재현 가능 문서)를 유지하되 각 장의 목표를 다음 동사로 다시 쓴다.

| 기존 (기억·이해·적용) | 개편 (명세·검증·해석) |
|---|---|
| `for` 문을 작성할 수 있다 | 반복 작업을 자연어 명세로 쓰고, 생성된 `for`/`map()` 코드가 명세와 일치하는지 검증할 수 있다 |
| `dplyr` 동사를 사용할 수 있다 | 데이터 변환 결과가 맞는지 행 수·요약값·반례로 확인하는 절차를 설계할 수 있다 |
| t-검정을 실행할 수 있다 | 검정 가정을 시뮬레이션으로 확인하고, AI 가 제안한 분석의 통계적 타당성을 판단할 수 있다 |

원칙: **AI 가 대신할 수 있는 것은 압축, AI 출력을 판단하는 데 필요한 것은 유지·강화.** 기초 문법 장(02, 05)은 분량을 줄이되 "읽기" 연습(코드를 보고 결과 예측)을 늘린다.

## 2. "AI와 함께" 절 템플릿

모든 장 끝(연습문제 앞)에 하나씩. 헤딩 ID 는 `ai-<chapter-id>`.

```markdown
## AI와 함께: <이 장 주제로 할 작업> {#ai-<chapter-id>}

```{block2, type="rmdimportant"}
**이 절의 목표**: AI 에게 <작업>을 시키고, 결과를 <검증 방법>으로 확인한다.
```

### 과제 명세

<학생이 AI 에게 요청할 작업을 한국어로 3~5줄. 입력 데이터, 원하는 출력, 제약 조건을 명시>

### 프롬프트

```{block2, type="rmdnote"}
<실제 사용한 프롬프트 전문>
```

### AI 가 생성한 코드

```{r ai-<chapter-id>-gen, eval=FALSE}
# 생성: <모델명>, <YYYY-MM-DD>. 수정 없이 그대로 실은 코드.
<생성 코드>
```

### 검증

<다음 중 2개 이상>
1. 결과 예측: 실행 전에 기대 출력을 적고 비교
2. 작은 예제: 손으로 계산 가능한 3~5행 데이터로 실행
3. 반례: 결측·중복·빈 입력을 넣어 동작 확인
4. 시뮬레이션: 알려진 답이 있는 데이터를 생성해 비교 (07장 방식)
5. 대안 구현과 비교: base R 과 tidyverse 로 각각 구현해 `identical()`/`all.equal()`

```{r ai-<chapter-id>-verify}
<검증 코드: 실제로 실행되고 렌더됨>
```

### 흔한 오류

```{block2, type="rmdcaution"}
- <이 작업에서 LLM 이 자주 틀리는 패턴 1: 예) group_by 후 ungroup 누락>
- <패턴 2>
```

### 연습

1. 프롬프트를 바꿔 <변형>을 요청하고 같은 검증을 수행하시오.
2. 생성 코드에서 일부러 버그를 하나 넣고 짝이 찾도록 하시오.
```

## 3. LLM 응답 기록 규칙 (필수)

- **지어내지 않는다.** 강의노트에 싣는 AI 응답·코드는 실제로 모델에서 받은 것이어야 한다. 얻을 수 없으면 그 절을 쓰지 않거나 "직접 실행해 보자" 로 바꾼다.
- 생성 코드 청크 첫 줄에 `# 생성: <모델명>, <날짜>` 를 적는다. 사후 수정했으면 `# 수정: <무엇을>` 추가.
- 렌더 중 API 호출 금지. 생성 코드는 `eval=FALSE`, 검증 코드는 실행. LLM 을 R 에서 호출하는 예시(ellmer)는 `eval=FALSE` 로 두고 응답은 텍스트로 싣는다.
- 긴 대화 기록은 `ai-transcripts/<장>/<slug>.md` 에 저장하고 본문에는 요약만. 파일 머리에 모델, 날짜, 프롬프트 전문.
- API 키는 `.Renviron` (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) 에 두고 코드에 쓰지 않는다. `.Renviron` 은 커밋 금지 (`.gitignore` 확인).
- 학생에게: 개인정보·미공개 연구 데이터를 프롬프트에 넣지 않도록 안내하는 콜아웃(`rmdwarning`)을 관련 절에 넣는다.

## 4. 신규 장 (2026-09-10 강사 결정)

전체 재구성안은 **`upgrade/curriculum-plan.md`** 에 있다. 장 구성을 건드리기 전에 반드시 읽는다. 신규 장은 세 개다.

### 4a. 프로그래밍과 계산 (Part 1 첫 장, 현 01장 흡수)
- 계산이란 무엇인가: 입력 → 처리 → 출력. **AI가 코드를 쓰는 시대에 왜 프로그래밍을 배우는가**를 정면으로 다룬다.
- 값·이름·할당의 개념 모형. 평가 순서. 오류의 세 종류(문법·실행·논리).
- 도구 셋업: R, Positron(권장)/RStudio, Quarto. 스크린샷은 2026년 버전.
- 이 강의의 AI 사용 규칙: 허용, 단 (1) 프롬프트와 출력을 기록 (2) 검증 없이 제출 금지 (3) 설명 요구 시 답할 수 있어야 함.
- 첫 실습은 반드시 **예측-실행-대조**로. 이 장에서 습관을 만든다.

### 4b. 정확성·디버깅·검증 (Part 1, 독립 6장 — 함수 장에 부속시키지 않음)

**독립 장으로 두는 근거 (강사, 2026-09-10)**: "LLM을 통해 디버깅 작업을 예전에 비해 매우 효율적으로 수행할 수 있으나 결국 중요한 부분은 인간이 다시 한 번 확인하는 절차가 중요해짐." 이 장의 무게중심은 디버깅 기법 나열이 아니라 **AI가 빨라진 디버깅의 결과를 사람이 재확인하는 절차** 그 자체다. 함수 장(5장)의 부속 절로 두면 이 비중이 죽으므로 독립시킨다. 현재 노트에 사실상 없는 영역이기도 하다(디버깅 언급 2회, `traceback`/`tryCatch`/`testthat` 0회).

- 예측-대조를 방법론으로 정식화. 경계 사례와 반례 만들기.
- 오류 메시지 읽는 법. 최소 재현 예제(minimal reproducible example) 만들기.
- `traceback()`, `browser()`, `tryCatch()` — 이 장에서 가르치는 도구는 일반 디버깅 기법이지만, 최종 활동은 **AI가 제안한 수정이 실제로 문제를 고쳤는지 재확인하는 절차**로 맺는다. "AI가 원인이라고 말한 지점이 진짜 원인인가?" "AI의 수정이 다른 경계 사례를 깨뜨리지는 않는가?"를 이 장의 도구로 직접 검증한다.
- `testthat` 맛보기: `expect_equal()` 수준. 함수를 만들면 테스트도 만든다는 습관 — AI가 만든 함수도 예외가 아니다.
- 시뮬레이션 기반 검증은 시뮬레이션 장과 상호참조.
- 4c(AI와 함께 프로그래밍하기)는 이 장에서 만든 재확인 습관을 LLM 프롬프트·응답 맥락에 적용하는 장이다. 순서가 중요하다: 검증 절차를 먼저 몸에 익히고(6장), 그다음 AI 협업에 적용한다(4c/16장).

### 4c. AI와 함께 프로그래밍하기 (Part 2 마지막 장)
- 명세 쓰기: 자연어로 입력·출력·제약을 적는 연습. 프롬프트는 명세다.
- `ellmer::chat_anthropic()` / `chat_openai()` 기본 사용, 시스템 프롬프트.
- 구조화 출력(`chat_structured()` + `type_object()`): 자유 텍스트 → 데이터 프레임. 정보통계 맥락 예로 기존 `dataset/news-scraping.csv` 재사용.
- 도구 호출(`tool()`): LLM 이 R 함수를 호출하게 하기.
- 비결정성과 재현성: `set.seed()` 가 통하지 않는 세계에서 재현성을 어떻게 확보하는가(응답 저장, 모델·날짜 기록).
- "AI 코드 버그 찾기" 실습 5~10개. 실제 LLM 출력에서 수집한 것만 사용한다.
- 모든 API 예시는 `eval=FALSE` + 저장된 응답 텍스트.

**만들지 않는 장**: Quarto·git·renv 워크플로. 강의 범위 밖(강사 결정). 단 Quarto 문서 작성 자체는 기존 13장을 전환해 유지한다.

## 5. 기존 장 개편 방향

장별 처리 방침은 `upgrade/curriculum-plan.md` 5절의 대응표를 따른다. 여기서는 모든 장에 공통으로 적용하는 동작만 적는다.

**기본 동작: 청크 순서를 뒤집는다.** 기존 노트의 청크는 대부분 "코드 → 출력 → 설명" 이다. 이를 다음으로 바꾼다.

```markdown
### 절 제목 {#sec-id}

<개념 설명. "왜"가 먼저>

```{block2, type="rmdtip"}
**예측해 보자**: 아래 코드의 출력은 무엇일까? 실행하기 전에 적어 보자.
```

```{r ex-label, eval=FALSE}
<코드만, 출력 없이>
```

<잠깐 여백 또는 접힌 영역>

```{r ex-label-run, echo=FALSE}
<같은 코드를 실행해 출력>
```

<왜 그런 결과가 나오는지 설명. 흔한 오해를 rmdcaution 으로>
```

**사전형 내용은 부록으로 내린다.** 삭제가 아니라 이동이다. 문자열 함수 목록, `par()` 파라미터 전수, 청크 옵션 전수, dplyr 동사 사전이 대상이다. 본문에는 대표 함수 3~5개와 참조표 링크만 남긴다.

**읽기 문항을 넣는다.** 연습문제를 쓰기 문항으로만 채우지 않는다. 코드를 주고 결과를 예측하게 하거나, 틀린 코드의 이유를 설명하게 하는 문항을 절반 가까이 둔다. 2학년 입문자가 실제로 가장 많이 하는 행위가 코드 읽기이기 때문이다.

## 6. 톤

- AI 는 "빠르지만 검증이 필요한 조수". 과장도 폄하도 하지 않는다.
- 학생이 AI 없이 문제를 풀 수 있어야 한다고 강요하지 않는다. 대신 AI 출력을 판단할 수 있어야 한다고 요구한다.
- 특정 상용 도구 이름은 예시로만. 도구는 매년 바뀌므로 "2026년 기준" 을 명시한다.
