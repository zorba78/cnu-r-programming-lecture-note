전화번호부에서 이름을 찾는 일로 시작합니다.

전화번호부는 이름과 전화번호를 가나다순으로 인쇄한 책으로, 스마트폰 이전에는 집마다 한 권씩 있었습니다. 1,000쪽짜리 전화번호부에서 ’이아무개’를 찾는다고 해 봅시다.

방법 A는 첫 쪽부터 한 쪽씩 넘기는 겁니다. 이름이 책에 있으면 반드시 찾습니다. 다만 이름이 마지막 쪽에 있으면 1,000쪽을 다 봐야 합니다.

방법 B는 가운데를 펼치는 겁니다. 펼친 쪽에 ’박’씨가 나오면, ’이’는 그보다 뒤에 있으니까 앞쪽 절반은 볼 필요가 없지요. 남은 뒤쪽 절반의 가운데를 또 펼칩니다. 이렇게 하면 1,000쪽이라도 열 번 안쪽에서 끝납니다.

방법 A와 B처럼 정해 둔 순서대로 따라 하면 결과가 나오는 절차를 알고리즘이라고 부릅니다.

이 예에서 볼 점은 두 가지입니다. 첫째, 두 방법은 같은 쪽을 찾고, 확인하는 쪽수만 다릅니다. 최악의 경우 방법 A 는 1,000번, 방법 B 는 10번입니다. 1절은 이 확인 횟수를 연산 횟수로 세어 비교하는 방법을 다룹니다.

둘째, 방법 B는 이름이 가나다순으로 정렬되어 있어야 쓸 수 있습니다. 동아리 가입 순서대로 적은 명단이라면 펼친 쪽의 이름과 비교해도 찾는 이름이 앞쪽에 있는지 뒤쪽에 있는지 알 수 없으므로 방법 B를 못 씁니다. 3절 이진 탐색에도 벡터가 정렬되어 있어야 한다는 조건이 붙습니다.

실제로 사람은 가운데가 아니라 ’ㅇ’이 있을 만한 뒤쪽을 짐작해서 펼칩니다. 찾는 값의 크기로 위치를 짐작해 펼치는 이 방법은 보간 탐색이라는 별도의 알고리즘입니다.

half_count <- function(pages) {
  count <- 0
  while (pages > 1) {
    pages <- ceiling(pages / 2)   # 없는 쪽 절반을 버림

  count
}

방법 A는 어떨까요? 쪽수만큼, 그러니까 1,000번, 10,000번, 100만 번입니다. 1.4절에서 두 방법의 증가 양상을 빅오 표기법으로 적습니다. 방법 A 는 O(n), 방법 B 는 O(log n) 입니다.

“방을 깨끗이 청소해”: 로봇에게는 정해지지 않은 항목 셋

  • 어디서 시작?

로봇에게 주는 약속된 절차

  1. 방을 칸으로 나누고 왼쪽 위에서 시작
  2. 한 줄 끝까지 이동하며 청소
  3. 줄 끝에서 아래로 한 칸, 방향 반대로
  4. 마지막 칸을 청소하면 멈춤
clean_room <- function(n_row, n_col) {
  visit <- matrix(0L, n_row, n_col)  # 청소 순서
  step <- 0L
  for (i in seq_len(n_row)) {          # 1. 한 줄씩
    cols <- seq_len(n_col)
    if (i %% 2 == 0) cols <- rev(cols) # 3. 방향 반대로
    for (j in cols) {                  # 2. 줄 끝까지
      step <- step + 1L
      visit[i, j] <- step
    }
  }
  visit                                # 4. 멈춤
}

두 번째 예입니다. 청소 로봇을 샀다고 해 봅시다. 사람은 “방 좀 깨끗이 치워”라는 말만 듣고도 청소를 합니다. 로봇에게 이 말은 절차가 아닙니다.

어디서 시작하는지, 깨끗이는 어느 정도인지, 언제 멈추는지가 정해져 있지 않습니다. 사람은 이 세 가지를 경험으로 정합니다. 로봇에게는 시작 위치, 청소 범위, 멈추는 시점을 모두 정해 둔 절차를 주어야 합니다.

왼쪽 아래 네 단계가 그 절차입니다. 방을 칸으로 나누고, 한 줄씩 지그재그로 갑니다. 잔디 깎는 기계가 움직이는 방식이에요.

오른쪽은 그 네 단계를 R로 옮긴 겁니다. 주석의 번호가 왼쪽 단계 번호와 같습니다. for 반복문 두 개와 if 문 하나로 씁니다. 결과 행렬의 숫자가 각 칸을 몇 번째로 청소했는지입니다. 둘째 줄은 오른쪽 끝에서 7번으로 시작해서 왼쪽으로 갑니다.

방 한가운데에 소파가 있으면, 소파가 놓인 칸에서 로봇은 무엇을 합니까? (잠시 기다린 뒤) 이 절차에는 정해져 있지 않습니다. 다음 슬라이드의 일반성 조건이 가구가 놓인 방을 다룹니다.

청소 로봇 예를 알고리즘의 정의와 다섯 조건으로 정리합니다.

알고리즘은 문제를 풀기 위한 단계와 그 순서를 미리 정해 둔 절차입니다. 상자의 ’약속된’은 이 뜻입니다. 단계가 정해져 있으므로 같은 입력이면 사람이 실행하든 로봇이나 컴퓨터가 실행하든 결과가 같습니다.

표의 오른쪽 칸은 각 조건을 청소 로봇에 대응시킨 것입니다. 앞의 세 조건은 명확성, 유일성, 입력과 출력으로, 각 단계가 모호하지 않고, 다음 단계가 하나로 정해지고, 정의된 입력을 받아 결과를 낸다는 뜻입니다. 청소 로봇의 절차는 “깨끗이” 대신 “모든 칸을 한 번씩”을 쓰고, 줄 끝에서 할 일이 하나뿐이고, 가로와 세로 칸 수를 받아 칸별 청소 순서를 내므로 세 조건을 만족합니다.

이 장의 코드가 어기는 것은 뒤의 두 조건입니다. 유한성은 유한한 단계 뒤에 반드시 멈춰야 한다는 조건입니다. “깨끗해질 때까지 청소해”라고 정하면, 먼지 센서 값이 0이 되지 않는 한 로봇은 멈추지 않습니다.

일반성은 정의된 입력 전체에서 동작해야 한다는 겁니다. 우리 로봇은 크기가 다른 방에서도 모든 칸을 한 번씩 청소합니다. 그런데 소파가 놓인 방은 다루지 못합니다. 우리 절차에는 가구라는 입력이 없습니다. 만든 사람이 떠올리지 못한 입력이지요. 이 장의 코드에서는 3절 이진 탐색에서 탐색 범위에 원소가 하나만 남은 경우가 이런 입력입니다.

청소 로봇의 “가구 놓인 방”과 같은 문제: 코드를 만든 사람이 떠올리지 못한 입력

이 장에는 이 두 조건을 어기는 코드가 하나씩 나옵니다.

왼쪽은 유한성 위반입니다. 1부터 n까지 더하는 재귀 함수인데, n이 0이면 종료 조건을 지나쳐 내려가서 멈추지 않습니다. 오늘 2절에서 직접 보여 드리겠습니다.

오른쪽은 일반성 위반입니다. 예제 한두 개에서 정답이 나왔다는 것은 그 예제에서 동작한다는 뜻이고, 정의된 입력 전체에서 동작한다는 뜻은 아닙니다. 청소 로봇에게 소파 놓인 방이 그랬듯, 이 코드도 만든 사람이 떠올리지 못한 입력에서 틀립니다. 탐색 범위에 원소가 하나 남으면 그 원소를 확인하지 않고 NA 를 돌려줍니다.

3절에서 이 함수에 벡터의 모든 원소를 넣어 20개 중 8개를 못 찾는 것을 확인하고, 6절에서 같은 검사를 AI 코드에 적용합니다.

  • 연산 횟수는 입력이 같으면 항상 같은 값

메모리

  • 재는 단위: 동시에 확보해야 하는 공간의 크기
  • 변수, 자료 구조, 호출 스택 프레임
  • 재귀 깊이가 여기에 직접 들어감

“이 코드가 비싸다” = “연산 횟수가 많다” 또는 “메모리를 많이 잡는다”
둘 중 어느 쪽인지 항상 구분해서 말할 것

이 수업에서 비용은 알고리즘이 요구하는 수행 시간과 메모리, 두 가지를 합쳐 부르는 말입니다.

수행 시간은 초가 아니라 연산 횟수로 잽니다. 초시계로 잰 초는 같은 코드라도 여러분 노트북과 제 노트북에서 다르고, 같은 노트북에서도 함께 실행 중인 다른 프로그램에 따라 달라집니다. 사칙연산, 비교, 반복, 함수 호출의 횟수는 입력이 같으면 어느 기기에서 세어도 같은 값입니다.

메모리는 실행 중에 동시에 확보해야 하는 공간의 크기입니다. 변수, 자료 구조, 호출 스택 프레임이 여기에 들어갑니다. 2절의 재귀는 호출할 때마다 호출 스택에 프레임을 하나씩 쌓으므로, 호출 깊이에 비례해 메모리를 씁니다.

맨 아래 상자입니다. “이 코드가 비싸다”는 말을 들으면 연산 횟수가 많다는 뜻인지 메모리를 많이 잡는다는 뜻인지 확인합니다. 한쪽을 줄이면 다른 쪽이 늘기도 합니다. 4절의 병합 정렬은 비교 횟수를 n log n 수준으로 줄이는 대신 길이 n 의 임시 벡터만큼 메모리를 더 씁니다.

가운데 표를 보세요. 프로그램 1은 시간이 n에 비례하고, 처음에 길이 n 의 벡터를 한 번 확보한 뒤로 메모리가 늘지 않습니다. 프로그램 2는 시간이 n 제곱에 비례하고, 반복마다 길이가 1, 2, …, n 인 벡터를 새로 할당합니다. 시간은 n 대 n² 으로 차수가 다르고, 메모리는 프로그램 2만 반복마다 새로 할당합니다.

최선의 경우는 선형 탐색에서 찾는 값이 첫 원소일 때처럼 특정 입력에서만 성립합니다. 다른 입력에서는 그 횟수를 넘습니다. 평균은 입력이 어떤 분포로 들어오는지 가정해야 구할 수 있고, 가정이 틀리면 평균도 틀립니다. 최악의 경우의 연산 횟수는 어떤 입력에서도 넘지 않는 상한입니다.

그래서 이 장에서는 알고리즘을 최악의 경우로 비교합니다.

1.4 빅오 표기법

노트

정의: 상수 \(C\), \(k\) 가 존재해
\(x \geq k\) 인 모든 \(x\) 에서 \(|f(x)| \leq C|g(x)|\)

\(\Rightarrow\) \(f(x) = \mathcal{O}(g(x))\), “\(f\) 는 \(g\) 의 빅오”

그림 읽기

  • \(f(x)\): 알고리즘의 실제 연산 횟수
  • \(Cg(x)\): 기준 함수 \(g\) 에 상수 \(C\) 를 곱한 선
  • \(k\) 이후 (파란 구간): \(f(x)\) 가 \(Cg(x)\) 아래에 머묾
  • \(k\) 이전: \(f(x)\) 가 위에 있어도 무관

\(n\) 이 충분히 커지면 저차항의 비중이 0 에 수렴, 증가율이 가장 큰 항만 남음

\(g\) 는 \(f\) 의 점근적 상한

빅오 표기법입니다. 정의부터 보시죠.

오른쪽 그림이 이 정의를 그린 것입니다. 그림은 johngrib.github.io 의 빅오 표기법 글에서 가져왔습니다.

끝이 파랗게 칠해진 곡선이 f(x), 우리가 재려는 알고리즘의 실제 연산 횟수입니다. 그 위로 가장 가파르게 올라가는 검은 선이 Cg(x), 우리가 고른 기준 함수 g 에 상수 C 를 곱한 겁니다. 맨 아래 선이 g(x) 자체입니다. g 는 f 보다 낮아도 됩니다. 상수 C 를 곱해 위로 올리면 되니까요.

x축의 k 지점을 보세요. 두 곡선이 거기서 만나고, 그 뒤로는 f(x) 가 Cg(x) 아래에 있습니다. 파랗게 칠한 부분이 그 구간입니다. k 이후의 모든 x 에서 f(x) ≤ Cg(x) 이면 “f는 g의 빅오다” 라고 하고, Cg(x) 를 f(x) 의 상한이라고 부릅니다. k 앞에서는 f(x) 가 Cg(x) 보다 위에 있어도 정의에 영향이 없습니다.

정의에는 “x가 k보다 클 때” 라는 조건이 붙습니다. k보다 작은 구간은 따지지 않습니다. n이 10이면 n² 은 100번, n log₂n 은 약 33번이라 차이가 67번이고, n이 백만이면 두 슬라이드 뒤의 표처럼 초당 10억 연산 기준 0.02초와 약 17분으로 벌어집니다. 그래서 빅오는 n 이 k 보다 클 때의 증가 양상만 봅니다. 저차항을 버리는 이유도 같습니다. n² + n 에서 n 의 비중은 n 이 백만이면 약 백만분의 일입니다.

1.4 실제로 쓰는 것은 세 규칙

규칙 1, 계수 법칙

계수 소거

\(\mathcal{O}(5n) = \mathcal{O}(n)\)

반복이 \(5n\) 번이든 \(100n\) 번이든 모두 \(\mathcal{O}(n)\)

규칙 2, 합의 법칙

순차 실행 시 증가율이 큰 쪽만 잔존

\(\mathcal{O}(n) + \mathcal{O}(n^2) = \mathcal{O}(n^2)\)

단, 입력 변수가 다르면 \(\mathcal{O}(n + m)\)

규칙 3, 곱의 법칙

반복문 중첩 시 반복 횟수 곱

\(\mathcal{O}(n) \times \mathcal{O}(n) = \mathcal{O}(n^2)\)

case1 <- function(n) {              # (가)
  s <- 0; for (i in seq_len(n)) s <- s + i; s
}
case2 <- function(n) {              # (나)
  s <- 0; for (i in seq_len(5 * n)) s <- s + i; s
}
case3 <- function(n, m) {           # (다)
  s <- 0
  for (i in seq_len(n)) s <- s + i
  for (j in seq_len(m)) s <- s + j
  s
}
case4 <- function(n) {              # (라)
  s <- 0; for (i in seq_len(n)) for (j in seq_len(n)) s <- s + j; s
}

(가) \(\mathcal{O}(n)\)

(나) \(\mathcal{O}(5n) = \mathcal{O}(n)\): 규칙 1

(다) \(\mathcal{O}(n + m)\): 규칙 2의 단서

(라) \(\mathcal{O}(n^2)\): 규칙 3

코드 읽을 때 쓰는 것은 정의가 아니라 이 세 규칙: 반복이 몇 번 도는지만 세면 됨

코드를 읽고 차수를 정할 때는 정의 대신 이 세 규칙을 씁니다.

규칙 1. 계수는 버립니다. 반복을 5n번 돌든 100n번 돌든 O(n)입니다. 정의에서 상수 C 를 100 으로 잡으면 100n ≤ Cn 이 성립하기 때문입니다. 5n 이든 100n 이든 n 이 두 배가 되면 연산 횟수도 두 배가 됩니다.

규칙 2. 두 부분이 이어서 실행되면 증가율이 큰 쪽만 남깁니다. for문 하나 돌고 그다음에 이중 for문 돌면, 앞의 for문의 n 은 차수에 넣지 않습니다. n 이 천이면 n 은 n² 의 천분의 일이고, n 이 커질수록 그 비중은 0 에 가까워지기 때문입니다. 단서가 하나 있습니다. 입력 변수가 다르면 못 합칩니다. n짜리 반복 다음에 m짜리 반복이면 O(n + m)이고, 이건 더 못 줄입니다. n과 m 중 뭐가 큰지 모르니까요.

규칙 3. 중첩되면 곱합니다. n 번 도는 반복 안에 n 번 도는 반복이 있으면 n × n = n² 번이고, n 이 천이면 백만 번입니다.

코드를 읽을 때는 각 반복문이 몇 번 도는지 세고, 이어지면 큰 쪽을, 중첩되면 곱을 취합니다. 오른쪽 (가)부터 (라)까지가 그 예입니다.

컴퓨터를 빠른 것으로 바꿔도 알고리즘의 차수는 그대로입니다. 컴퓨터가 백 배 빨라져도 O(n²)은 여전히 O(n²)입니다. 17분이 10초로 줄 뿐이고, O(n log n)의 0.02초와는 여전히 500배 차이입니다. 컴퓨터가 100배 빨라지는 것은 수행 시간에 상수 100분의 1을 곱하는 것과 같고, 규칙 1에 따라 상수는 차수를 바꾸지 않습니다. n을 10배 키우면 O(n²)의 연산 횟수는 100배가 되어 10초가 다시 17분이 됩니다.

수행 시간을 줄이려면 O(n²) 정렬을 O(n log n) 정렬로 바꾸는 것처럼 차수가 낮은 알고리즘을 씁니다. n 이 백만이면 17분이 0.02초가 됩니다.

1.4 차수의 증가 양상

\(n = 40\) 에서 \(\mathcal{O}(n)\) 은 40, \(\mathcal{O}(n^2)\) 은 1,600: 세로축 상한 200 을 \(n = 15\) 에서 넘음

앞 표의 차수를 n 이 1 부터 40 까지인 구간에서 그림으로 그렸습니다. 가로가 입력 크기, 세로가 연산 횟수입니다.

회색 O(1)은 n 과 관계없이 1 이라 바닥에 붙어 있습니다. 청록색 O(log n)은 n이 40일 때 5.3입니다. 초록색 O(n)은 직선으로 올라갑니다. 노란색 O(n log n)은 n이 38 근처에서 세로축 끝 200을 넘고, n이 40이면 213으로 O(n)의 5.3배입니다. 빨간색 O(n²)은 n이 15일 때 225로 세로축 끝 200을 넘어 그림 밖으로 나가고, n이 40이면 1,600입니다.

이 그림의 가로축은 n이 40까지이고, 앞 표는 n이 백만까지입니다.

n이 백만이면 앞 표처럼 O(n)은 백만 번, O(n²)은 10의 12승 번으로 백만 배 차이입니다.

여기까지가 1절입니다. 잠깐 쉬었다가 재귀로 넘어가겠습니다.

half_count <- function(pages) {
  count <- 0                    # 1.
  while (pages > 1) {           # 2.
    pages <- ceiling(pages / 2) # 3.
    count <- count + 1          # 4.
  }
  count                         # 5.
}

가운데가 2단계 의사코드입니다. 의사코드는 프로그래밍 언어의 문법 없이 절차를 줄 단위로 적은 것입니다. 첫 줄에 함수 이름과 입력, 둘째 줄과 셋째 줄에 입력과 출력이 무엇인지 적고, 그다음이 본문입니다. 줄 앞의 번호가 자연어 절차의 번호입니다. 자연어 2번 “남은 쪽이 1 보다 많은 동안 반복” 이 의사코드 2번 while 줄이 되고, 3번과 4번은 그 안에 들여 쓴 두 줄이 됩니다. 들여쓰기가 “반복하는 동안 할 일” 이라는 뜻입니다.

오른쪽이 3단계 R 코드입니다. 주석 번호가 의사코드 번호와 같습니다. 의사코드 한 줄이 R 한 줄이 됩니다. 의사코드의 들여쓰기는 R 의 중괄호가 되고, 화살표 대입은 R 의 <- 가 되고, “pages / 2 를 올림” 은 ceiling() 이 됩니다.

왼쪽 아래 상자는 의사코드를 거치는 이유입니다. 첫째, 문법을 신경 쓰지 않고 절차만 보므로, 반복이 멈추는지, 빈 벡터 같은 경계 입력에서 어떻게 되는지를 R 로 옮기기 전에 따져 볼 수 있습니다. 2.2 와 3.3 에서 이런 잘못을 봅니다. 둘째, 의사코드는 특정 언어에 묶이지 않아 같은 의사코드에서 R 로도, Python 으로도 옮길 수 있습니다.

오른쪽 아래 상자는 이 수업의 의사코드 표기 규약입니다. function, if, else, for, while, return 여섯 낱말만 R 과 같은 영어로 쓰고 나머지는 한국어로 씁니다. 그래야 R 로 옮길 때 이 낱말이 그대로 대응됩니다. 블록은 들여쓰기 네 칸으로 나타내고 중괄호는 쓰지 않습니다. 대입은 왼쪽 화살표, 같은지 비교는 등호 하나입니다. R 에서는 같은지 비교가 등호 두 개이므로 옮길 때 주의합니다.

앞으로 알고리즘마다 자연어와 손 추적을 먼저 보고, 의사코드는 슬라이드를 넘기기 전에 여러분이 먼저 종이에 써 봅니다. 그다음 제가 쓴 의사코드와 비교하고 R 로 옮깁니다.

2.1 재귀 함수의 세 부분

자연어: S(n) = 1 + 2 + … + n

  1. 종료 조건 먼저: 답을 바로 아는 입력
    n 이 1 이면 답은 n, 곧 1
  2. 한 단계 작게: 입력을 줄여 자기 자신 호출
    1 부터 n − 1 까지의 합을 같은 방법으로
  3. 결과 합치기: 작은 문제의 답으로 원래 답 계산
    그 합에 n 을 더함

의사코드

function recursive_sum(n)
    입력: 1 이상의 정수 n
    출력: 1 + 2 + ... + n
1.  if n = 1 이면:
        return n
2.  작은 합 ← recursive_sum(n − 1)
3.  return n + 작은 합

R 코드: 주석 번호 = 의사코드 번호

recursive_sum <- function(n) {
  if (n == 1) return(n)      # 1. 종료 조건
                             # 2, 3 은 다음에
}
recursive_sum <- function(n) {
  if (n == 1) return(n)      # 1. 종료 조건
  recursive_sum(n - 1)       # 2. 한 단계 작게
}
recursive_sum <- function(n) {
  if (n == 1) return(n)      # 1. 종료 조건
  n + recursive_sum(n - 1)   # 2. 작게 호출, 3. n 을 더함
}

재귀 함수는 세 부분으로 이루어집니다. 왼쪽 위가 1부터 n 까지의 합 S(n) 을 이 세 부분으로 쓴 자연어 절차입니다. 각 줄의 굵은 글씨가 부분의 이름이고, 그 아래가 합 문제에 적용한 내용입니다.

1번, 종료 조건을 먼저 씁니다. 더 쪼개지 않아도 답을 바로 아는 입력입니다. n 이 1 이면 답은 n 자신, 곧 1 입니다. 2번, 문제를 한 단계 작게 만들어 자기 자신을 부릅니다. 1부터 n 까지의 합보다 한 단계 작은 문제는 1부터 n - 1 까지의 합입니다. 3번, 돌아온 답으로 원래 문제의 답을 만듭니다. 1부터 n - 1 까지의 합에 n 을 더하면 1부터 n 까지의 합입니다.

이 세 줄을 의사코드로 옮겨 보겠습니다. 클릭하기 전에 ‘구현의 세 단계’ 슬라이드에서 정한 규약대로 종이에 먼저 써 보세요. 첫 줄 function, 둘째 줄 입력, 셋째 줄 출력, 그다음 본문입니다. 1분 드리겠습니다.

(클릭) 써 본 것과 비교해 보세요. 입력은 1 이상의 정수 n, 출력은 1부터 n 까지의 합입니다. 자연어 1번이 의사코드 1번 if 줄과 그 안의 return n 이 됩니다. 2번 “같은 방법으로” 가 의사코드 2번에서 recursive_sum(n − 1) 이라는 자기 자신 호출이 되고, 그 값을 작은 합이라고 부릅니다. 3번이 return n + 작은 합 입니다.

(클릭) 오른쪽 R 코드도 같은 순서로 씁니다. 처음에는 함수 머리와 의사코드 1번 줄만 씁니다. 주석의 번호가 의사코드 줄 번호입니다.

(클릭) 의사코드 2번, 한 단계 작은 문제를 부르는 줄을 씁니다. 이 상태로 실행하면 recursive_sum(n - 1) 의 값을 그대로 돌려주므로 n 이 3 이든 10 이든 결과는 1 입니다. 3번 합치는 줄이 빠졌기 때문입니다.

(클릭) 의사코드 3번, 돌아온 값에 n 을 더합니다. R 에서는 의사코드 2번과 3번 두 줄이 n + recursive_sum(n - 1) 한 줄에 들어갑니다. 작은 합이라는 이름을 따로 두지 않고 호출한 자리에서 바로 더한 것입니다.

(클릭) 실행하면 3 에서 6, 10 에서 55 입니다. 1부터 10 까지 더한 값 55 와 같습니다.

종료 조건을 먼저 쓰는 이유는 재귀 호출이 마지막에 도착할 곳을 먼저 정해 두기 위해서입니다. 종료 조건이 없는 재귀는 멈추지 않습니다.

2.1 호출과 반환 순서 추적

recursive_sum(3) 의 호출과 반환

  • 내려갈 때: 호출만, n 을 하나씩 줄임
  • 올라올 때: 덧셈, 2 + 1 = 3, 3 + 3 = 6

호출과 반환마다 cat() 으로 찍기

sum_trace <- function(n, depth = 0) {
  pad <- strrep("  ", depth)          # 깊이만큼 들여쓰기
  cat(pad, "S(", n, ") 호출\n", sep = "")
  if (n == 1) s <- n                  # 1. 종료 조건
  else s <- n + sum_trace(n - 1, depth + 1)   # 2, 3
  cat(pad, "S(", n, ") = ", s, " 반환\n", sep = "")
  s
}

화살표 방향을 보면, 내려갈 때는 n 을 하나씩 줄여 호출만 하고, 덧셈은 올라올 때 일어납니다. recursive_sum(3) 의 3 + 3 은 recursive_sum(2) 가 3 을 돌려준 뒤에 계산됩니다.

이 순서를 그림 없이 확인하는 방법이 오른쪽입니다. 함수 안에 cat() 을 두 줄 넣어, 호출될 때 한 번, 값을 돌려줄 때 한 번 화면에 찍습니다. depth 인수는 호출 깊이입니다. 자기 자신을 부를 때 depth + 1 을 넘기고, 깊이만큼 공백을 넣어 들여씁니다.

출력을 보면 S(3), S(2), S(1) 순서로 호출되고, S(1), S(2), S(3) 순서로 반환됩니다. 마지막 줄의 6 이 함수가 돌려준 값입니다.

재귀 함수가 예상과 다른 값을 내면 이렇게 호출과 반환을 찍어 손으로 따라간 순서와 비교합니다. 확인이 끝나면 cat() 줄은 지웁니다.

2번 줄에서 입력을 줄였을 때 그 입력이 반드시 1번 줄의 조건에 닿아야 합니다. n 에서 1 씩 빼면 1 이상의 정수는 언젠가 1 이 되지만, 0 이나 음수는 1 을 지나쳐 내려갑니다. 이 점검은 R 코드 없이 의사코드 두 줄만 보고도 할 수 있습니다. 의사코드를 먼저 쓰는 이유 가운데 하나입니다. 이 결함은 입력이 작은 쪽, 곧 종료 조건의 1 바로 아래인 0 에서 드러났습니다. 입력이 커질 때의 문제는 이 절 끝에서 n = 5000 으로 봅니다.

함수를 짠 뒤에는 정의역 끝의 입력을 넣어 봅니다. 수치 인수에는 0 과 음수, 벡터 인수에는 빈 벡터와 길이 1 인 벡터입니다.

2.3 계승: 같은 세 부분으로 쓰기

자연어: 점화식에서

\[ n! = \begin{cases} n \times (n-1)!, & n \geq 1 \\ 1, & n = 0 \end{cases} \]

  1. 종료 조건: n 이 0 이면 답은 1
  2. 한 단계 작게: (n − 1)! 을 같은 방법으로
  3. 결과 합치기: 그 값에 n 을 곱함

손으로 따라가기: 4!

  • 내려가기: 4!, 3!, 2!, 1!, 0! = 1
  • 올라오기: 1! = 1, 2! = 2, 3! = 6, 4! = 24

경계 입력 n = −1: 0 을 지나쳐 내려감 → 2.2 와 같은 중첩 한계 오류

의사코드

function factorial_manual(n)
    입력: 0 이상의 정수 n
    출력: n!
1.  if n = 0 이면:
        return 1
2.  작은 답 ← factorial_manual(n − 1)
3.  return n × 작은 답

R 코드: 주석 번호 = 의사코드 번호

factorial_manual <- function(n) {
  if (n == 0) return(1)          # 1. 종료 조건
  n * factorial_manual(n - 1)    # 2. 작게 호출, 3. 곱함
}
factorial_manual(4)
[1] 24
all(sapply(0:10, factorial_manual) == factorial(0:10))
[1] TRUE

같은 세 부분을 계승에 적용합니다. 계승은 n! = n × (n - 1)! 이고 0! = 1 로 정의합니다. 왼쪽 위 점화식을 세 부분의 자연어로 옮긴 것이 그 아래 세 줄입니다.

1번, 종료 조건. 답을 바로 아는 입력은 n 이 0 일 때이고 답은 1 입니다. 2번, 한 단계 작게. n! 보다 한 단계 작은 문제는 (n - 1)! 입니다. 3번, 합치기. 돌아온 (n - 1)! 에 n 을 곱합니다.

4! 을 손으로 따라가 보겠습니다. 내려갈 때는 4!, 3!, 2!, 1!, 0! 순서로 호출하고 0! 에서 1 을 받습니다. 올라올 때 1! 은 1 × 1, 2! 은 2 × 1, 3! 은 3 × 2, 4! 은 4 × 6 으로 24 가 됩니다.

왼쪽 아래 상자는 경계 입력입니다. -1 을 넣으면 n 이 -1, -2, -3 으로 줄어 n = 0 을 지나쳐 내려갑니다. 2.2 의 recursive_sum(0) 과 같은 중첩 한계 오류입니다. 계승의 정의역은 0 이상의 정수이므로, 의사코드의 입력 줄에 “0 이상의 정수” 라고 적고, 이 함수에는 그 범위의 입력만 넣습니다.

이제 의사코드입니다. 2.1 의 recursive_sum 의사코드와 같은 모양이므로, 클릭하기 전에 종이에 먼저 써 보세요. 1분 드리겠습니다.

(클릭) 써 본 것과 비교해 보세요. 자연어 1번이 의사코드 1번 if 줄과 return 1 이 되고, 2번이 factorial_manual(n − 1) 호출, 3번이 return n × 작은 답 입니다. 2.1 의 의사코드와 다른 곳은 세 군데뿐입니다. 입력이 0 이상의 정수, 1번 줄의 조건과 반환값이 n = 0 과 1, 3번 줄이 더하기 대신 곱하기입니다.

(클릭) R 코드는 의사코드를 한 줄씩 옮긴 것이고, 주석 번호가 의사코드 번호입니다. 2.1 처럼 의사코드 2번과 3번이 R 에서는 한 줄로 합쳐집니다.

2.4 하노이 탑

규칙

  • 한 번에 원판 하나만 이동
  • 큰 원판을 작은 원판 위에 올릴 수 없음

자연어: 원판 n 개를 A 에서 C 로

  1. 원판이 1 개면 A \(\rightarrow\) C 로 바로 이동
  2. 위쪽 \(n-1\) 개를 A \(\rightarrow\) B
    (크기만 하나 작은 같은 문제)
  3. 가장 큰 원판을 A \(\rightarrow\) C
  4. B 의 \(n-1\) 개를 B \(\rightarrow\) C
    (역시 같은 문제)

하노이 탑입니다. 자기 자신을 두 번 부르는 예입니다.

왼쪽 애니메이션을 보세요. 기둥이 세 개 있고, 원판이 크기 순으로 쌓여 있습니다. 이걸 전부 오른쪽 기둥으로 옮기는 게 목표입니다.

규칙은 두 개. 한 번에 하나씩만 옮긴다. 큰 걸 작은 것 위에 올리면 안 된다.

원판이 세 개면 7번 옮기면 되므로 손으로 순서를 찾을 수 있습니다. 열 개면 1,023번이라 순서를 손으로 정하기 어렵습니다.

재귀로 풀 때는 원판 전체의 이동 순서를 한꺼번에 정하지 않습니다. 가장 큰 원판을 C로 옮기기 직전의 상태부터 정합니다.

그 직전에는 위에 있는 n-1개가 전부 B에 가 있어야 합니다. 그래야 가장 큰 원판 위가 비고, C 도 비어 있습니다.

그래서 오른쪽 자연어 절차는 네 줄입니다. 1번은 종료 조건으로, 원판이 하나뿐이면 바로 C 로 옮기고 끝납니다. 원판이 둘 이상이면 2번, n-1개를 B로. 3번, 큰 거 하나를 C로. 4번, B의 n-1개를 C로.

2번과 4번은 원판이 n-1개인 하노이 탑 문제이고, 출발, 도착, 경유 기둥만 바뀝니다. 2.1 의 세 부분으로 말하면, 1번이 종료 조건이고, 원판 n-1 개 문제를 두 번 부르는 2번과 4번이 한 단계 작게, 2번, 3번, 4번의 이동을 이 순서로 이어 붙이는 것이 결과 합치기입니다.

오른쪽 아래 애니메이션이 원판 세 개짜리 정답입니다. 일곱 번 움직이지요. 다음 슬라이드에서 이 일곱 번을 이 절차와 맞춰 손으로 따라갑니다.

앞 슬라이드의 자연어 절차를 원판 3개로 손으로 따라가 보겠습니다. 왼쪽의 H(k, X→Y) 는 원판 k 개를 X 에서 Y 로 옮기는 문제를 줄여 쓴 것입니다.

H(3, A→C) 는 원판이 셋이라 1번 종료 조건에 해당하지 않으므로 절차 2, 3, 4 로 나뉩니다. 절차 2 가 위의 2개를 A 에서 B 로 옮기는 H(2, A→B), 절차 3 이 가장 큰 원판 3 을 A 에서 C 로, 절차 4 가 B 의 2개를 C 로 옮기는 H(2, B→C) 입니다.

H(2, A→B) 를 한 번 더 분해합니다. 원판 1 을 A 에서 C 로 비켜 두고, 원판 2 를 A 에서 B 로, 원판 1 을 C 에서 B 로 옮깁니다. 이때는 C 가 경유 기둥입니다. H(2, B→C) 도 같은 모양이고, 이때는 A 가 경유 기둥입니다. H(1, …) 은 절차 1, 종료 조건이라 더 분해하지 않고 바로 옮깁니다.

오른쪽 표는 이동이 끝날 때마다 세 기둥에 남은 원판을 아래부터 적은 것입니다. 1번부터 3번까지가 H(2, A→B) 입니다. 3번이 끝나면 B 에 2 1 이 쌓이고 A 에는 원판 3 만 남습니다. 굵게 표시한 4번이 가장 큰 원판의 이동입니다. C 가 비어 있으므로 옮길 수 있습니다. 5번부터 7번이 H(2, B→C) 입니다. 1번부터 3번과 같은 모양의 세 이동을 기둥 이름만 바꿔 반복합니다.

function move_hanoi(k, from, to, via)
    입력: 원판 수 k, 출발 from, 도착 to, 경유 via
    출력: 이동 순서를 한 줄씩 출력
1.  if k = 1 이면:
        원판 1 을 from 에서 to 로 옮김
    else:
2.      move_hanoi(k − 1, from 에서 via 로, to 경유)
3.      원판 k 를 from 에서 to 로 옮김
4.      move_hanoi(k − 1, via 에서 to 로, from 경유)

출력 7줄 = 손 추적 표의 이동 1~7, 순서까지 일치
원판 n 개: 이동 2ⁿ − 1 회, 호출이 매번 둘로 갈라짐 → O(2ⁿ), 원판 64개면 1초에 하나씩 옮겨도 5천억 년 초과

R 코드: 주석 번호 = 의사코드 번호

move_hanoi <- function(k, from, to, via) {
  if (k == 1) {                                        # 1.
    cat(sprintf("원판 1: %s -> %s\n", from, to))
  } else {
    move_hanoi(k - 1, from = from, to = via, via = to) # 2.
    cat(sprintf("원판 %d: %s -> %s\n", k, from, to))    # 3.
    move_hanoi(k - 1, from = via, to = to, via = from) # 4.
  }
}

  s

이번엔 무한 재귀가 아닙니다. 종료 조건은 n <= 1 로 고쳤습니다. 호출 깊이가 오천이라 R 의 중첩 한계를 넘은 겁니다. 호출마다 스택 프레임이 쌓이므로, R 은 메모리를 다 쓰기 전에 깊이를 제한합니다.

재귀는 공간 복잡도가 O(n)입니다. n번 부르면 프레임이 n개 쌓이니까요. 오른쪽은 같은 계산을 for 문으로 옮긴 것입니다. 누적 변수 s 하나만 갱신하므로 공간 복잡도가 O(1) 이고, 호출이 쌓이지 않으므로 깊이 제한도 없습니다. n 이 5000 이어도 12502500 을 돌려줍니다.

그러면 재귀를 왜 씁니까? 코드가 문제의 점화식과 같은 모양이 되기 때문입니다. recursive_sum 의 두 줄은 S(1) = 1, S(n) = n + S(n - 1) 을 그대로 옮긴 것입니다. 하노이 탑도 재귀로 쓰면 자연어 절차 네 줄이 의사코드 네 줄, R 네 줄로 그대로 옮겨지지만, 반복문으로 쓰려면 매번 옮길 원판과 기둥을 정하는 규칙을 따로 세워야 합니다.

작업 순서는 이렇습니다. 점화식을 재귀로 옮겨 작은 입력에서 결과를 확인합니다. 호출 깊이가 중첩 한계 5000 에 가까운 입력을 다뤄야 하면 반복문으로 옮기고, 작은 입력에서 두 결과가 같은지 대조합니다.

3.1 선형 탐색: 자연어, 의사코드, R

자연어: 1.1 의 방법 A

  1. 첫 원소부터 하나씩 꺼냄
  2. 찾는 값과 같으면 그 위치 반환
  3. 끝까지 없으면 NA 반환

의사코드

function linear_search(target, vec)
    입력: 찾는 값 target, 벡터 vec
    출력: 위치, 없으면 NA
1.  for i 를 1 부터 vec 의 길이까지:
2.      if vec[i] = target 이면:
            return i
3.  return NA

R 코드: 주석 번호 = 의사코드 번호

linear_search <- function(target, vec) {
  for (i in seq_along(vec)) {         # 1. 하나씩
    if (vec[i] == target) return(i)   # 2. 찾으면 위치
  }
  NA_integer_                         # 3. 끝까지 없음
}

(클릭) 써 본 것과 비교해 보세요. 입력과 출력 줄에서 없을 때 무엇을 돌려줄지 정합니다. 여기서는 NA 입니다. 자연어 1번 “하나씩 꺼냄” 이 의사코드 1번 for 줄입니다. i 는 지금 보고 있는 위치로, 반복하면서 바뀌는 값입니다. 2번 “같으면 위치 반환” 은 for 안에 들여 쓴 if 줄과 return i, 3번 “끝까지 없으면 NA” 는 for 블록이 끝난 뒤의 return NA 입니다. 멈추는 곳이 두 군데라는 것이 의사코드에 보입니다. 찾으면 2번 줄의 return 에서, 못 찾으면 반복이 끝까지 돈 뒤 3번 줄에서 멈춥니다.

의사코드 1번 줄 “1 부터 vec 의 길이까지” 를 R 로 옮길 때 주의할 점이 있습니다. 경계 입력인 빈 벡터입니다. seq_along() 은 길이 0 인 벡터에서 아무 값도 내지 않아, 반복을 한 번도 하지 않고 3번 줄의 NA 로 갑니다. 1:length(vec) 로 옮기면 길이 0 일 때 1:0, 곧 1 과 0 을 돌고, vec[1] 이 NA 라서 if 문에서 “missing value where TRUE/FALSE needed” 오류가 납니다. 의사코드에는 빈 벡터를 따로 처리하는 if 줄이 없습니다. 반복 범위가 비면 바로 3번 줄로 가기 때문이고, R 에서는 seq_along() 이 그 동작을 맡습니다.

3.2 이진 탐색입니다. 1.1 의 방법 B, 가운데를 펼치는 방법입니다.

왼쪽이 자연어 절차 다섯 줄입니다. 전화번호부의 ’남은 쪽’을 코드에서는 두 위치 lo 와 hi 로 나타냅니다. lo 는 남은 범위의 첫 위치, hi 는 마지막 위치이고, 처음에는 1 과 n 입니다. 가운데 위치 mid 의 값을 보고, 같으면 끝입니다. 찾는 값이 더 작으면 mid 를 포함한 오른쪽을 버리고, 더 크면 mid 를 포함한 왼쪽을 버립니다. 버린다는 것은 lo 나 hi 를 옮긴다는 뜻입니다. 범위가 비면, 곧 lo 가 hi 보다 커지면 없는 값이므로 NA 입니다.

10 을 찾으면 21 이 10 보다 크므로 4번부터 8번까지 버리고 hi 를 3 으로 옮깁니다. 다음은 8 이 작아서 lo 를 3 으로, 다음은 15 가 커서 hi 를 2 로 옮깁니다. lo 3 이 hi 2 보다 커졌으므로 범위가 비었고 NA 입니다.

3.2 이진 탐색: 의사코드에서 R 로

의사코드

function binary_search(target, ovec)
    입력: 찾는 값 target, 정렬된 벡터 ovec
    출력: 위치, 없으면 NA
1.  lo ← 1, hi ← ovec 의 길이
5.  while lo ≤ hi 인 동안:
2.      mid ← (lo + hi) 를 2 로 나눈 몫
3.      if ovec[mid] = target 이면:
            return mid
4.      if ovec[mid] > target 이면:
            hi ← mid − 1
        else:
            lo ← mid + 1
5.  return NA

써 본 의사코드와 왼쪽을 비교해 보세요.

입력 줄에 벡터가 정렬되어 있어야 한다는 조건을 붙였습니다. 인수 이름 ovec 의 o 는 ordered, 정렬되었다는 뜻입니다. 출력 줄은 찾은 위치, 없으면 NA 입니다.

본문의 줄 번호가 앞 슬라이드 자연어 절차의 번호입니다. 자연어 1번 “범위를 전체로” 가 의사코드 1번, lo 와 hi 를 정하는 줄입니다. 자연어 5번 “아니면 2로” 는 2번으로 돌아가 반복한다는 뜻이므로 의사코드에서는 5번 while 줄이 되고, 2, 3, 4번이 그 안에 들여 쓴 줄이 됩니다. 그래서 의사코드에서는 5번이 2번보다 위에 옵니다. 5번의 다른 절반, “범위가 비면 NA” 는 while 이 끝난 뒤의 마지막 줄 return NA 입니다. 반복이 몇 번 돌지 미리 모르므로 for 가 아니라 while 이고, 조건은 “범위가 남아 있는 동안”, 곧 lo ≤ hi 입니다. 반복하면서 바뀌는 값은 lo, hi, mid 셋으로, 손 추적 표의 열 이름과 같습니다. 멈추는 곳은 두 군데입니다. 찾으면 3번 줄의 return mid, 범위가 비면 마지막 줄의 return NA 입니다.

경계 입력인 빈 벡터를 따로 처리하는 if 줄은 없습니다. 길이가 0 이면 1번 줄에서 hi 가 0 이라 5번 while 조건 lo ≤ hi 가 처음부터 거짓이고, 반복 없이 마지막 줄의 NA 로 갑니다.

(클릭) 오른쪽 R 코드는 세 번에 나누어 씁니다. 처음에는 뼈대입니다. 함수 머리, 의사코드 1번 줄과 5번 while 줄만 R 로 쓰고, 반복문 안에서 할 일은 의사코드 번호를 단 주석으로 적어 둡니다.

(클릭) 반복문 안을 채웁니다. 주석 2, 3, 4 를 한 줄씩 코드로 바꿉니다. 2번은 가운데 위치로, “2 로 나눈 몫” 이 R 의 %/% 입니다. 1L 의 L 은 정수형이라는 표시입니다. 3번의 등호 하나는 R 에서 등호 두 개가 됩니다. 4번은 의사코드에서 if 와 else 네 줄이고, R 에서는 if 한 줄과 else 한 줄입니다. 가운데 값이 찾는 값보다 크면 hi 를 mid - 1 로, 아니면 lo 를 mid + 1 로 옮깁니다. 손 추적 표의 ‘버리는 쪽’ 열이 이 두 줄입니다.

(클릭) 마지막으로 반복문을 빠져나온 뒤 돌려줄 값, 의사코드 마지막 줄의 NA 를 씁니다.

(클릭) 아래 상자. 4번 줄이 정렬 조건의 근거입니다. ovec[mid] 가 찾는 값보다 크면 hi 를 mid - 1 로 옮겨 mid 의 오른쪽을 한 번에 버립니다. mid 오른쪽 값이 모두 ovec[mid] 이상이라고 보는 것이고, 이것은 벡터가 정렬되어 있을 때만 참입니다. 의사코드 입력 줄에 “정렬된” 을 적은 이유입니다. 다음 슬라이드에서 이 가정을 어긴 입력을 넣어 봅니다.

정렬 비용까지 더하면 이진 탐색의 비교 횟수가 항상 적지는 않음

  • 전제: 자료가 정렬되어 있어야 적용 가능
  • 정렬 자체의 비용 \(\mathcal{O}(n \log n)\)
  • 탐색 1회: 선형 최대 \(n\) 회 < 정렬 \(n \log n\) 회
  • 탐색 반복: 탐색마다 \(n\) 회 대 \(\log n\) 회, 반복 횟수가 늘면 정렬 비용 상쇄

이제 비용을 재 보겠습니다. 1.2절에서 정한 대로 시간이 아니라 비교 횟수를 셉니다. 비교 횟수는 하드웨어와 관계없이 입력이 같으면 같은 값입니다.

표를 보세요. n이 백일 때 선형은 평균 50.5번, 이진은 5.8번입니다. n이 만일 때 선형은 5,251번, 이진은 12.4번.

n을 백 배 키웠더니 선형은 50.5에서 5,250.9로 약 104배 늘었습니다. 이진은 5.8에서 12.4로 2.1배, 횟수로는 6.6번 늘었습니다. log₂100 이 약 6.6 입니다.

n 에 비례해 느는 선형과, n 이 백 배가 될 때 log₂100 번만 느는 이진의 차이가 O(n)과 O(log n)의 차이입니다. 이진 탐색이 왜 log n 인지는 왼쪽 상자 첫 줄입니다. 비교 한 번마다 후보가 n, n/2, n/4 로 절반씩 줄고, k 번 비교한 뒤 후보가 1개가 되면 n 을 2 로 k 번 나눈 값이 1 이므로 k 는 log₂ n 입니다. 3.2 의 손 추적에서 길이 8 인 v8 은 범위가 8, 4 또는 3, 2 또는 1 개로 줄며 세 번 비교했습니다. 백만 개면 선형은 평균 50만 번, 이진은 스무 번입니다.

오른쪽 상자는 정렬 비용을 더한 비교입니다.

“이진 탐색이 비교 횟수가 적으니까 항상 이진 탐색을 쓰면 된다” 는 틀립니다. 이진 탐색을 쓰려면 정렬이 되어 있어야 하지요. 정렬에도 연산이 듭니다. 정렬 자체가 O(n log n) 입니다. 선형 탐색 한 번의 O(n) 보다 연산 횟수가 많습니다.

데이터를 받아서 값 하나만 찾고 버릴 거면 처음부터 훑는 선형 탐색이 비교 횟수가 적습니다. 선형 탐색은 최대 n 번이고, 정렬만 해도 n log n 번이기 때문입니다. 같은 데이터에서 여러 번 찾아야 하면 한 번 정렬해 두는 쪽이 전체 비교 횟수가 적어집니다. 탐색 한 번이 최대 n 번에서 log n 번으로 줄어서, 탐색 횟수가 늘수록 정렬 비용이 메워집니다. n 이 백만이면 정렬에 약 2천만 번이 들고 탐색 한 번마다 최대 약 백만 번을 줄이므로, 스무 번 넘게 찾으면 정렬하는 쪽이 적습니다.

그래서 탐색 방법을 고를 때는 “어느 쪽 비교 횟수가 적은가” 보다 “같은 자료에서 몇 번 찾을 것인가” 를 먼저 정하고, 정렬 비용을 포함한 전체 비교 횟수로 비교합니다.

삽입 정렬입니다. 카드 게임에서 카드를 한 장씩 받아서 손에 쥘 때, 새 카드를 이미 쥔 카드들 사이 제자리에 끼워 넣습니다. 손에 든 카드는 항상 정렬된 상태이고, 마지막 카드를 끼우면 끝납니다. 왼쪽 위 자연어 네 줄이 이 절차입니다.

코드에서는 x 의 앞부분, 1번부터 i - 1 번까지가 손에 쥔 카드입니다. i 번째 값을 key 로 꺼내 들고, 앞에서 key 보다 큰 값들을 한 칸씩 뒤로 밀어 자리를 만든 다음, 거기에 key 를 넣습니다.

(클릭) 오른쪽 R 코드의 뼈대입니다. for 문과 key 꺼내기까지 쓰고, 밀기와 끼워 넣기는 의사코드 번호를 단 주석으로 둡니다. 의사코드의 “2 부터 n 까지” 를 R 에서는 2:n 으로 옮겼습니다. n 이 1 이면 2:1 이 2 와 1 을 돌지만, 바로 위 경계 줄이 n < 2 를 먼저 돌려보내므로 여기서는 안전합니다.

(클릭) 4번, while 이 끝난 자리 j + 1 에 key 를 넣습니다. while 이 멈춘 j 는 key 보다 작거나 같은 값의 위치이거나 0 이므로, 그 바로 뒤가 빈자리입니다.

왼쪽이 합치는 절차를 자연어로 쓴 것입니다. 1번, 결과를 담을 자리를 두 묶음 길이의 합만큼 준비하고, 두 묶음의 맨 앞에서 시작합니다. 2번, 결과의 자리마다 두 묶음의 맨 앞 값을 봅니다. 오른쪽 묶음이 바닥났으면 왼쪽에서 꺼내고, 왼쪽 맨 앞 값이 오른쪽 맨 앞 값보다 작거나 같아도 왼쪽에서 꺼냅니다. 3번, 그렇지 않으면 오른쪽에서 꺼냅니다. 꺼낸 쪽은 다음 값으로 한 칸 옮깁니다.

오른쪽 표가 2 4 5 와 1 3 6 을 손으로 합친 기록입니다. 첫 자리에서는 2 와 1 을 비교해 오른쪽 1 을 꺼내고, 오른쪽 맨 앞이 3 으로 바뀝니다. 둘째 자리는 2 와 3 이라 왼쪽 2, 셋째는 4 와 3 이라 오른쪽 3, 넷째와 다섯째는 4 와 6, 5 와 6 이라 왼쪽에서 꺼냅니다. 마지막 자리에서는 왼쪽이 바닥났으므로 비교 없이 오른쪽 6 을 꺼냅니다. 비교는 다섯 번입니다.

오른쪽 아래 상자. 결과 자리 하나를 채울 때 비교는 많아야 한 번이고, 한쪽이 바닥나면 비교 없이 꺼냅니다. 그래서 두 묶음 길이의 합이 m 이면 비교는 최대 m − 1 번입니다. 여섯 개를 합친 이 예에서는 다섯 번입니다. 이 사실이 병합 정렬 슬라이드의 비용, 깊이마다 원소 n 개를 한 번씩 훑는다는 계산의 근거가 됩니다.

왼쪽 아래 상자. 2번의 “작거나 같으면” 에서 등호가 중요합니다. 값이 같으면 왼쪽 것을 먼저 꺼내므로, 같은 값끼리는 원래 순서가 유지됩니다. 이런 정렬을 안정 정렬이라고 합니다. 데이터 프레임을 한 열로 정렬한 뒤 다른 열로 다시 정렬할 때, 안정 정렬이어야 같은 값 안에서 앞의 정렬 순서가 남습니다.

function smerge(left, right)

    출력: 둘을 합친 정렬된 벡터

smerge <- function(left, right) {
  temp <- numeric(length(left) + length(right))  # 1. 결과 자리
  l <- r <- 1L                                   # 1. 두 맨 앞
  for (i in seq_along(temp)) {                   # 2. 자리마다
    if (r > length(right) ||                     # 2. 오른쪽이 바닥났거나
        (l <= length(left) && left[l] <= right[r])) {  #    왼쪽 ≤ 오른쪽
      temp[i] <- left[l]; l <- l + 1L            #    왼쪽에서 꺼냄
    } else {                                     # 3.
      temp[i] <- right[r]; r <- r + 1L           #    오른쪽에서 꺼냄
    }
  }
  temp
}

의사코드

function merge_sort(x)
    입력: 수치형 벡터 x
    출력: 정렬된 벡터
    n ← x 의 길이
1.  if n ≤ 1 이면:
        return x
2.  mid ← n 을 2 로 나눈 몫
3.  left ← merge_sort(x 의 1 ~ mid 번째)
3.  right ← merge_sort(x 의 mid + 1 ~ n 번째)
4.  return smerge(left, right)

2절의 세 부분: 종료 조건 1번, 한 단계 작게 2, 3번, 결과 합치기 4번
시간 O(n log n): 깊이 약 log₂ n, 깊이마다 원소 n 개
추가 메모리 O(n): smerge() 의 temp

R 코드: 주석 번호 = 의사코드 번호

merge_sort <- function(x) {
  n <- length(x)
  if (n <= 1) return(x)                   # 1. 종료 조건
  mid <- n %/% 2L                         # 2. 반으로 나눔
  left  <- merge_sort(x[1:mid])           # 3. 앞 절반 재귀
  right <- merge_sort(x[(mid + 1):n])     # 3. 뒤 절반 재귀
  smerge(left, right)                     # 4. 합치기
}

자연어 1번 “길이 1 이하면 이미 정렬됨” 이 의사코드 1번 if 줄입니다. 그대로 돌려줍니다. 자연어 2번 “반으로 나눔” 이 2번 줄입니다. mid 는 n 을 2 로 나눈 몫이라, 길이 6 이면 3, 길이 3 이면 1 입니다. 손 추적 표의 나누기 줄과 같습니다. 자연어 3번 “두 반을 각각 병합 정렬” 이 3번 두 줄입니다. 앞 절반과 뒤 절반을 각각 merge_sort() 로 정렬합니다. 2절의 하노이 탑처럼 자기 자신을 두 번 부릅니다. 자연어 4번 “합침” 이 4번 줄로, 앞 슬라이드의 smerge() 를 부릅니다.

왼쪽 아래 상자 첫 줄은 2절의 재귀 함수의 세 부분으로 본 것입니다. 1번 줄이 종료 조건, 2번과 3번 줄이 한 단계 작게, 4번 줄이 결과 합치기입니다. 하노이 탑에서는 이동을 이어 붙이는 것이 합치기였고, 여기서는 smerge() 가 합치기입니다.

(클릭) 오른쪽 R 코드의 주석 번호가 의사코드 번호입니다. 의사코드의 “x 의 1 ~ mid 번째” 가 x[1:mid] 입니다. 번호가 없는 n 줄은 자연어에 없던 준비 줄입니다.

실행하면 v6 이 정렬되고, v 도 sort() 와 같습니다. as.numeric() 을 붙인 이유는 v 가 정수형인데 smerge() 의 temp 가 numeric() 으로 만든 실수형이라, 값이 같아도 identical() 이 FALSE 를 내기 때문입니다.

왼쪽 아래 상자의 나머지 두 줄은 비용입니다. 반씩 쪼개니까 깊이가 log₂ n, 각 깊이에서 원소 전체를 한 번씩 훑으니까 n, 곱하면 n log n 입니다. 대신 smerge() 가 합칠 때마다 temp 벡터를 만들므로 메모리를 O(n) 더 씁니다. 비교 횟수는 줄고 메모리는 느는 이런 경우 때문에 1.2절에서 비용을 수행 시간과 메모리로 나눠 말했습니다.

자연어: 기준 학생 세우기

퀵 정렬입니다. 체육 시간에 키 순서로 줄 세우는 걸 떠올려 보세요. 선생님이 한 학생을 기준으로 세웁니다. 그보다 작은 학생은 왼쪽, 큰 학생은 오른쪽으로 가라고 하지요. 그러면 기준 학생은 이미 제자리입니다. 이제 왼쪽 무리와 오른쪽 무리 안에서 각각 기준 학생을 새로 세워 같은 방식으로 나눕니다. 무리가 한 명 이하가 되면 끝납니다. 왼쪽 자연어 다섯 줄이 이 절차이고, 이 장에서는 첫 원소를 기준값으로 삼습니다. 영어로 pivot 이라고 합니다.

오른쪽 표로 v6 을 따라가 봅니다. 첫 원소 5 가 기준값입니다. 5 보다 작은 2 4 1 3 과 큰 6 으로 나뉩니다. 작은 무리 2 4 1 3 에서는 첫 원소 2 가 기준값이라 1 과 4 3 으로 나뉩니다. 4 3 에서는 4 가 기준값이라 3 과 빈 무리로 나뉩니다. 원소가 하나 이하인 무리는 더 나누지 않습니다.

이어 붙이기는 깊은 쪽부터입니다. 3 과 4 를 붙여 3 4, 1 과 2 와 3 4 를 붙여 1 2 3 4, 마지막으로 1 2 3 4 와 5 와 6 을 붙여 정렬이 끝납니다.

아래 상자. 병합 정렬과 같은 분할 정복인데, 값을 비교하는 단계가 반대입니다. 병합 정렬은 위치로 반을 자르고 합칠 때 값을 비교했지요. 퀵 정렬은 기준값보다 작은지 큰지 비교하면서 나누므로 나눌 때 순서가 정해지고, 합칠 때는 이어 붙이기만 합니다.

넘기기 전에 왼쪽 다섯 줄을 의사코드로 써 보세요. 함수 이름은 quick_sort 입니다. 3번 “세 무리로 나눔” 은 기준값보다 작은 값, 같은 값, 큰 값을 각각 모으는 세 줄로 쓰면 됩니다. 2분 드리겠습니다.

        [] 5 [6]
  • 작은 무리는 늘 비고, 큰 무리는 하나씩만 줄어듦
  • 깊이 \(n-1\), 비교 \((n-1) + \cdots + 1 = n(n-1)/2\): 버블과 같음
  • 평균 \(\mathcal{O}(n \log n)\) 이지만 최악 \(\mathcal{O}(n^2)\)

답은 B입니다. 계단이 생깁니다.

왜 그럴까요? 첫 원소를 기준값으로 잡는데, 정렬된 입력에서 첫 원소는 항상 제일 작은 값입니다. 그러면 작은 무리는 늘 비어 있고, 큰 무리는 하나씩만 줄어듭니다. 무리가 반씩 줄어야 깊이가 log n 인데, 하나씩 줄어서 깊이가 n-1이 되고, 비교 횟수는 n-1 더하기 n-2 더하기 … 버블 정렬과 같은 n(n-1)/2 입니다.

오른쪽을 보세요. 같은 5,000개의 값을 순서만 바꿔서 넣었습니다. (클릭) 무작위 순서면 정렬 결과가 1:5000 과 같아 TRUE 입니다. 정렬된 순서로 넣으면 오류로 멈춥니다. 정렬된 5,000개면 재귀가 4,999 단계까지 쌓여야 하는데, 그 전에 R 의 한계에 닿은 겁니다. 오류 메시지는 node stack overflow 로 2.2절의 evaluation nested too deeply 와 다릅니다. R 은 재귀 호출이 쌓이는 공간에 한계를 여러 개 두고 있어서 어느 한계에 먼저 닿느냐에 따라 메시지가 달라지지만, 2.2절의 recursive_sum2(5000)이 멈췄던 것과 원인은 같은 호출 깊이입니다.

정렬해 둔 자료에 값 몇 개를 덧붙여 다시 정렬하는 것처럼, 이미 거의 정렬된 자료를 정렬하는 일이 있습니다. 기준값을 가운데 원소나 무작위로 고르면 정렬된 입력이 최악이 되지 않습니다. 다만 어떤 규칙이든 비교 횟수가 n(n-1)/2 가 되는 입력이 있습니다. 가운데 원소를 기준값으로 바꿔 보는 것이 노트 연습문제 10번입니다.

‘평균 O(n log n)’ 에 ’평균’이 붙는 것은, 기준값이 늘 가장 작거나 가장 큰 값이 되는 입력에서는 n(n-1)/2 번 비교하기 때문입니다.

이론적으로 분석한 복잡도가 실제 연산 횟수와 일치하는지 확인하는 것도 검증

이제 네 정렬의 비교 횟수를 셉니다. 표를 보기 전에 먼저 생각해 보세요. 원소 수를 두 배로 늘리면 비교 횟수는 몇 배가 될까요? 버블과 삽입이 O(n²) 이므로 (2n)² = 4n², 네 배입니다. 병합과 퀵은 O(n log n) 이므로 2n log₂(2n) = 2n(log₂n + 1), n 이 천이면 약 2.2배로 두 배보다 조금 큽니다.

실행 시간이 아니라 비교 횟수를 세는 이유도 짚어 둡니다. 실행 시간은 하드웨어와 부하에 따라 달라지고, 병합과 퀵은 0.02초 아래로 측정되어 배율을 계산하기 어렵습니다. 제가 처음에 실행 시간으로 재 봤을 때 병합 정렬이 0.00초로 찍혀서 배율 계산이 안 됐습니다. 비교 횟수는 0 으로 찍히지 않고, 같은 입력이면 항상 같은 값입니다. 위 표의 버블, 삽입, 병합, 퀵 열은 각 정렬 함수에서 두 값을 비교하는 곳마다 1 을 더하도록 고친 함수로 센 값입니다.

표를 보시죠.

버블 열을 따라가 보세요. 124,750 → 499,500 → 1,999,000. 나눠 보면 4배씩입니다. 옆에 n(n-1)/2 열을 붙여 놨는데, 세 행 모두 버블 열과 값이 같습니다. 손으로 계산한 공식과 실제로 센 횟수가 일치합니다.

삽입 열은 64,544 → 253,599 → 990,270 으로 약 3.9배씩 늘어납니다. 값은 n²/4 근처, 버블의 절반쯤이지요. 끼워 넣을 때 평균적으로 앞부분의 절반쯤을 지나가니까 그렇습니다. 같은 O(n²)라도 계수가 다른 겁니다.

병합과 퀵은 2.2배에서 2.4배씩 늘어납니다. 병합은 n log₂n 의 약 0.9배, 퀵은 약 1.0에서 1.1배로, 앞에 붙는 계수만 다릅니다. 빅오가 계수를 무시한다고 했지요. n이 두 배가 될 때 늘어나는 배율은 2n log₂(2n) ÷ n log₂n 으로 차수가 정하고, 앞에 붙는 계수 0.9 나 1.1 과는 관계가 없습니다.

왼쪽 아래 실행 시간도 같은 방향입니다. 그런데 병합과 퀵을 비교하면 비교 횟수와 시간의 순서가 다릅니다. 퀵이 비교를 더 많이 하는데 시간은 더 짧게 나옵니다. 퀵 정렬 코드는 x[x < pivot] 같은 벡터 연산이라 원소 단위 반복이 내부의 C 코드에서 돌고, 병합 정렬의 smerge는 R의 for문이라 원소 하나마다 R 코드를 한 번씩 해석해 실행합니다. 차수가 같으면 벡터 연산이냐 R 의 for 문이냐 같은 구현의 차이가 실행 시간의 차이를 만듭니다.

오른쪽 상자 맨 아래가 이 슬라이드의 요점입니다. 우리가 손으로 “버블은 n(n-1)/2번 비교한다” 고 분석했지요. 그 분석이 맞는지 실제로 세서 확인했습니다. 코드가 맞는지 확인하는 것만 검증이 아니라, 내가 한 분석이 맞는지 확인하는 것도 검증이에요.

5.1 원리와 점화식

자연어: 접선을 따라 반복

\(f(x) = 0\) 을 만족하는 \(x\) 를 반복 계산으로 근사

  1. 초기값 \(x_0\) 설정
  2. \(x_n\) 에서 접선 계산: 기울기 \(f'(x_n)\)
  3. 접선과 \(x\) 축의 교점을 \(x_{n+1}\) 로 채택
  4. 종료 조건까지 2~3 반복

\[x_{n+1} = x_n - \frac{f(x_n)}{f'(x_n)}\]

종료 조건: 최대 반복 횟수 초과 / \(x\) 갱신 폭이 허용 오차보다 작음 / \(|f(x)|\) 가 허용 오차 이내

뉴턴-랩슨입니다. 방정식의 해를 수치적으로 찾는 방법이에요.

통계에서는 최대가능도추정량을 구할 때 이걸 씁니다. 로그가능도를 미분해서 0이 되는 지점을 찾아야 하는데, 5.6절의 로지스틱 회귀처럼 그 식을 손으로 풀 수 없는 모형이 있습니다. 그때 반복 계산으로 근사하는 방법이 이겁니다.

오른쪽 동영상을 재생해 보겠습니다. (재생)

초기값으로 점을 하나 찍습니다. 그 점에서 접선을 긋습니다. 그 접선이 x축과 만나는 지점으로 옮겨갑니다. 거기서 또 접선을 긋습니다. 또 옮깁니다.

반복할수록 해에 가까워집니다. 5.2절의 예에서는 -5 에서 출발해 여섯 번 만에 갱신 폭이 10의 -8승보다 작아집니다.

수식은 그 과정을 그대로 적은 겁니다. 현재 위치에서 함수값을 기울기로 나눈 만큼 빼라.

한 번에 움직이는 거리는 f(x) 를 f’(x) 로 나눈 값입니다. 기울기가 같으면 함수값이 0 에서 멀수록 멀리 움직이고, 함수값이 같으면 기울기가 완만할수록 멀리 움직입니다.

종료 조건은 상자의 세 가지입니다. 반복이 최대 횟수에 닿으면 멈추고, x 가 허용 오차보다 작게 바뀌면 멈추고, |f(x)| 가 허용 오차보다 작으면 멈춥니다. 구현마다 이 가운데 일부를 고릅니다. 다음 슬라이드의 구현은 최대 반복 횟수와 갱신 폭 두 가지를 씁니다.

왼쪽 위 네 줄이 이 절차의 자연어입니다. 넘기기 전에 의사코드로 써 보세요. 함수 이름은 newton, 입력은 함수 f, 도함수 fp, 초기값 x0, 허용 오차 tol, 최대 반복 횟수 max_iter 다섯 개입니다. 4번 “반복” 을 for 로 쓸지 while 로 쓸지, 멈추는 조건 두 가지를 어디에 둘지 생각하면서 쓰세요. 2분 드리겠습니다.

newton <- function(f, fp, x0, tol = 1e-8, max_iter = 50) {
  x <- x0                                  # 1. 초기값
  path <- matrix(x0, nrow = 1)             #    반복 기록의 첫 줄
  for (iter in seq_len(max_iter)) {        # 4. 멈춤 1: 최대 반복
    step <- as.vector(solve(fp(x), f(x)))  # 2. 갱신량 f(x) / f'(x)
    x <- x - step                          # 3. 다음 위치

    if (max(abs(step)) < tol) break        # 4. 멈춤 2: 수렴
  }

}

써 본 의사코드와 왼쪽을 비교해 보세요.

입력은 다섯 개입니다. 해를 찾을 함수 f, 그 도함수 fp, 초기값 x0, 허용 오차 tol, 최대 반복 횟수 max_iter. 도함수는 손으로 구해 함수로 넘깁니다. 이렇게 f 와 fp 를 인수로 받아 두면, 5.4절부터 다른 문제에 쓸 때 이 두 함수만 바꿔 넣으면 됩니다. 출력은 해 x, 몇 번 반복했는지 iter, 반복마다의 위치를 모은 기록 path 세 가지입니다. 반복 횟수와 기록을 함께 돌려주는 것은 다음 슬라이드에서 수렴 과정을 확인하기 위해서입니다.

본문의 번호가 5.1 자연어 절차의 번호입니다. 자연어 1번 “초기값 설정” 이 1번 줄이고, 기록 path 의 첫 줄도 여기서 만듭니다. 자연어 4번 “반복” 이 for 줄입니다. 최대 max_iter 번까지만 돌게 해서, 수렴하지 않는 초기값에서도 함수가 끝나게 합니다. 1절의 유한성 조건입니다. 자연어 2번 “기울기로 접선 계산” 이 갱신량 step, 3번 “접선과 x 축의 교점으로” 가 x 에서 step 을 빼는 줄입니다. 그 아래 4번 if 줄이 두 번째 멈춤 조건입니다. 갱신 폭이 tol 보다 작으면 수렴한 것으로 보고 반복을 멈춥니다. 그래서 4번이 for 줄과 if 줄 두 곳에 있습니다. 마지막 return 줄은 자연어에 없던 반환이라 번호가 없습니다.

의사코드에 없는 경계 입력이 하나 있습니다. f′(x) 가 0 이면 나눌 수 없어 R 에서 오류가 납니다. 이 함수는 따로 검사하지 않습니다.

(클릭) 오른쪽 R 코드는 세 번에 나누어 씁니다. 처음은 뼈대입니다. 의사코드 1번 줄과 4번 for 줄만 R 로 쓰고, 반복문 안은 의사코드 번호를 단 주석으로 둡니다.

(클릭) 반복문 안을 채웁니다. 2번 갱신량은 f(x) 를 f’(x) 로 나눈 값인데, 나눗셈 대신 solve() 를 썼습니다. 아래 상자에서 설명합니다. 3번 x 에서 갱신량을 빼서 다음 위치로 옮기고, 그 위치를 기록에 한 줄 붙입니다. 의사코드의 한 줄이 R 에서는 두 줄입니다. 4번 if 줄의 “반복을 멈춤” 이 R 의 break 입니다. 의사코드의 |step| 을 max(abs(step)) 으로 쓴 것은 5.5, 5.6 에서 step 이 벡터가 될 때 가장 큰 성분으로 판정하기 위해서입니다.

(클릭) 반복문이 끝나면 의사코드 마지막 줄대로 해, 반복 횟수, 기록을 리스트로 돌려줍니다.

(클릭) 아래 상자. solve(a, b) 는 a 곱하기 d 가 b 가 되는 d 를 구합니다. a 와 b 가 수 하나면 b 나누기 a 와 같습니다. a 가 행렬이면 연립방정식을 풉니다. 모수가 여러 개인 5.5, 5.6 에서 f 자리에 기울기 벡터, fp 자리에 헤세 행렬을 넣으면 이 줄이 그대로 동작합니다. as.vector() 는 solve() 가 행렬 모양으로 돌려준 결과를 벡터로 바꾸는 것입니다.

왼쪽은 다른 방법과 대조하는 것입니다. 3차 다항식이므로 polyroot() 로 모든 근을 구할 수 있습니다. 계수를 상수항부터 차례로 넣습니다. 허수부가 0 인 것만 골라 냈더니 -3.151719 하나만 나옵니다. 실근이 하나뿐이고, newton() 이 구한 값과 같습니다. 나머지 두 개는 켤레 복소수라 x축 위의 점이 아닙니다. 동영상에서 곡선이 x축을 한 번만 가로지른 이유가 이겁니다.

오른쪽은 초기값을 바꿔 가며 돌려 본 것입니다. 열은 초기값, 얻은 x, 반복 횟수, 그 x 에서의 f 값입니다.

-5, 0, 1, 5 에서는 모두 -3.151719 에 도착했습니다. 반복 횟수는 6, 18, 18, 32 번으로 다릅니다. 1 에서 출발하면 네 번째 걸음에서 극대점 -1.23 근처, 곧 기울기가 0 에 가까운 곳을 지나면서 -90 까지 튀었다가 돌아옵니다. f/f’ 의 분모가 0 에 가까우면 한 걸음이 커지기 때문입니다.

-1 에서 출발한 줄을 보세요. 반복이 50 번, 곧 max_iter 에 닿아 멈췄고, x 는 1.03, f(x) 는 56.8 입니다. 해가 아닙니다. 이 함수는 2.165 에서 극소를 갖는데 그 값이 31.3 으로 0 보다 커서, 그 근처에는 x 축과 만나는 점이 없습니다. -1 에서 출발한 경로는 그 근처에서 맴돌다가 최대 반복에 닿았습니다. 함수는 오류 없이 x 를 돌려줍니다. 반환된 x 만 보면 해로 착각합니다. 그래서 iter 가 max_iter 에 닿았는지, f(x) 가 0 에 가까운지를 함께 확인합니다.

해가 여러 개인 함수라면 어느 해로 갈지를 초기값이 결정합니다. 최대가능도추정에서 로그가능도에 봉우리가 여러 개면, 초기값에 따라 전역 최대점이 아닌 다른 봉우리에서 멈출 수 있습니다. 그래서 실무에서는 초기값을 여러 개 잡아 돌려 보고 비교합니다.

왼쪽 아래 표가 이 절에서 newton() 에 넣는 두 함수의 목록입니다. 방정식의 해에는 f 와 f’, 극값에는 f’ 와 f’’, 회귀와 로지스틱 회귀에는 기울기 벡터와 헤세 행렬을 넣습니다.

오른쪽 코드. 5.2 에서 쓴 f 와 fp 를 그대로 쓰고, 2계 도함수 fpp 만 손으로 구해 새로 만듭니다. 맞게 미분했는지 D() 를 두 번 써서 확인합니다. R 이 기호로 미분해 주는 함수입니다. 출력 5 * (3 * (2 * x)) - 7 * 2 를 정리하면 30x - 14 로 같습니다. 이것도 대조입니다.

그리고 newton() 의 f 자리에 fp, fp 자리에 fpp 를 넣습니다. 출력을 보세요. 초기값 다섯 개가 두 곳으로 갈라집니다. 2.165 쪽은 f’’ 이 양수라 극소, -1.232 쪽은 f’’ 이 음수라 극대입니다. 알고리즘은 기울기가 0 인 곳을 찾을 뿐, 거기가 극소인지 극대인지는 알려 주지 않습니다. 마지막 열처럼 2계 도함수의 부호를 따로 계산해 확인합니다.

게다가 극소라고 해서 전체에서 제일 작은 값은 아닙니다. 이 f 는 x가 작아지면 끝없이 내려갑니다. 로그가능도에 봉우리가 여러 개면 초기값에 따라 다른 봉우리에 올라갑니다. 초기값이 도달하는 해를 정한다는 5.3절의 내용이 최적화에서도 성립합니다.

5.5 회귀: 같은 newton() 에 ∇S 와 H 넣기

mpg 를 wt 로 설명, 잔차제곱합 최소화

\[S(\boldsymbol\beta) = (\mathbf{y} - \mathbf{X}\boldsymbol\beta)^\top(\mathbf{y} - \mathbf{X}\boldsymbol\beta)\]

\[\nabla S = -2\mathbf{X}^\top(\mathbf{y} - \mathbf{X}\boldsymbol\beta), \quad \mathbf{H} = 2\mathbf{X}^\top\mathbf{X}\]

점화식에 대입하면 초기값이 소거됨

\[\boldsymbol\beta_1 = (\mathbf{X}^\top\mathbf{X})^{-1}\mathbf{X}^\top\mathbf{y}\]

정규방정식 \(\mathbf{X}^\top\mathbf{X}\boldsymbol\beta = \mathbf{X}^\top\mathbf{y}\) 의 해: 원래 2차 함수이므로 한 걸음에 끝남

X <- cbind(1, mtcars$wt)                 # 첫 열 = 절편
y <- mtcars$mpg
grad_S <- function(b) -2 * t(X) %*% (y - X %*% b)
hess_S <- function(b) 2 * t(X) %*% X     # b 가 없다
r <- newton(grad_S, hess_S, c(0, 0))
r$path                                   # 0, 1, 2번째 위치
         [,1]      [,2]
[1,]  0.00000  0.000000
[2,] 37.28513 -5.344472
[3,] 37.28513 -5.344472
coef(lm(mpg ~ wt, data = mtcars))

이제 통계 문제입니다. mtcars 에서 연비를 무게로 설명하는 단순선형회귀. 최소제곱은 잔차제곱합을 최소로 만드는 계수를 찾는 겁니다. 행렬로 쓰면 왼쪽 위 식입니다. X는 첫 열이 전부 1인 행렬이에요. 절편 때문입니다.

기울기와 헤세 행렬을 구하면 그 아래 식입니다. 오른쪽 코드에서 이 두 식을 그대로 함수 grad_S 와 hess_S 로 옮겼습니다. 헤세 행렬 2X’X 에는 베타가 들어 있지 않습니다. 그래서 hess_S 는 인수 b 를 받기만 하고 쓰지 않습니다.

그리고 5.2 에서 만든 newton() 의 f 자리에 grad_S, fp 자리에 hess_S 를 넣고 (0, 0) 에서 출발합니다. 함수는 한 줄도 고치지 않았습니다. solve() 가 2×2 연립방정식을 풉니다.

r$path 를 보세요. 첫 줄이 출발점 (0, 0), 둘째 줄이 한 걸음 뒤 37.29, -5.34, 셋째 줄도 같습니다. 한 걸음 만에 도착했고, 두 번째 걸음은 갱신 폭이 0 에 가까워 수렴 조건으로 멈췄습니다.

(클릭) lm() 과 대조하면 같습니다.

왜 한 걸음일까요? 왼쪽 가운데. 점화식에 대입하면 초기값이 지워지고 (X’X)⁻¹X’y 만 남습니다. 회귀분석에서 배우는 최소제곱추정량 공식, 정규방정식의 해 그대로입니다. 잔차제곱합이 베타의 2차 함수라서 그렇습니다. 뉴턴-랩슨은 매 걸음 함수를 2차 함수로 근사하는데, 원래 함수가 2차 함수면 근사한 함수가 원래 함수와 같으므로 한 걸음에 최소점에 닿습니다.

그러니까 여러분이 배운 정규방정식은, 뉴턴-랩슨이 한 걸음에 끝나는 특별한 경우라고 볼 수 있습니다. 참고로 lm()은 정규방정식을 그대로 풀지 않고 QR 분해를 씁니다. X’X 를 직접 만들어 풀 때보다 반올림 오차가 작습니다.

5.6 로지스틱 회귀: 같은 newton() 으로 반복

am: 자동 0, 수동 1 → 수동일 확률을 무게로 설명

\[p_i = \frac{1}{1 + \exp\{-(\beta_0 + \beta_1 x_i)\}}\]

로그가능도를 최대화

\[\ell(\boldsymbol\beta) = \sum_i \{ y_i \log p_i + (1 - y_i)\log(1 - p_i) \}\]

\[\nabla\ell = \mathbf{X}^\top(\mathbf{y} - \mathbf{p}), \quad \mathbf{H} = -\mathbf{X}^\top\mathbf{W}\mathbf{X}\]

\(\mathbf{W} = \mathrm{diag}\{p_i(1-p_i)\}\)

\(\mathbf{H}\) 안에 \(\boldsymbol\beta\) 가 있음 → 걸음마다 달라짐 → 반복 필요

기울기와 헤세 행렬만 새로 작성

am <- mtcars$am
prob <- function(b) as.vector(1 / (1 + exp(-X %*% b)))
grad_l <- function(b) t(X) %*% (am - prob(b))      # 기울기
hess_l <- function(b) {                            # 헤세 행렬
  p <- prob(b)
  -t(X) %*% (X * (p * (1 - p)))   # X 의 각 행에 p(1-p) 를 곱함
}
r_logit <- newton(grad_l, hess_l, c(0, 0))
r_logit$x

r_logit$iter

반복은 newton() 의 for 문이 맡음: 걸음마다 확률 p 를 새로 계산해 H 를 다시 만듦

이번엔 반응변수가 0 아니면 1인 경우입니다. 합격과 불합격, 발병 여부 같은 거요. mtcars 의 am 은 자동 변속기면 0, 수동이면 1입니다. 수동일 확률을 무게로 설명하는 모형이 로지스틱 회귀모형입니다. 위의 식처럼 확률을 S자 곡선으로 놓습니다.

계수는 로그가능도를 최대로 만드는 값입니다. 기울기와 헤세 행렬을 구하면 가운데 식이 나오는데, 앞의 회귀와 다른 점은 헤세 행렬 안에 베타의 함수인 p 가 들어 있다는 겁니다. 회귀모형에서는 헤세 행렬이 상수였지요. 여기서는 걸음마다 헤세 행렬이 바뀝니다. 그래서 한 걸음에 안 끝나고 반복해야 합니다. 정규방정식처럼 한 번에 계산하는 공식도 없습니다.

오른쪽 코드에서 새로 쓴 것은 세 함수뿐입니다. prob 은 계수 b 에서 확률 p 를 계산하고, grad_l 과 hess_l 은 왼쪽 두 식을 그대로 옮긴 것입니다. X * (p * (1 - p)) 는 X 의 각 행에 p(1-p) 를 곱하는 것으로, 대각행렬 W 를 만들지 않고 W 를 곱한 것과 같은 결과를 냅니다.

반복은 newton() 의 for 문이 맡습니다. 걸음마다 grad_l 과 hess_l 이 현재 계수로 확률을 새로 계산하므로, 헤세 행렬이 걸음마다 바뀌는 계산이 됩니다. 갱신 폭이 10의 -8승보다 작아지면 멈춥니다.

1,272걸음이 드는 방법을 쓰는 이유는 오른쪽 표의 한 걸음의 비용에 있습니다. 뉴턴-랩슨은 모수가 p개면 p×p 헤세 행렬을 만들고 연립방정식을 풀어야 합니다. 경사하강법은 길이 p인 기울기 벡터 하나면 됩니다.

모수가 두세 개인 통계모형이면 헤세 행렬이 2×2, 3×3 이라 한 걸음의 계산이 작고, 걸음 수가 적은 뉴턴-랩슨이 전체 계산량도 적습니다. glm()이 그래서 뉴턴-랩슨 계열을 씁니다. 그런데 여러분이 쓰는 LLM 은 모수가 수십억 개입니다. 모수가 10억 개만 돼도 헤세 행렬의 원소는 10의 18승 개이고, 원소 하나에 8바이트면 8 엑사바이트라 메모리에 담을 수 없습니다. 그래서 딥러닝 모형은 경사하강법의 변형으로 학습합니다.

1절에서 비용은 시간과 메모리 두 가지라고 했지요. 전체 계산량은 걸음 수 곱하기 한 걸음의 계산량이고, 뉴턴-랩슨은 한 걸음마다 p×p 행렬을 저장할 메모리도 필요합니다. 모수가 적으면 뉴턴-랩슨, p×p 행렬을 저장할 수 없을 만큼 많으면 경사하강법을 씁니다.

이 수업에서 경사하강법은 여기까지 다룹니다. 학습률을 자동으로 조절하는 방법은 기계학습을 다루는 과목에서 배웁니다.

이 절이 답하는 질문: 세 가지 검증을 통과한 생성 코드는 요구사항에 없는 입력에서 어떻게 동작하는가?

마지막 6절입니다. 3절의 세 가지 검증, 곧 전수 검사, 경계 사례, 정답이 알려진 함수와의 대조를 AI가 만들어 준 코드에 적용하고, 요구사항에 없는 입력도 넣어 봅니다.

6.1–6.2 프롬프트 = 요구사항

중요

작업 요구사항

오름차순으로 정렬된 수치형 벡터 vec 과 값 target 을 받아, target 이 있으면 그 위치를, 없으면 NA 를 반환하는 재귀 이진 탐색 함수를 R 로 작성하라.

# 생성: Claude Opus 5, 2026-09-11. 수정 없이 그대로 수록.
binary_search_rec <- function(vec, target, lo = 1, hi = length(vec)) {
  if (lo > hi) return(NA_integer_)
  mid <- (lo + hi) %/% 2
  if (vec[mid] == target) return(mid)
  else if (vec[mid] > target) binary_search_rec(vec, target, lo, mid - 1)
  else binary_search_rec(vec, target, mid + 1, hi)
}
  • 3.3절에서 수정한 rbinary_search2() 와 동일한 구조
  • 종료 조건도 lo > hi 로 올바름
  • 그럼에도 검증 절차 수행

프롬프트는 곧 요구사항입니다.

AI에게 작업을 시킬 때 쓰는 문장, 곧 프롬프트는 소프트웨어 공학에서 말하는 요구사항에 해당합니다. 요구사항에 적지 않은 경우는 구현이 임의로 정합니다. 사람에게 일을 시킬 때도 지시에 없는 부분은 일하는 사람이 정합니다. 6.4절에서 그 예를 봅니다.

위 상자가 제가 실제로 준 요구사항입니다. 읽어 보세요. 정렬된 벡터와 값을 받아서, 있으면 위치를, 없으면 NA를 반환하는 재귀 이진 탐색.

한 문장으로 썼고, 중복값이나 정렬되지 않은 입력을 어떻게 처리할지는 적지 않았습니다.

아래가 받은 코드입니다. 받은 그대로 고치지 않고 실었습니다. 주석에 모델명과 날짜를 적어 뒀어요. AI 응답을 실을 때 언제 어느 모델에서 받았는지 기록하는 것이 이 강의노트의 규칙입니다.

코드를 보세요. 3.3절에서 우리가 고친 rbinary_search2() 와 구조가 같습니다. 종료 조건도 lo > hi 입니다.

그런데 구조가 같아 보인다는 것은 검증이 아닙니다. 3절의 세 가지 검증을 돌리겠습니다.

요구사항에 없는 입력, 곧 중복값이 있는 벡터와 정렬되지 않은 벡터는 다음 슬라이드에서 넣어 봅니다.

6.4 요구사항이 규정하지 않은 부분

d <- c(1, 3, 3, 3, 5, 7)
c(이_구현 = binary_search_rec(d, 3), R의_match = match(3, d))   # 중복값
  이_구현 R의_match 
        3         2 
u <- c(19, 7, 2, 15, 10)                                        # 정렬 안 된 입력
c(반환 = binary_search_rec(u, 19), 실제_위치 = which(u == 19))
     반환 실제_위치 
       NA         1

미규정 1, 중복값

어느 위치를 반환할지 요구사항에 없음
→ 구현이 임의로 결정 (match() 는 가장 앞, 이 구현은 중간)

미규정 2, 정렬되지 않은 입력

전제가 깨졌을 때의 동작 규정 없음
→ 오류도 경고도 없이 “없다”고 반환

오류 없이 잘못된 결과를 반환하면 그 값이 다음 분석에 그대로 쓰임: 명시적으로 실패하면 그 자리에서 멈춰 알아챌 수 있음

(클릭) 요구사항에 없는 입력 두 가지를 넣어 봤습니다.

첫째, 중복값. c(1, 3, 3, 3, 5, 7) 에서 3을 찾으면요? 이 구현은 3번 자리를 줍니다. R의 match() 는 2번 자리를 줍니다. 3이 2, 3, 4번에 다 있으니까 둘 다 틀린 건 아닙니다.

이 함수가 첫 번째 위치를 돌려준다고 가정하고 다음 계산에 쓰면 결과가 틀립니다. 어느 위치를 돌려줄지 요구사항에 적지 않았으므로, 이 구현은 처음 비교한 가운데 위치 3 을 돌려줬습니다.

둘째, 정렬 안 된 입력. c(19, 7, 2, 15, 10) 에서 19를 찾습니다. 19는 1번 자리에 있는데 NA가 나옵니다.

오류 메시지와 경고 없이 “없다” 는 뜻의 NA 를 돌려줍니다. 이런 동작을 조용히 틀린다고 합니다.

맨 아래 상자를 읽겠습니다.

오류 없이 잘못된 결과를 반환하면, 그 값이 다음 분석에 그대로 쓰입니다.

함수가 오류로 멈추면 그 자리에서 원인을 찾을 수 있습니다. 조용히 틀리면 실행이 계속되어, 그 값이 보고서나 논문의 표에 그대로 들어갈 수 있습니다.

6.4 AI 생성 코드에서 자주 나타나는 오류

주의

  • 경계 조건: < 와 <=, mid 와 mid - 1 혼동
  • 전제 미검사: “정렬되어 있다”, “NA 가 없다” 등 미확인
  • 빈 입력: 길이 0인 벡터에서 인덱스 1 참조
  • 요구사항의 공백: 미규정 부분을 임의 결정 후 미고지

이 장의 rbinary_search(), 중복값, 정렬 안 된 입력: 오류 메시지 없이 결과 반환
NA 가 든 입력만 오류로 멈춤 → 실행만으로는 발견 불가, 검증 절차 필요

각 유형이 실제로 나타나는 모양

if (maxL <= minL) return(NA)   # 경계 조건
#     ^^ minL > maxL 이어야 함

binary_search_rec(u, 19)       # 전제 미검사
# u 가 정렬 안 됨 → 조용히 NA

vec[1]                         # 빈 입력
# length(vec) == 0 이면 NA

binary_search_rec(d, 3)  # 3    # 요구사항 공백
match(3, d)              # 2    # 어느 쪽이 맞는가?

첫 줄은 사람이 쓴 이 수업의 코드. AI만의 문제가 아님

오류 유형 이 검증에서 잡힘
경계 조건 전수 검사: 모든 원소를 넣어 보면 40% 실패(20개 중 8개)
전제 미검사 경계 사례: 정렬 안 된 입력을 일부러 넣어 봄
빈 입력 경계 사례: 길이 0, 길이 1
요구사항의 공백 정답이 알려진 기준과 대조: which(), match() 와 비교

AI 코드에서 자주 나오는 오류 유형을 정리했습니다.

첫째, 경계 조건. < 와 <=, mid 와 mid - 1 처럼 부등호나 위치를 잘못 고른 오류입니다. 3절의 rbinary_search() 가 이 유형이었고, 이 코드는 사람이 썼습니다. 경계 조건 오류는 사람이 쓴 코드에서도 나옵니다.

둘째, 전제 미검사. 입력이 정렬되어 있다고 가정하고, 실제로 정렬되어 있는지 확인하는 코드가 없습니다.

셋째, 빈 입력 처리 누락. 길이 0 인 벡터에서 vec[1] 을 참조하면 오류 없이 NA 가 나옵니다.

넷째, 요구사항의 공백을 임의로 메우고 알려 주지 않는 것.

아래 상자를 보세요. 오늘 본 rbinary_search(), 중복값, 정렬되지 않은 입력 세 경우는 오류 메시지 없이 결과를 냈습니다. 벡터에 NA 가 들어 있을 때만 missing value where TRUE/FALSE needed 오류로 멈춥니다.

그래서 오류 없이 실행되었다는 것만으로는 결과가 맞는지 알 수 없습니다.

AI를 쓰지 말라는 뜻은 아닙니다. 6.2절의 코드도 AI가 만든 코드입니다. 받은 코드에는 전수 검사, 경계 사례, 정답이 알려진 함수와의 대조를 돌리고, 요구사항에 적지 않은 입력, 오늘의 예로는 중복값과 정렬되지 않은 벡터를 따로 넣어 봅니다.

정리

비용 = 수행 시간 + 메모리

  • 결과가 같은 코드도 연산 횟수의 증가율이 다름
  • 같은 알고리즘도 입력에 따라 다름: 평가 기준은 최악의 경우
  • 차수 차이는 하드웨어 향상으로 메워지지 않음

재귀

  • 종료 조건 + 재귀 단계
  • 깊이 \(n\) 이면 스택 프레임 \(n\) 개 사용

최적화

  • 통계의 추정 = 최적화 → 도함수의 근 찾기
  • 뉴턴-랩슨 걸음 수가 적음, 경사하강법 한 걸음의 계산량이 적음

검증

  • 예제 몇 개 통과 ≠ 정확성의 근거
  • 전수 검사, 경계 사례, 정답이 알려진 기준과의 대조
  • 오류 메시지 없는 결함은 절차로만 발견

AI와 함께

  • 프롬프트 = 요구사항
  • 요구사항이 규정하지 않은 곳에서 구현이 갈라짐

정리하겠습니다.

왼쪽 위. 비용은 수행 시간과 메모리 두 가지입니다. “비싸다” 고 할 때는 연산 횟수인지 메모리인지 함께 말합니다. 그리고 비교할 때는 한 번 잰 값보다 n 이 커질 때 연산 횟수가 늘어나는 비율, 곧 증가율을 봅니다.

같은 알고리즘도 입력에 따라 비교 횟수가 다릅니다. 퀵 정렬은 무작위 입력 1,000개에서 10,569번 비교했지만 이미 정렬된 입력에서는 버블 정렬과 같은 499,500번 비교했습니다.

왼쪽 가운데. 재귀는 종료 조건과 재귀 단계 두 부분입니다. 종료 조건은 경계 바로 바깥의 입력으로 확인합니다. recursive_sum 은 n = 0 에서 멈추지 않았고, n == 1 을 n <= 1 로 고쳐서 멈췄습니다. 호출 깊이가 n 이면 스택 프레임 n 개를 쓰고, R 의 기본 설정에서는 깊이 5000 에서 오류가 납니다.

왼쪽 아래. 통계의 추정은 최적화이고, 최적화는 결국 도함수의 근을 찾는 일입니다. 뉴턴-랩슨은 걸음 수가 적고, 경사하강법은 한 걸음의 계산량이 적습니다. 이 장의 회귀에서는 1걸음 대 1,272걸음이었습니다. 뉴턴-랩슨은 한 걸음마다 p×p 헤세 행렬을 저장하고 연립방정식을 풀어야 해서, 여기서도 비용은 시간과 메모리 두 가지입니다.

오른쪽 위는 검증입니다. 예제 몇 개 통과한 건 정확성의 근거가 아닙니다. rbinary_search() 는 저자가 고른 예제를 통과했지만 20개 중 8개를 못 찾았습니다. 코드를 받으면 전수 검사, 경계 사례, 대조 세 가지를 돌립니다.

오른쪽 아래. 프롬프트는 요구사항입니다. 그리고 요구사항에 적지 않은 경우는 구현마다 다르게 정해집니다. 중복값에서 이 구현은 3번, match() 는 2번 자리를 돌려줬습니다. 결과가 갈릴 수 있는 경우는 AI에게 시킬 때 요구사항에 적습니다.
