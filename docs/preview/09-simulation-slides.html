1절입니다. 시뮬레이션은 비행 시뮬레이터처럼, 현실에서 해 보기 어려운 일을 모형 안에서 대신 해 보는 방법입니다.

통계에서 말하는 시뮬레이션은 조금 더 좁습니다. 확률 모형에서 난수로 가상의 자료를 만들고, 같은 실험을 아주 많이 반복해서 그 결과로 확률이나 기댓값을 근사합니다. 이걸 몬테카를로 방법이라고 부릅니다. 2차 세계대전 중 원자폭탄 개발 계획에서 이 계산을 하던 연구자들이 도박 도시 몬테카를로의 이름을 암호명으로 붙인 데서 왔습니다.

이 절의 질문은 하나입니다. 몇 번 반복하면 믿을 만한가.

1.1 생일이 같은 사람이 있을까

40명이 듣는 이 강의실에 생일이 같은 두 사람이 있을 확률은?

모형의 가정

  • 생일은 365일 가운데 하루, 모두 같은 확률
  • 사람끼리 독립, 2월 29일은 없음

한 번의 실험

  • 40명의 생일을 무작위로 뽑음
  • 겹치는 생일이 있는지 확인
has_shared_birthday <- function(n) {
  birthdays <- sample(1:365, n,
                      replace = TRUE)
  any(duplicated(birthdays))  # 겹침이 있는가
}

set.seed(2026)
has_shared_birthday(40)
[1] TRUE
has_shared_birthday(40)
[1] TRUE

한 번의 결과는 TRUE 또는 FALSE 일 뿐, 확률이 아님

일상의 질문으로 시작하겠습니다. 이 강의실에 40명이 있다고 합시다. 생일이 같은 두 사람이 있을 확률은 얼마일까요? 1년이 365일이니까 40명이면 별로 안 겹칠 것 같지요.

40명을 여러 번 모아 볼 수는 없지만 컴퓨터 안에서는 됩니다. 먼저 모형의 가정을 정합니다. 생일은 365일 가운데 하루를 같은 확률로 갖고, 사람끼리는 독립이고, 2월 29일은 없다고 칩니다. 이 가정이 중요합니다. 뒤에서 다시 나옵니다.

오른쪽 코드가 ‘한 반을 만드는’ 절차입니다. 365일에서 40개를 복원 추출로 뽑습니다. 같은 날이 또 나올 수 있으니까 복원 추출이지요. 그리고 duplicated() 로 겹치는 게 있는지 봅니다.

두 번 돌렸더니 둘 다 TRUE 가 나왔습니다. 그런데 이건 확률이 아닙니다. 한 번 해 봤더니 겹쳤다는 것뿐입니다.

예측입니다. 같은 실험을 만 번 반복해서 TRUE 의 비율을 구하면 얼마가 나올까요?

replicate() 는 식을 여러 번 실행해서 결과를 모아 주는 함수입니다. TRUE 는 1, FALSE 는 0 으로 계산되니까 평균을 내면 TRUE 의 비율이 됩니다.

10% 안팎, 50% 안팎, 90% 안팎. 손을 들어 봅시다.

아래 상자 두 번째 줄이 중요합니다. 실제 생일은 고르게 퍼져 있지 않습니다. 계절도 있고 쌍둥이도 있지요. 모형이 그걸 반영하지 않으면 만 번이 아니라 백만 번을 돌려도 그 차이는 안 줄어듭니다. 반복은 우연의 오차만 줄여 줍니다. 시뮬레이션의 답은 모형의 답입니다.

1.2 반복할수록 이론값으로

  • 대수의 법칙: 독립인 반복에서 비율은 확률로, 평균은 기댓값으로 수렴
  • 처음 몇십 번은 크게 흔들림

확률과 기댓값은 ’무한히 반복했을 때’의 값: 컴퓨터로 충분히 많이 반복해 근사

시뮬레이션이 왜 통하는지 보겠습니다. 반복할 때마다 그때까지의 비율을 기록해서 그린 겁니다. 점선이 이론값입니다.

처음 몇십 번은 위아래로 크게 흔들립니다. 그러다 반복이 쌓일수록 점선 근처로 모입니다.

이게 통계학개론에서 배운 대수의 법칙입니다. 독립인 실험을 반복하면 사건이 일어난 비율은 그 사건의 확률로, 평균은 기댓값으로 다가갑니다. 확률과 기댓값은 원래 ’무한히 반복했을 때’로 정의되지요. 무한히는 못 하지만 충분히 많이는 할 수 있습니다. 컴퓨터가 그걸 해 줍니다.

그러면 ’충분히’가 몇 번이냐. 다음 슬라이드입니다.

예측해 보자

반복 횟수 \(B\) 를 100배로 늘리면 추정값의 오차와 실행 시간은?

\[\text{표준오차} = \sqrt{\frac{p(1-p)}{B}}\]

A 오차 1/100, 시간 100배

B 오차 1/10, 시간 100배

C 오차 1/10, 시간 10배

반복 결과의 비율: 성공 확률이 \(p\) 인 시행을 \(B\) 번 한 표본비율, 그 표준오차가 몬테카를로 오차

예측입니다. 반복 결과의 비율은 결국 표본비율입니다. 성공 확률이 p 인 시행을 B 번 해서 성공한 비율이지요. 그러니 표준오차는 통계학개론에서 배운 대로 루트 p(1-p)/B 입니다. 이걸 몬테카를로 오차라고 부릅니다.

주의

시드는 결과를 고정할 뿐, 옳게 만들지 않음

  • 8장 옛 노트: 예제의 시드가 우연히 버그를 가림
  • 시드를 바꾸어도 몬테카를로 오차 안에서만 흔들리는지 확인

컴퓨터는 정해진 규칙대로 계산하는 기계라서 진짜 난수를 못 만듭니다. R 의 난수는 씨앗이라고 부르는 출발값에서 시작해 규칙대로 계산한 수열입니다. 그래서 유사난수라고 합니다.

왼쪽 코드를 보세요. 같은 씨앗으로 시작하면 같은 수가 나옵니다. 이게 set.seed() 의 역할입니다. 보고서에 실은 결과를 다른 사람이, 또는 한 달 뒤의 내가 똑같이 다시 얻을 수 있게 해 줍니다.

그런데 오른쪽 경고 상자가 중요합니다. 시드는 결과를 고정할 뿐 옳게 만들지 않습니다. 8장을 만들 때 옛 노트를 감사했더니, 예제의 시드가 우연히 버그를 가려서 렌더된 노트에서는 멀쩡해 보이던 코드가 있었습니다.

그래서 시드 하나로 얻은 결과가 그럴듯하면 시드를 바꿔 봅니다. 위의 다섯 값이 시드만 바꾼 결과입니다. 0.885 에서 0.894 사이. 이론값 0.891 에서 표준오차의 두 배 남짓 안에서만 흔들립니다. 이러면 믿을 만합니다.

2.1 주사위 게임의 기댓값

3.1 점을 뿌려 원주율 구하기

  • 비유: 정사각형 과녁에 눈을 감고 다트 던지기
  • 사분원 안에 꽂힐 확률 = 넓이의 비 \(\pi/4\)
  • 꽂힌 비율의 4배 → 원주율: 적중법(hit-or-miss)
estimate_pi <- function(n) {
  x <- runif(n)              # 가로 좌표
  y <- runif(n)              # 세로 좌표
  4 * mean(x^2 + y^2 <= 1)   # 안에 든 비율의 4배
}
set.seed(2026)
estimate_pi(1000)
[1] 3.212

한 변이 1 인 정사각형 과녁에 눈을 감고 다트를 던진다고 해 봅시다. 과녁 안에 반지름 1 인 사분원을 그려 두면, 다트가 사분원 안에 꽂힐 확률은 넓이의 비, π/4 입니다.

그러니까 다트를 많이 던져서 안에 꽂힌 비율을 네 배 하면 원주율이 나옵니다. 왼쪽 그림이 점 2,000개를 뿌린 겁니다. 청록색이 안에 든 점입니다.

코드는 세 줄입니다. 가로 좌표, 세로 좌표를 균일분포에서 뽑고, x² + y² 이 1 이하인 비율에 4를 곱합니다. 점 천 개로 3.212. 아직 많이 부정확하지요. 점을 늘리면 어떻게 될까요?

3.2 표본평균 방법

\[\int_a^b f(x)\,dx = (b - a)\,E[f(U)], \quad U \sim \text{Uniform}(a, b)\]

  • 구간에서 점을 고르게 뽑아 함수값의 평균 × 구간의 길이
  • 옛 노트의 함수, 구간 \([1, 3]\)
f <- function(x) 2 + cos(x + sin(atan(x)) + 3)
mc_mean <- function(n, a = 1, b = 3)
  (b - a) * mean(f(runif(n, a, b)))

적중법은 점이 안에 들었는지, 0 아니면 1 만 씁니다. 정보를 버리는 셈이지요. 더 나은 방법이 있습니다.

적분을 기댓값으로 바꾸는 겁니다. U 가 구간 a 에서 b 의 균일분포를 따르면, 적분값은 구간의 길이 곱하기 f(U) 의 기댓값입니다. 그러니까 구간에서 점을 고르게 뽑아서 함수값의 평균을 내고, 구간의 길이를 곱하면 됩니다. 이걸 표본평균 방법이라고 합니다.

3.3 뷔퐁의 바늘

  • 1777년 뷔퐁의 문제: 간격 \(d\) 인 평행선에 길이 \(l\) 인 바늘을 떨어뜨리면 선에 걸칠 확률은 \(2l / (\pi d)\)
  • 걸친 비율 \(\hat P\) 에서 \(\hat\pi = 2l / (d\hat P)\)
buffon_pi <- function(n, l = 1, d = 2) {
  a <- runif(n, 0, d / 2)   # 중심에서 선까지
  theta <- runif(n, 0, pi)  # 바늘의 각
  p_hat <- mean(a <= (l / 2) * sin(theta))
  2 * l / (d * p_hat)
}
set.seed(2026)
buffon_pi(1e6)
[1] 3.139678

주의

이 코드의 허점

  • 원주율을 구하려고 runif(n, 0, pi) 에서 이미 원주율을 사용
  • 실제 바늘 던지기는 원주율을 몰라도 가능
  • 코드가 무엇을 전제하는지 읽어 내는 것도 검증

역사적인 예를 하나 보겠습니다. 1777년 프랑스의 박물학자 뷔퐁이 낸 문제입니다. 평행선이 그어진 마룻바닥에 바늘을 떨어뜨리면 선에 걸칠 확률은 얼마인가. 답은 2l 나누기 π d 입니다. 식에 π 가 들어 있으니까, 바늘을 많이 던져서 걸친 비율을 구하면 원주율을 거꾸로 구할 수 있습니다.

코드는 바늘 중심에서 가까운 선까지의 거리 a 와 바늘의 각 θ 를 균일분포에서 뽑고, a 가 l/2 sin θ 이하이면 걸친 것으로 셉니다. 백만 번 던져서 3.1397. 오른쪽 동영상은 옛 노트에 있던 것으로, 500번 던지는 동안 추정값이 참값으로 다가가는 모습입니다. (재생)

그런데 오른쪽 경고 상자를 보세요. 이 코드에는 허점이 있습니다. 원주율을 구하겠다면서 각도를 뽑을 때 runif(n, 0, pi), 이미 pi 를 썼습니다. 실제로 바늘을 던지는 실험은 원주율을 몰라도 할 수 있지만, 이 코드는 원주율을 알아야 돌아갑니다.

결과가 맞는 것과 별개로, 코드가 무엇을 전제하고 있는지 읽어 내는 것. 이것도 검증입니다.

이 절이 답하는 질문: 이 방법은 이름표의 약속을 지키는가?

5절입니다. 신뢰구간과 가설검정은 ’같은 연구를 무수히 반복하면’이라는 전제 위에 서 있습니다. 95% 신뢰구간은 반복의 95% 에서 모수를 포함한다고 약속하고, 유의수준 5% 검정은 귀무가설이 참인 연구의 5% 에서만 잘못 기각한다고 약속합니다.

시뮬레이션은 그 반복을 실제로 해 봅니다. 참값을 우리가 정해 두었으니까, 방법이 약속을 지키는지 직접 셀 수 있습니다.

5.1 신뢰구간 만들기

mu <- 50; sigma <- 10; n <- 20   # 참값
ci_mean <- function(x, level = 0.95) {
  half <- qt(1 - (1 - level) / 2,
             df = length(x) - 1) *
          sd(x) / sqrt(length(x))
  c(lower = mean(x) - half,
    upper = mean(x) + half)
}
set.seed(2026)
x <- rnorm(n, mean = mu, sd = sigma)
ci_mean(x)
   lower    upper 
41.55921 50.57116 
t.test(x)$conf.int[1:2]   # 내장 함수와 대조
[1] 41.55921 50.57116

\[\bar{x} \pm t_{0.975,\,n-1}\,\frac{s}{\sqrt{n}}\]

  • 참값을 정해 둠: \(\mu = 50\), \(\sigma = 10\), \(n = 20\)
  • 직접 만든 함수는 먼저 내장 함수와 대조
  • 두 결과가 같음: 이제 이 함수로 반복

모평균에 대한 95% 신뢰구간 공식입니다. 통계학개론에서 배운 그대로입니다.

참값을 먼저 정해 둡니다. 모평균 50, 모표준편차 10, 표본 크기 20.

신뢰구간을 구하는 함수를 직접 만들었습니다. 직접 만든 함수는 먼저 내장 함수와 대조합니다. t.test() 가 내주는 신뢰구간과 같은지 봤더니 같습니다. 이제 이 함수로 반복하겠습니다.

5.2 1종 오류와 p-값의 분포

p < 0.05 인 비율: 0.0496

  • 귀무가설이 참이면 p-값은 균일분포
  • 0.05 보다 작은 p-값이 약 5%: 그것이 1종 오류율
  • 귀무가설이 참인 연구 20개 중 하나는 p < 0.05

p-값: 귀무가설이 참일 때 관측한 것 이상으로 극단적인 통계량이 나올 확률, 귀무가설이 참일 확률도 1종 오류 확률도 아님

답은 C 입니다. 1 근처에 몰리지 않습니다. 0 과 1 사이에 고르게 퍼집니다. 균일분포입니다.

그래서 0.05 보다 작은 p-값이 약 5% 나오고, 이게 곧 1종 오류율입니다. 0.0496. 약속대로입니다.

이게 무슨 뜻이냐면, 한 번의 연구에서 p = 0.03 을 얻었다고 해서 그게 우연이 아니라는 보장은 없다는 겁니다. 차이가 전혀 없는 연구 20개 가운데 하나는 그런 p-값을 냅니다.

오른쪽 상자의 정의를 정확히 기억하세요. p-값은 귀무가설이 참이라고 할 때 관측한 것만큼 극단적인 결과가 나올 확률입니다. 귀무가설이 참일 확률이 아닙니다. 1종 오류를 범할 확률도 아닙니다. 1종 오류율은 검정 전에 정해 두는 α 입니다. 옛 노트에 이 부분이 잘못 적혀 있어서 이번에 바로잡았습니다.

시뮬레이션 코드도 코드라서 틀릴 수 있습니다. 오류 없이 그럴듯한 숫자를 내는 실수 세 가지입니다.

첫째, 반복하는 함수 안에서 set.seed() 를 부르는 것. 부를 때마다 같은 씨앗으로 돌아가니까 천 번 반복해도 같은 실험 한 번을 천 번 복사한 겁니다. 서로 다른 p-값이 1개뿐이지요. 1종 오류율이 0 이 나왔습니다. 이론값 0.05 와 대조했으면 바로 알았을 겁니다. 시드는 맨 앞에서 한 번만.

둘째, rnorm() 의 세 번째 인수는 분산이 아니라 표준편차입니다. 분산 4 를 원해서 4 를 넣었더니 분산이 16 인 자료가 나왔습니다. 만든 자료의 분산을 한 번만 확인했어도 알았을 겁니다.

셋째가 가장 알기 어렵습니다. sample() 에 원소가 두 개인 벡터를 넣으면 섞어 줍니다. 그런데 원소가 하나, 7 하나만 넣으면 7 을 섞는 게 아니라 1부터 7까지를 섞습니다. 도움말에 적혀 있는 동작입니다. 후보를 조건으로 좁히다가 하나만 남는 경계 사례에서 결과가 조용히 망가집니다. 원소를 섞으려면 위치를 섞으세요.

셋 다 오류 메시지가 없습니다. 그래서 먼저 답을 아는 경우로 시험하고, 만든 자료가 의도한 분포인지 평균과 분산을 확인한 다음에 씁니다.

7.1–7.2 프롬프트와 생성 코드

R로 독립 이표본 t-검정의 1종 오류율을 시뮬레이션으로 추정하는 함수를 만들어 줘. 두 집단의 표본 크기와 표준편차, 반복 횟수를 인수로 받고, 유의수준 0.05에서 귀무가설을 기각한 비율을 반환하면 돼.

# 생성: Claude Sonnet 5, 2026-09-12. 수정 없이 그대로 수록.
sim_type1_error <- function(n1, n2, sd1, sd2, nsim = 10000, alpha = 0.05, seed = NULL) {
  if (!is.null(seed)) set.seed(seed)

  reject_count <- 0

  for (i in seq_len(nsim)) {
    x <- rnorm(n1, mean = 0, sd = sd1)
    y <- rnorm(n2, mean = 0, sd = sd2)   # 귀무가설(H0: mu1 = mu2)이 참이 되도록 두 집단의 평균을 0으로 같게 둔다

    p_value <- t.test(x, y)$p.value
    if (p_value < alpha) reject_count <- reject_count + 1
  }

  reject_count / nsim
}

프롬프트입니다. 수업에서 흔히 쓸 법한 수준으로만 요청했습니다. 독립 이표본 t-검정의 1종 오류율을 시뮬레이션으로 추정하는 함수, 표본 크기와 표준편차와 반복 횟수를 받아서 기각 비율을 돌려 달라.

아래가 실제로 받은 응답의 코드입니다. 수정 없이 그대로 실었습니다. 응답 전문은 저장소의 ai-transcripts 폴더에 있습니다.

코드를 읽어 봅시다. 두 집단의 평균을 모두 0 으로 뽑습니다. 귀무가설이 참이 되게 한 거지요. 주석에도 그렇게 적혀 있습니다. t.test() 로 p-값을 구해서 alpha 보다 작으면 셉니다. seed 인수도 선택으로 두었습니다.

응답에는 설명도 붙어 있었습니다. 평균을 같게 둬야 1종 오류율이 된다는 것, t.test() 의 기본값이 Welch 검정이라는 것, seed 를 선택으로 둔 이유. 설명도 코드도 그럴듯합니다. 그래도 검증합니다.

결과 숫자만 옮기면 알아채기 어려움: 응답의 설명까지 읽어야 드러나는 차이

첫째가 가장 중요합니다. 요청에는 ’독립 이표본 t-검정’이라고만 썼습니다. 통계학개론에서는 보통 등분산 t-검정을 먼저 배우지요. 그런데 이 AI 는 t.test() 의 기본값인 Welch 검정을 골랐습니다. 그리고 그 선택을 응답의 설명에 밝혀 두었습니다. 좋은 응답입니다.

그런데 5.4 의 조건에서 두 검정은 0.054 대 0.266 으로 크게 다릅니다. 만약 학생이 알고 싶었던 게 수업에서 배운 등분산 t-검정의 오류율이었다면, 이 함수는 다른 질문에 정확하게 답한 겁니다. 숫자만 받아서 보고서에 옮겼다면 알아채기 어렵습니다. 응답의 설명까지 읽어야 드러납니다.

오른쪽은 나머지 미규정입니다. 분포를 정규분포로 고정했고 바꿀 수단이 없습니다. 추정값의 오차 없이 비율 하나만 돌려줍니다. 1절에서 추정값은 오차와 함께 읽으라고 했지요. 표본 크기가 1 이면 t.test() 가 오류로 멈춥니다. 이건 조용히 틀린 값을 내는 것보다는 낫습니다.

7.4 시뮬레이션 코드에서 자주 나타나는 오류

  • 귀무가설을 참으로 만들지 않음: 1종 오류율이라면서 두 평균을 다르게 뽑음 → 사실은 검정력을 잼
  • 방법을 명시하지 않음: var.equal 처럼 결과를 크게 바꾸는 선택을 기본값에 맡김
  • 반복 안의 시드: 모든 반복이 같은 자료를 씀
  • 오차 없는 결론: 0.053 이 0.05 와 다른지 판단하지 않음

사람이 쓴 코드도 마찬가지

# 옛 노트: '귀무가설이 참일 때'라는 설명 아래
x1 <- rnorm(n1, 0.75, 1.79)
x2 <- rnorm(n2, 2.33, 2.0)    # 두 모평균이 다름

공통점: 오류 메시지가 나오지 않음

답을 아는 경우와 대조하는 절차로만 발견

시뮬레이션 코드에서 자주 나타나는 오류를 정리하겠습니다.

첫째, 귀무가설을 참으로 만들지 않는 것. 1종 오류율을 구한다면서 두 집단의 평균을 다르게 뽑으면, 사실은 검정력을 재는 겁니다. 이번 AI 응답은 이 점을 스스로 짚었지요.

둘째, var.equal 처럼 결과를 크게 바꾸는 선택을 명시하지 않고 기본값에 맡기는 것. 셋째, 반복 안의 시드. 넷째, 몬테카를로 오차 없이 결론을 내는 것.

오른쪽을 보세요. 사람이 쓴 코드도 마찬가지입니다. 이 강의의 옛 노트에 ’귀무가설이 참일 때’라고 설명해 놓고 두 집단의 평균을 0.75 와 2.33 으로 다르게 뽑은 시뮬레이션이 실려 있었습니다. 제가 쓴 코드입니다. 이번 개편 때 감사하면서 찾았습니다. 그대로 돌려 보면 구간 100개 중 44개가 0 을 배제합니다. 1종 오류율이라면 5개 안팎이어야 하지요. 사실은 검정력을 잰 겁니다.

공통점은 오류 메시지가 안 난다는 겁니다. 그래서 답을 아는 경우와 대조하는 절차로만 찾을 수 있습니다. AI 가 썼든 사람이 썼든 같습니다.

정리

몬테카를로 방법

  • 같은 실험을 많이 반복해 확률과 기댓값을 근사
  • 오차는 \(1/\sqrt{B}\): 정확도 한 자리 = 반복 100배
  • 반복은 우연의 오차만 줄임, 모형의 가정은 그대로

재현성

  • set.seed() 는 맨 앞에서 한 번
  • 시드는 결과를 고정할 뿐, 옳게 만들지 않음

이론의 확인

  • 95% 포함, 5% 오류: 가정이 맞을 때의 약속
  • 가정이 깨지면 1종 오류 26%, 포함 확률 75% 까지

검증의 도구

  • 참값을 정하고, 자료를 만들고, 반복하고, 대조
  • AI 의 코드도 같은 절차, 응답의 설명까지 읽기
