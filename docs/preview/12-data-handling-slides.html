2 행과 열 고르기

필요한 행과 열만 남기기

행 수를 바꾸는 함수는 filter() 뿐: 조용한 오류도 여기서

이 절에서

  • filter(): 조건에 맞는 행
  • select() 와 rename(): 열 고르기
  • arrange() 와 slice_max(): 정렬과 상위 행

이 절이 답하는 질문: 조건으로 나눈 조각들의 행 수를 더하면 원래 행 수인가?

2절입니다. 표에서 필요한 행과 열만 남기는 함수들입니다.

select 는 열을, arrange 는 순서를 바꿀 뿐 행 수는 그대로입니다. 행 수를 바꾸는 건 filter 뿐이고, 그래서 조용한 오류도 대부분 여기서 생깁니다. 이 절의 질문은 조건으로 나눈 조각들의 행 수를 더하면 원래 행 수가 되는가입니다.

예측입니다. 8월 자료는 도서관 21곳입니다. 대출권수 3만 권 미만과 3만 권 이상으로 나눴습니다. 두 조각의 행 수를 더하면 얼마일까요?

3만 미만과 3만 이상, 수직선을 둘로 나눴으니 당연히 21 아닐까요? 아래 질문을 생각해 보세요. 두 조건 가운데 어느 쪽도 참이 아닌 행이 있을 수 있을까요?

찾아보면 휴관 중인 여울도서관입니다. 대출권수가 NA 지요. NA 가 3만보다 작냐고 물으면 R 은 모른다, NA 라고 답합니다. 크냐고 물어도 NA 입니다. filter 는 TRUE 인 행만 남기니까 이 행은 두 조건 모두에서 경고 없이 빠집니다. 조건 앞에 느낌표를 붙여 뒤집어도 NA 의 반대는 여전히 NA 라서 같습니다.

“3만 권 이상인 도서관을 빼고 나머지를 보자”가 의도였다면 오른쪽의 filter_out 이 맞습니다. dplyr 1.2.0 에 새로 생긴 함수입니다. 조건이 참인 행을 빼고, NA 인 행은 참이 아니니까 남깁니다. 그래서 11행입니다.

아래 상자가 이 절의 핵심입니다. 조건으로 나눴으면 조각의 행 수를 더해서 원래 행 수와 대조하세요. 안 맞으면 조건 열에 결측값이 있습니다.

“여러 값 가운데 하나”는 %in%

답은 C 입니다. 첫 코드는 두 곳만 골랐고 경고도 없습니다. %in% 은 다섯 곳이고요.

오른쪽 표가 같다 기호가 실제로 한 비교입니다. 시도 열은 길이 20 이고 비교할 벡터는 길이 2 입니다. R 은 짧은 쪽을 되풀이해서 길이를 맞춥니다. 그래서 1행은 서울과, 2행은 대전과, 3행은 다시 서울과 비교합니다. 1행 누리도서관은 서울이 서울과 만나서 참, 6행 다온도서관은 대전이 대전과 만나서 참. 나머지 서울과 대전 도서관은 하필 자리가 어긋났습니다.

행 수가 2의 배수가 아니면 경고라도 나오는데, 20 행이라 그마저 없습니다.

“여러 값 가운데 하나와 같다”는 %in% 입니다. AI 가 짠 코드에서도 가끔 보이는 실수이니 눈에 익혀 두세요.

이 절에서

  • mutate()

  • recode_values() 와 replace_values()
  • across(): 여러 열에 한 번에

이 절이 답하는 질문: 조건을 적은 순서와 빠뜨린 경우가 결과를 어떻게 바꾸는가?

3절입니다. mutate 로 새 열을 만들거나 기존 열을 바꿉니다.

행 수는 바뀌지 않으니 filter 보다 안전해 보이지만, 값을 정하는 규칙이 틀리면 모든 행이 한꺼번에 조용히 틀립니다. 이 절의 질문은 조건을 적은 순서와 빠뜨린 경우가 결과를 어떻게 바꾸는가입니다.

mutate 부터 보겠습니다. 개관일에서 연도를 뽑고, 그 연도로 운영연수를 계산했습니다. mutate 안에서는 방금 만든 개관연도 열을 바로 다음 줄에서 쓸 수 있습니다.

왼쪽 아래. 2005년 이전에 개관한 도서관만 개관일을 남기고 나머지는 NA 로 두려고 합니다. base R 의 ifelse 와 dplyr 의 if_else 로 똑같이 적었습니다.

ifelse 결과를 보세요. 날짜가 12492 같은 숫자가 됐습니다. R 의 날짜는 1970년 1월 1일부터 센 날 수에 “이건 날짜다”라는 속성을 붙인 값인데, ifelse 가 그 속성을 버린 겁니다. if_else 는 날짜 그대로입니다.

if_else 는 참일 때와 거짓일 때의 값이 같은 유형이어야 한다는 규칙을 지킵니다. 오른쪽 아래처럼 문자와 숫자를 섞으면 결과를 만들지 않고 멈춥니다. 문자와 숫자를 섞으려 했다면 대개 실수입니다. 조용히 틀린 값을 만드는 것보다 멈추는 편이 낫습니다.

서로 다른 방법으로 구한 값의 대조는 코드 검증의 좋은 방법

넓은 표에서 월 열 여덟 개에 같은 계산을 하려면 열 이름을 여덟 번 적어야 합니다. across 는 고른 열마다 같은 함수를 적용합니다.

역슬래시 x 는 function(x) 를 줄여 쓴 표기입니다. “x 를 받아서 결측을 뺀 합을 돌려주는 함수”를 그 자리에서 만든 거지요. 같은 방법으로 월마다 결측값 수를 세서 모두 더하면 8칸입니다.

오른쪽이 중요합니다. 같은 월 합계를 긴 표에서는 summarise 에 .by 로 한 줄에 구할 수 있습니다. 두 방법의 결과가 같은지 all.equal 로 대조했더니 TRUE 입니다.

서로 다른 방법으로 구한 같은 값을 대조하는 것은 코드를 검증하는 좋은 방법입니다. AI 가 짜 준 코드도 이렇게 다른 길로 한 번 더 구해 보면 확인이 됩니다.

4 집단별로 요약하기

여러 행을 한 행으로 줄이기

줄어든 행이 원래 행을 빠짐없이 한 번씩 대표하는가

이 절에서

  • summarise() 와 .by
  • group_by() 는 남는다
  • 개수 세기: n() 와 count()
  • 결측과 요약

이 절이 답하는 질문: 집단 합계의 합은 전체 합계인가?

4절입니다. summarise 는 여러 행을 한 행으로 줄입니다. 집단을 지정하면 집단마다 한 행이 됩니다.

행을 줄이는 계산이니까, 줄어든 행들이 원래 행을 빠짐없이 한 번씩 대표하는지 확인하는 게 중요합니다. 이 절의 질문은 집단 합계의 합이 전체 합계인가입니다.

4.1 summarise() 와 .by

  • group_by(): 집단 값을 정렬

summarise 는 여러 행을 한 행으로 줄입니다. 왼쪽 위는 전체를 한 행으로 요약했습니다. 총대출권수와 도서관 수입니다.

집단별로 요약할 때는 .by 에 집단을 나누는 열을 적습니다. 월별 대출권수를 구하고, 그 여덟 달을 다시 더해 봤습니다. 전체 합계와 같지요.

당연해 보이지만 이게 요약의 불변량입니다. 한 행이 정확히 한 달에 속하니까 집단 합계의 합은 전체 합계입니다. 이 등식이 깨지면 어떤 행이 집단에서 빠졌거나 두 집단에 들어간 겁니다.

오른쪽은 같은 계산을 group_by 로 한 겁니다. 결과의 순서가 다릅니다. .by 는 표에 처음 나온 순서를 지키고, group_by 는 집단 값을 정렬합니다. 그런데 두 방법의 더 중요한 차이는 따로 있습니다. 다음 예측으로 보겠습니다.

4.4 결측과 요약

0 은 “대출 없음”인가, “자료 없음”인가

  • 바로 앞 결과: 여울 3분기 합계 0, 값있는달 0
  • 7월과 8월은 휴관: 값이 없음
  • sum(na.rm = TRUE): 더할 값이 없으면 0

같은 도서관, 세 가지 “월평균”

도서관 평균 운영한_달 여덟_달
누리도서관 46,482 46,482 46,482
여울도서관 NA 19,751 12,344
새솔도서관 NA 8,322 4,161

분모는 질문이 정함

  • mean(x): 결측이 있으면 NA
  • mean(x, na.rm = TRUE): 운영한 달의 평균
  • sum(x, na.rm = TRUE) / 8: 휴관을 0 으로 센 평균
  • 운영 중 이용 수준 → 운영한 달, 주민이 받은 서비스의 양 → 여덟 달

결측을 빼는 것은 계산이 아니라 결정: 합계 옆에 값이 있는 행의 수, 평균에는 분모를 함께 보고

  • 집단마다 여러 행(사분위수 등): summarise() 는 오류(1.2.0), reframe()

바로 앞 결과에서 여울도서관의 3분기 합계가 0 이었습니다. 7월과 8월에 한 권도 안 빌려줬다는 뜻일까요? 아닙니다. 휴관이라 값이 없는 겁니다. sum 은 na.rm 으로 결측을 빼고 나면 더할 값이 하나도 없을 때 0 을 돌려줍니다. 0 과 자료 없음은 다르니까 합계 옆에 값이 있는 달의 수를 같이 적어야 합니다.

평균은 더 미묘합니다. 왼쪽 아래 표를 보세요. 결측이 없는 누리도서관은 세 값이 같습니다. 여울도서관은 na.rm 을 안 주면 NA, 주면 문을 연 다섯 달의 평균, 휴관한 달을 0 으로 보면 훨씬 작은 값입니다.

어느 게 맞을까요? 질문이 정합니다. 운영 중인 도서관의 이용 수준을 보려면 운영한 달의 평균이, 주민이 한 해 동안 받은 서비스의 양을 보려면 휴관을 0 으로 센 평균이 맞습니다.

na.rm 에 TRUE 를 주는 건 결측을 없는 셈으로 치겠다는 결정입니다. 코드 한 줄에 숨기지 말고 결과표에 분모를 적으세요.

마지막 줄은 짧게. 사분위수처럼 집단마다 값이 여러 개인 요약은 dplyr 1.2.0 부터 summarise 에서 오류이고, reframe 을 씁니다.

5.2 결합의 종류

함수 결과에 남는 행 붙이는 열
left_join(x, y) x 의 모든 행, 짝이 없으면 y 의 열은 NA y 의 열
inner_join(x, y) 짝이 있는 행만 y 의 열
full_join(x, y) 양쪽의 모든 행 y 의 열
semi_join(x, y) 짝이 있는 x 의 행 없음
anti_join(x, y) 짝이 없는 x 의 행 없음

작은 예: x 의 키 a, b, c 와 y 의 키 a, b, d

x <- tibble(키 = c("a", "b", "c"))
y <- tibble(키 = c("a", "b", "d"), 값 = c(1, 2, 4))
c(left = nrow(left_join(x, y, by = "키")),
  inner = nrow(inner_join(x, y, by = "키")),
  full = nrow(full_join(x, y, by = "키")),
  semi = nrow(semi_join(x, y, by = "키")),
  anti = nrow(anti_join(x, y, by = "키")))
 left inner  full  semi  anti 
    3     2     4     2     1
  • left: c 의 값 은 NA
  • inner: c 와 d 가 빠짐
  • full: d 까지 4행, d 의 x 쪽 열은 NA
  • anti: 짝이 없는 c 한 행

앞의 셋은 열을 붙이고, 뒤의 둘은 x 의 행을 고름: anti_join() 은 짝 없는 행을 찾는 검사 도구

두 표 x 와 y 를 키로 짝지을 때, 짝이 없는 행을 어떻게 다루느냐에 따라 함수가 나뉩니다.

left_join 은 x 의 모든 행을 남기고, 짝이 없으면 y 에서 온 열을 NA 로 채웁니다. inner_join 은 짝이 있는 행만 남깁니다. full_join 은 양쪽 모두입니다.

아래 둘은 성격이 다릅니다. semi_join 과 anti_join 은 열을 붙이지 않고, 짝이 있는지로 x 의 행을 고릅니다. semi 는 짝이 있는 행, anti 는 짝이 없는 행입니다.

아래 작은 예를 보세요. x 의 키는 a, b, c, y 의 키는 a, b, d 입니다. left 는 x 의 세 행을 남기고 c 의 값은 NA, inner 는 짝이 있는 a, b 두 행, full 은 d 까지 네 행, semi 는 두 행, anti 는 짝이 없는 c 한 행입니다.

특히 anti_join 을 기억하세요. 짝이 없는 행을 찾는 검사 도구로 자주 씁니다. 바로 다음 예측에서 씁니다.

늘어난 행은 합계를 부풀립니다. 8월 대출에 시도와 인구를 차례로 붙였더니 21 행이 22 행이 되고, 8월 합계가 41,275권 늘었습니다. 온새미도서관의 8월 대출권수가 한 번 더 더해진 겁니다.

오른쪽 표가 중요합니다. 방금은 x 쪽, 즉 도서관별 표에서 시도가 여러 번 나오고 y 쪽에도 중복이 있어서 다대다 경고가 나왔습니다.

그런데 x 쪽 키가 한 번씩만 나오면, 예를 들어 시도별로 먼저 요약한 표에 인구를 붙이면, 경고 없이 행만 늘어납니다. 세종 행이 조용히 두 개가 되는 거지요.

그러니 경고에 기대지 말고 행 수와 합계를 대조하세요. 8절에서 AI 가 짠 코드가 바로 이 경우입니다.

주의

left_join() 의 unmatched = "error" 는 y 의 짝 없는 행을 검사: “x 의 모든 행에 짝”을 확인하려면 inner_join() 이나 anti_join()

결합하기 전에 우리는 두 표의 관계를 알고 있습니다. 도서관은 여럿이 한 시도에 속하고, 시도는 인구 표에 한 번만 나와야 합니다. 다대일 관계지요.

이 가정을 relationship 인수로 코드에 적으면, 가정이 깨질 때 결합이 멈춥니다. 왼쪽 위처럼 many-to-one 을 적었더니 8 행이 여러 행과 짝지어진다고 멈췄습니다. 온새미도서관, 세종이지요.

오른쪽은 짝이 없는 행에 대한 가정입니다. “모든 도서관의 시도가 인구 표에 있어야 한다”는 inner_join 에 unmatched 를 두 값으로 줍니다. 첫 값은 x, 둘째 값은 y 의 짝 없는 행입니다. x 에 짝 없는 행이 있으면 멈추고, y 에만 있는 제주는 버립니다. 5 행, 강원특별자치도의 새봄도서관에서 멈췄습니다.

아래 경고 상자가 헷갈리는 부분입니다. left_join 에 unmatched 를 error 로 주면 y 의 짝 없는 행을 검사합니다. left_join 에서 버려지는 행은 y 쪽에만 생기기 때문입니다. 우리 목적과 반대지요. 그래서 x 의 모든 행에 짝이 있는지 확인하려면 inner_join 을 쓰거나 anti_join 결과가 0 행인지 봅니다.

bind_rows 는 열 이름으로 짝을 맞추고, 한쪽에 없는 열은 NA 로 채웁니다. 이것도 조용한 변화입니다. 시도와 열람석이 NA 지요. 같은 이름의 열인데 유형이 다르면, 예를 들어 개관일을 문자로 적었으면 붙이지 않고 멈춥니다.

시도를 모르는 채로 추가해도 시도별 분석에서는 여전히 빠집니다. 새솔도서관을 어떻게 다룰지는 7절에서 정합니다.

7.1 무엇이 보존되어야 하는가: 불변량

변환 보존되어야 할 것 확인하는 방법 이 장에서 대조한 수
filter() 로 나누기 조각들의 행 수 합 = 원래 행 수 nrow() 합 비교 10 + 10 = 20, 원래 21 (2.1)
mutate(), select(), arrange() 행 수 전후 nrow() 기본 정보 20행 그대로
summarise(.by = ) 집단 합계의 합 = 전체 합계, 값이 있는 행의 수 sum() 대조, sum(!is.na()) 여덟 달의 합 4,841,338 = 전체 (4.1)
다대일 결합 행 수 = x 의 행 수, 짝 없는 행 없음 relationship, unmatched, anti_join() 20행이 21행: 세종 중복 (5.3)
pivot_longer() 행 수 = 원래 행 수 × 접은 열 수, 합계 왕복 검사 168 = 21 × 8, 합계 같음 (1.2)
bind_rows() 행 수 = 두 표의 행 수 합, 새 결측 없음 nrow(), 결측 수 비교 21행, 시도와 열람석 NA (5.5)

의도해서 뺀 행이 있으면 뺀 양을 기록하고 남은 것 + 뺀 것 = 원래로 대조

변환에 따라 변하지 않아야 할 양을 불변량이라고 부릅니다. 오늘 쓴 불변량을 정리한 표입니다.

filter 로 나누면 조각들의 행 수 합이 원래 행 수. mutate, select, arrange 는 행 수가 그대로. summarise 는 집단 합계의 합이 전체 합계. 다대일 결합은 행 수가 x 의 행 수 그대로이고 짝 없는 행이 없어야 합니다. pivot_longer 는 행 수가 원래 행 수 곱하기 접은 열 수, 그리고 왕복 검사. bind_rows 는 두 표의 행 수 합.

오른쪽 열은 오늘 실제로 대조한 수입니다. 2절에서 조각을 더하니 20 이라 결측을 찾았고, 5절에서 20 행이 21 행이 되어 세종 중복을 찾았습니다.

불변량이 깨졌다고 늘 틀린 건 아닙니다. 새솔도서관처럼 의도해서 뺀 행이 있으면, 뺀 양을 따로 기록해 두고 남은 것 더하기 뺀 것이 원래와 같은지 대조합니다.

대조를 매번 눈으로 하지 않도록 함수로 만듭니다. 11장의 check_loans 와 같은 방식입니다. stopifnot 에 조건마다 이름을 붙이면, 실패할 때 어느 가정이 깨졌는지 문장으로 알려 줍니다.

네 조건입니다. 시도는 한 행에 하나, 시도 수가 기본 정보의 시도 수와 같다, 인구가 빠진 시도가 없다, 그리고 시도별 합계와 미배정 대출의 합이 전체 대출과 같다. 우리 결과는 아무것도 출력하지 않고 조용히 통과합니다.

오른쪽이 중요합니다. 검증 함수도 코드이니까, 틀린 입력에서 실제로 멈추는지 확인해야 믿을 수 있습니다. 고치기 전의 인구 표로 같은 표를 만들어 넣었더니 첫 조건, 시도는 한 행에 하나다에서 멈췄습니다.

stopifnot 은 처음 실패한 조건만 알려 줍니다. 중복을 고치면 다음 조건, 인구 결측에서 다시 멈춥니다. 결함이 여러 개일 수 있다는 뜻입니다.

library(tidyverse)

  left_join(libraries |> select(도서관ID, 시도), by = "도서관ID")

  group_by(시도) |>

8.4 받은 결과표를 확인하는 순서

데이터 변환 코드에서 자주 나타나는 오류

  • 결측을 만난 조건: filter() 가 행을 조용히 뺌
  • == 로 여러 값 비교: 자리끼리 비교
  • group_by() 를 풀지 않음: 뒤의 계산이 집단마다
  • 원래 열 이름을 재사용: summarise() 의 뒤 계산이 새 값을 봄
  • 키 중복과 명칭 불일치: 결합이 행을 늘리거나 NA 로 채움
  • 확인 코드가 결측만 찾음: 중복과 값의 변화는 통과

AI 의 확인 코드는 AI 가 떠올린 결함만 확인: 통과는 “그 결함이 없다”는 뜻, “결과가 맞다”는 뜻이 아님

받은 결과표를 확인하는 순서: ① 키가 한 번씩 나오는가 ② 합계가 보존되는가 ③ 짝 없는 행은 기록했는가 ④ 검증 함수로 남기기

result |> count(시도) |> filter(n > 1)     # ① 0행
sum(result$총대출권수) + 미배정 ==
  sum(loans$대출권수, na.rm = TRUE)       # ② TRUE
loans |> anti_join(libraries,
                   by = "도서관ID")       # ③ 기록
check_sido_rate(result, loans, libraries) # ④

데이터 변환 코드에서 자주 나타나는 오류를 정리하겠습니다. 사람이 짠 코드든 AI 가 짠 코드든 똑같이 나타납니다.

결측을 만난 조건, 같다 기호로 여러 값 비교, 풀지 않은 group_by, summarise 안에서 원래 열 이름 재사용, 키 중복과 명칭 불일치. 그리고 오늘 본 새로운 유형, 확인 코드가 결측만 찾는 경우입니다.

오른쪽 위가 오늘 AI 절의 핵심입니다. AI 가 넣어 준 확인 코드는 AI 가 떠올린 결함만 확인합니다. 그 확인을 통과했다는 건 그 결함이 없다는 뜻이지 결과가 맞다는 뜻이 아닙니다.

불변량은 어떤 결함인지 몰라도 결과의 구조를 확인합니다. 그래서 결과표를 받으면 적어도 이 순서로 확인하세요. 키가 한 번씩 나오는가, 합계가 보존되는가, 짝 없는 행은 기록했는가, 그리고 검증 함수로 남기기. 오른쪽 아래 코드가 그 네 줄입니다. 여러분 프로젝트의 결과표에도 이름만 바꿔서 그대로 쓸 수 있습니다.

정리

모양과 고르기, 만들기

  • 표를 받으면 한 행이 무엇인지 말하고 행 수와 키로 확인
  • filter() 는 TRUE 만 남김: 조각의 행 수 합 대조, 뺄 행은 filter_out()
  • 여러 값 가운데 하나는 %in%
  • case_when() 은 좁은 조건부터, 빠뜨림은 .unmatched = "error"

요약

  • 집단 합계의 합 = 전체 합계
  • group_by() 는 남음: 한 번의 계산에는 .by
  • 결측을 빼는 것은 결정: 값이 있는 행의 수와 분모를 함께

결합과 모양 바꾸기

  • 합치기 전에 키의 중복, 합친 뒤 짝 없는 행
  • 가정은 relationship, unmatched 로 코드에
  • 다대다 경고는 늘 나오지 않음: 행 수와 합계 대조
  • 모양을 바꾸면 왕복 검사

AI와 함께

  • AI 는 붙여 넣은 행만 봄
  • 확인 코드의 통과 ≠ 결과가 맞음: 불변량으로 대조
