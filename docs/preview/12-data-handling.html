중요

학습 목표

  • 표에서 한 행이 무엇을 가리키는지(관측 단위)를 말하고, 분석 목적에 맞게 넓은 표와 긴 표 사이를 오갈 수 있다.
  • 행 고르기, 열 만들기, 집단별 요약을 파이프로 이어 변환 절차를 작성할 수 있다.
  • 조건과 요약이 결측값을 만났을 때 결과가 어떻게 달라지는지 실행하기 전에 예측할 수 있다.
  • 두 표를 합치기 전에 키의 유일성과 짝을 확인하고, 합친 뒤 행 수가 바뀐 이유를 설명할 수 있다.
  • 변환마다 보존되어야 할 것(행 수, 합계, 키)을 정하고 코드로 대조할 수 있다.
  • AI 가 생성한 데이터 변환 코드를 행 수, 키, 합계 대조로 검증하고, AI 가 보지 못한 자료의 결함을 찾아낼 수 있다.

11장에서는 파일을 읽고, 읽은 결과를 원문과 대조했다. 그런데 읽은 표가 곧바로 분석에 맞는 경우는 드물다. 필요한 행만 고르고, 새 변수를 만들고, 집단별로 요약하고, 다른 기관의 표와 합치고, 표의 모양을 바꾼다. 이 과정을 데이터 핸들링(data handling)이라 한다. 분석 시간의 대부분이 여기에 쓰인다.

데이터 핸들링 코드는 AI 가 가장 잘 써 주는 코드 가운데 하나다. 그리고 가장 조용히 틀리는 코드이기도 하다. 조건 하나가 결측값을 만나면 행이 경고 없이 빠지고, 합칠 표에 중복된 키가 하나 있으면 행이 늘어나 합계가 부풀어 오른다. 코드는 오류 없이 끝나고 표는 그럴듯하다. 틀렸다는 사실은 무엇이 보존되어야 하는지 알고 대조할 때만 드러난다. 6장의 예측과 대조, 11장의 합계 대조가 이 장에서는 변환마다 되풀이된다.

이 장은 dplyr 과 tidyr 의 함수를 사전처럼 나열하지 않는다. 함수마다 결과가 달라지는 지점을 예측하고 확인하는 데 집중한다. 인수 전체는 dplyr 함수 목록 에서 찾아보면 된다.

1 데이터의 모양

변환을 시작하기 전에 표가 어떻게 생겼는지부터 정한다. 같은 정보도 여러 모양의 표에 담을 수 있고, 모양에 따라 쉬운 계산과 어려운 계산이 갈린다.

1.1 한 행은 무엇인가

표를 받으면 먼저 한 행이 무엇을 가리키는지 묻는다. 이것을 관측 단위(unit of observation)라 한다. libraries 의 한 행은 도서관 하나다. 그렇다면 도서관ID 는 행마다 달라야 하고, 서로 다른 도서관ID 의 수는 행 수와 같아야 한다.

힌트

예측해 보자: libraries 는 20행, loans_wide 는 21행이다. 두 표 모두 한 행이 도서관 하나라면, 각 표에서 서로 다른 도서관ID 는 몇 개이겠는가? 두 표의 도서관은 같은 도서관들이겠는가?

두 표 모두 행 수와 서로 다른 도서관ID 수가 같다. 한 행이 도서관 하나라는 가정이 맞다. 그런데 대출 표에는 기본 정보에 없는 L21 이 있다. setdiff(a, b) 는 a 에는 있고 b 에는 없는 값을 돌려준다. 이 도서관은 5월에 문을 연 새솔도서관이고, 기본 정보 표가 아직 갱신되지 않았다. 이 한 줄이 뒤에서 표를 합칠 때 문제를 일으킨다 (섹션 5.2).

중요

표를 받으면 한 행이 무엇인지 한 문장으로 적고, 그 문장이 맞는지 행 수와 키의 수로 확인한다. 연구 가설을 세울 때 적은 관측 단위(사람인가, 지역인가, 지역과 연도의 조합인가)가 실제 표의 한 행과 같은지도 여기서 확인한다.

이 모양을 tidy data 라 부른다. Wickham(2014) 이 정리한 세 원칙은 다음과 같다.

  1. 변수 하나는 열 하나다.
  2. 관측 하나는 행 하나다.
  3. 관측 단위 하나는 표 하나다.

2 행과 열 고르기

표에서 필요한 부분만 남기는 함수들이다. filter() 는 행을, select() 는 열을 고르고, arrange() 는 행의 순서를 바꾼다. 이 가운데 행 수를 바꾸는 것은 filter() 뿐이므로 조용히 틀리는 곳도 대부분 여기서 생긴다.

2.1 filter(): 조건에 맞는 행

filter() 는 조건이 참(TRUE)인 행만 남긴다. 8월 자료만 골라 보자.

aug <- loans |> filter(월 == "2026.08")
nrow(aug)
[1] 21

21개 도서관의 8월 자료다. 이제 대출권수 3만 권을 기준으로 두 조각으로 나눈다.

힌트

예측해 보자: 8월 21행을 대출권수 < 30000 과 대출권수 >= 30000 으로 나누었다. 두 조각의 행 수를 더하면 몇이 되겠는가?

small <- aug |> filter(대출권수 < 30000)
large <- aug |> filter(대출권수 >= 30000)

c(전체 = nrow(aug), 작음 = nrow(small), 큼 = nrow(large))
전체 작음   큼 
  21   10   10

10 + 10 = 20 이다. 한 행이 어느 조각에도 들어가지 않았다.

aug |> filter(is.na(대출권수))
# A tibble: 1 × 4
  도서관ID 도서관     월      대출권수
  <chr>    <chr>      <chr>      <dbl>
1 L12      여울도서관 2026.08       NA

휴관 중인 여울도서관이다. 대출권수가 NA 이면 NA < 30000 도 NA >= 30000 도 참이 아니라 NA 다. 값을 모르니 크다고도 작다고도 할 수 없다. filter() 는 TRUE 인 행만 남기므로 NA 인 행은 두 조건 모두에서 경고 없이 빠진다. 조건을 뒤집어 filter(!(대출권수 >= 30000)) 라고 써도 !NA 는 NA 이므로 결과는 같다.

“3만 권 이상인 도서관을 빼고 나머지를 보자”는 의도라면 dplyr 1.2.0 의 filter_out() 이 맞다. filter_out() 은 조건이 참인 행을 뺀다. 조건이 NA 인 행은 참이 아니므로 남는다.

aug |> filter_out(대출권수 >= 30000) |> nrow()
[1] 11
중요

조건으로 행을 나누었으면 조각들의 행 수를 더해 원래 행 수와 대조한다. 맞지 않으면 조건 열에 결측값이 있다. 남길 행을 말하고 싶으면 filter(), 뺄 행을 말하고 싶으면 filter_out() 을 쓴다. 두 함수는 결측값을 반대로 다룬다.

조건을 쉼표로 여러 개 적으면 모두 참인 행만 남는다(& 와 같다). “둘 중 하나”는 | 로 적는다. 여러 값 가운데 하나와 같은 행을 고를 때는 흔한 함정이 하나 있다.

힌트

예측해 보자: 서울과 대전의 도서관(서울 3곳, 대전 2곳)을 고르려 한다. 두 코드의 결과는 같겠는가?

3 열 만들고 바꾸기

mutate() 는 기존 열로 새 열을 만들거나 기존 열을 바꾼다. 행 수는 바뀌지 않지만, 값을 정하는 규칙이 틀리면 모든 행이 조용히 틀린다.

3.1 mutate()

libraries |>

         운영연수 = 2026 - 개관연도) |>

  head(3)
# A tibble: 3 × 4
  도서관     개관일     개관연도 운영연수
  <chr>      <date>        <int>    <dbl>
1 누리도서관 2004-03-15     2004       22
2 한빛도서관 1998-11-02     1998       28
3 가람도서관 2011-06-20     2011       15

mutate() 안에서는 앞에서 만든 열(개관연도)을 바로 다음 계산에 쓸 수 있다. 계산은 열 전체에 한 번에 적용된다. 4장에서 본 벡터 연산이다.

3.2 조건에 따라 값 정하기: if_else() 와 case_when()

조건이 둘이면 if_else(), 셋 이상이면 case_when() 을 쓴다. base R 에도 ifelse() 가 있는데, 결과의 유형을 다루는 방식이 다르다.

힌트

예측해 보자: 2005년 이전에 개관한 도서관만 개관일을 남기고 나머지는 NA 로 두려 한다. 두 코드가 돌려주는 값의 모양은 같겠는가?

early <- libraries$개관일 < as.Date("2005-01-01")
ifelse(early, libraries$개관일, NA)
if_else(early, libraries$개관일, NA)
early <- libraries$개관일 < as.Date("2005-01-01")

head(ifelse(early, libraries$개관일, NA), 3)
[1] 12492 10532    NA
head(if_else(early, libraries$개관일, NA), 3)
[1] "2004-03-15" "1998-11-02" NA

ifelse() 는 날짜를 12492 같은 수로 바꾸어 버렸다. R 의 날짜는 1970년 1월 1일부터 센 날 수에 “날짜”라는 속성을 붙인 값인데, ifelse() 는 그 속성을 버린다. if_else() 는 참일 때와 거짓일 때의 값이 같은 유형이어야 한다는 규칙을 지키고 유형을 보존한다. 규칙에 어긋나면 결과를 만들지 않고 멈춘다.

libraries |> mutate(규모 = if_else(열람석 >= 300, "대형", 0))
Error in `mutate()`:
ℹ In argument: `규모 = if_else(열람석 >= 300,
  "대형", 0)`.
Caused by error in `if_else()`:
! Can't combine `true` <character> and `false` <double>.

조용히 틀린 값을 만드는 것보다 멈추는 편이 낫다. 문자와 숫자를 섞으려 했다면 대개 실수다.

case_when() 은 조건 ~ 값 을 위에서부터 차례로 검사해 처음으로 참인 조건의 값을 준다.

힌트

3.3 값을 다른 값으로: recode_values() 와 replace_values()

조건이 아니라 값 자체를 다른 값으로 바꿀 때는 dplyr 1.2.0 의 두 함수를 쓴다.

함수 쓰임 짝이 없는 값
recode_values() 모든 값을 새 값으로 옮겨 새 변수를 만든다 default 또는 unmatched = "error"
replace_values() 일부 값만 바꾸고 나머지는 그대로 둔다 그대로 남음

월을 분기로 묶어 보자. 여러 값을 한 값으로 옮길 때는 왼쪽에 벡터를 적는다.

quarterly <- loans |>
  mutate(분기 = recode_values(월,
    c("2026.01", "2026.02", "2026.03") ~ "1분기",
    c("2026.04", "2026.05", "2026.06") ~ "2분기",
    c("2026.07", "2026.08") ~ "3분기",
    unmatched = "error"
  ))

quarterly |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE), 달 = n_distinct(월), .by = 분기)
# A tibble: 3 × 3
  분기  대출권수    달
  <chr>    <dbl> <int>
1 1분기  1674701     3
2 2분기  1886237     3
3 3분기  1280400     2

unmatched = "error" 를 준 까닭은 case_when() 과 같다. 3분기에 "2026.08" 을 빠뜨렸다면 8월 행에 분기가 없다는 오류로 멈춘다. 9월 자료가 추가되었는데 표를 고치지 않은 경우도 여기서 드러난다. 결과표의 달 열도 대조 수단이다. 3분기는 7월과 8월 두 달뿐이므로 다른 분기와 합계를 그대로 비교할 수 없다.

replace_values() 는 섹션 5.4 에서 시도 명칭을 고칠 때 쓴다. dplyr 1.2.0 이전의 case_match() 와 recode() 는 이 두 함수로 대체되었다.

3.4 여러 열에 한 번에: across()

넓은 표에서 월 열 여덟 개에 같은 계산을 하려면 열 이름을 여덟 번 적어야 한다. across() 는 고른 열마다 같은 함수를 적용한다.

loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(x, na.rm = TRUE)))
# A tibble: 1 × 8
  `2026.01` `2026.02` `2026.03` `2026.04` `2026.05`
      <dbl>     <dbl>     <dbl>     <dbl>     <dbl>
1    572451    506028    596222    626925    654989
# ℹ 3 more variables: `2026.06` <dbl>, `2026.07` <dbl>,
#   `2026.08` <dbl>

\(x) sum(x, na.rm = TRUE) 는 “x 를 받아 결측을 뺀 합을 돌려주는 함수”를 그 자리에서 만든 것이다. \(x) 는 function(x) 를 줄여 쓴 표기다(R 4.1 이상). 같은 방법으로 월마다 결측값 수를 셀 수 있다.

loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(is.na(x))))
# A tibble: 1 × 8
  `2026.01` `2026.02` `2026.03` `2026.04` `2026.05`
      <int>     <int>     <int>     <int>     <int>
1         1         2         1         1         0
# ℹ 3 more variables: `2026.06` <int>, `2026.07` <int>,
#   `2026.08` <int>

결측값은 모두 8칸이다. 긴 표에서 sum(is.na(loans$대출권수)) 로 센 수와 같은지 확인해 보자.

같은 월 합계를 긴 표에서 구하면 summarise(.by = 월) 한 줄이다(섹션 4). 서로 다른 방법으로 구한 같은 값을 대조하는 것은 코드를 검증하는 좋은 방법이다.

by_wide <- loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(x, na.rm = TRUE)))

by_long <- loans |>
  summarise(합계 = sum(대출권수, na.rm = TRUE), .by = 월)

all.equal(unlist(by_wide), setNames(by_long$합계, by_long$월))

5 표 합치기

시도별 인구 1만 명당 대출권수를 구하려면 대출(대출 표), 소속 시도(기본 정보 표), 인구(인구 표)가 모두 필요하다. 세 정보는 서로 다른 표에 있다. 두 표를 키로 짝지어 한 표로 만드는 것을 결합(join)이라 한다. 결합은 데이터 핸들링에서 행 수가 가장 크게, 가장 조용히 바뀌는 곳이다.

5.1 키: 행을 식별하는 열

키(key)는 표에서 한 행을 가리키는 열(또는 열의 조합)이다. 기본 정보 표의 키는 도서관ID, 긴 대출 표의 키는 도서관ID 와 월 의 조합, 인구 표의 키는 시도 다. 키라면 같은 값이 두 번 나오지 않아야 한다. 합치기 전에 확인한다.

5.2 결합의 종류

두 표 x 와 y 를 키로 짝지을 때, 짝이 없는 행을 어떻게 다루느냐에 따라 함수가 나뉜다.

함수 결과에 남는 행
left_join(x, y) x 의 모든 행. 짝이 없으면 y 에서 온 열은 NA
inner_join(x, y) 짝이 있는 행만
full_join(x, y) 양쪽의 모든 행
semi_join(x, y) 짝이 있는 x 의 행. y 의 열은 붙이지 않음
anti_join(x, y) 짝이 없는 x 의 행. y 의 열은 붙이지 않음

앞의 셋은 열을 붙이고, 뒤의 둘은 짝이 있는지로 x 의 행을 고른다. anti_join() 은 짝이 없는 행을 찾는 검사 도구로 자주 쓴다.

힌트

5.4 가정을 코드에 적기: relationship 과 unmatched

결합하기 전에 우리는 두 표의 관계를 알고 있다. 도서관은 여럿이 한 시도에 속하고, 시도는 인구 표에 한 번만 나와야 한다. 다대일(many-to-one) 관계다. 이 가정을 relationship 인수로 코드에 적으면, 가정이 깨질 때 결합이 멈춘다.

libraries |>
  left_join(population, by = "시도", relationship = "many-to-one")
Error in `left_join()`:
! Each row in `x` must match at most 1 row in `y`.
ℹ Row 8 of `x` matches multiple rows in `y`.
relationship 뜻
"one-to-one" 양쪽 모두 키가 한 번씩만 나온다
"one-to-many" x 의 키는 한 번씩, y 의 키는 여러 번 나올 수 있다
"many-to-one" x 의 키는 여러 번, y 의 키는 한 번씩만 나온다
"many-to-many" 양쪽 모두 여러 번 나올 수 있다 (의도한 경우에만)

짝이 없는 행에 대한 가정은 unmatched 인수로 적는다. “모든 도서관의 시도가 인구 표에 있어야 한다”는 가정은 inner_join() 에 unmatched = c("error", "drop") 을 주어 적는다. 첫 번째 값은 x, 두 번째 값은 y 의 짝 없는 행을 다룬다. x 에 짝 없는 행이 있으면 멈추고, y 에만 있는 행(제주특별자치도)은 버린다.

libraries |>
  inner_join(distinct(population), by = "시도",
             relationship = "many-to-one", unmatched = c("error", "drop"))
Error in `inner_join()`:
! Each row of `x` must have a match in `y`.
ℹ Row 5 of `x` does not have a match.

5행, 강원특별자치도의 새봄도서관에서 멈췄다.

주의

left_join() 에 unmatched = "error" 를 주면 y 의 짝 없는 행을 검사한다. left_join() 에서 버려지는 행은 y 쪽에만 생기기 때문이다. “x 의 모든 행에 짝이 있다”를 확인하려는 목적과 반대이므로, 그 목적이면 위처럼 inner_join() 을 쓰거나 anti_join() 결과가 0행인지 확인한다.

두 결함을 고친다. 세종 행은 두 행의 값이 완전히 같다는 것을 확인했으므로 distinct() 로 하나를 지운다. 값이 달랐다면 어느 행이 맞는지 자료를 준 기관에 확인해야 할 일이지 함수로 해결할 일이 아니다. 이전 명칭은 replace_values() 로 현재 명칭으로 바꾼다(섹션 3.3).

population_clean <- population |>
  distinct() |>
  mutate(시도 = replace_values(시도,
    "강원도" ~ "강원특별자치도",
    "전라북도" ~ "전북특별자치도"
  ))

lib_pop <- libraries |>
  inner_join(population_clean, by = "시도",
             relationship = "many-to-one", unmatched = c("error", "drop"))

nrow(lib_pop)
[1] 20

이번에는 멈추지 않고 20행이 나왔다. 결합 코드에 적어 둔 두 가정(시도는 인구 표에 한 번씩, 모든 도서관의 시도는 인구 표에 있다)이 실행될 때마다 확인된다. 다음 달 인구 표가 새로 들어와 같은 결함이 다시 생겨도 조용히 넘어가지 않는다.

6 모양 바꾸기

섹션 1.2 에서 넓은 표를 긴 표로 한 번 바꾸었다. 이 절에서는 두 방향의 변환을 자세히 보고, 모양을 바꾼 뒤 정보가 그대로인지 확인하는 방법을 다룬다.

6.1 넓은 표를 긴 표로: pivot_longer()

pivot_longer() 의 핵심 인수는 셋이다. 접을 열(cols), 열 이름이 들어갈 새 열의 이름(names_to), 칸의 값이 들어갈 새 열의 이름(values_to)이다. 열 이름 "2026.01" 에는 연도와 월 두 정보가 들어 있다. names_to 에 이름을 두 개 주고 names_sep 으로 나누는 기준을 주면 두 열로 나눌 수 있다.

지금까지 변환마다 보존되어야 할 것을 정하고 대조했다. 이 절에서는 그 대조를 모아 하나의 절차로 만든다. 목표는 “시도별 2026년 1~8월 총 대출권수와 인구 1만 명당 대출권수” 표다.

7.1 무엇이 보존되어야 하는가

변환에 따라 변하지 않아야 할 양을 불변량(invariant)이라 부른다. 이 장에서 쓴 불변량을 정리하면 다음과 같다.

변환 보존되어야 할 것 확인하는 방법
filter() 로 나누기 조각들의 행 수 합 = 원래 행 수 nrow() 합 비교 (섹션 2.1)
mutate(), select(), arrange() 행 수 전후 nrow()
summarise(.by = ) 집단 합계의 합 = 전체 합계, 값이 있는 행의 수 sum() 대조, sum(!is.na()) (섹션 4.1)
다대일 결합 행 수 = x 의 행 수, 짝 없는 행 없음 relationship, unmatched, anti_join() (섹션 5.4)
pivot_longer() 행 수 = 원래 행 수 × 접은 열 수, 합계 왕복 검사 (섹션 6.3)
bind_rows() 행 수 = 두 표의 행 수 합, 새 결측 없음 nrow(), 결측 수 비교

불변량이 깨졌다고 늘 틀린 것은 아니다. 새솔도서관처럼 의도해서 뺀 행이 있으면, 뺀 양을 따로 기록해 두고 “남은 것 + 뺀 것 = 원래”로 대조한다.

7.3 검증을 코드로 남기기

대조를 매번 눈으로 하지 않도록 함수로 만든다. 11장의 check_loans() 와 같은 방식이다. stopifnot() 에 조건마다 이름을 붙이면 실패할 때 어느 가정이 깨졌는지 문장으로 알려 준다.

check_sido_rate <- function(result, loans, libraries) {
  unassigned <- loans |> anti_join(libraries, by = "도서관ID")
  stopifnot(
    "시도는 한 행에 하나다" = !anyDuplicated(result$시도),
    "시도 수가 기본 정보의 시도 수와 같다" =
      nrow(result) == n_distinct(libraries$시도),
    "인구가 빠진 시도가 없다" = !anyNA(result$인구),
    "시도별 합계와 미배정 대출의 합이 전체 대출과 같다" =
      sum(result$총대출권수) + sum(unassigned$대출권수, na.rm = TRUE) ==
        sum(loans$대출권수, na.rm = TRUE)
  )
  invisible(TRUE)
}

8.2 AI 가 생성한 코드

응답은 처리 순서를 여섯 단계로 먼저 설명하고 코드를 내놓았다. 코드 안에 결과를 확인하는 줄을 두 곳 넣었고, 끝에 세 가지를 꼭 확인하라고 조언했다.

  1. 휴관한 달의 빈칸을 0 으로 보고 합산했으니 그 가정이 맞는지 확인할 것 (섹션 4.4 의 논의와 같다).
  2. 도서관ID 결합 뒤 시도가 NA 인 행이 없는지 확인할 것. 있다면 두 파일의 도서관ID 표기가 맞지 않는 것이다.

8.4 AI 가 보지 못한 부분

자료의 결함 파일에서의 위치 AI 응답 드러낸 대조
인구 표의 이전 명칭(강원도, 전라북도) 인구 표 11행, 14행 명칭 변경 가능성을 짚고 확인 코드를 줌 인구 결측 확인, anti_join()
기본 정보에 없는 신규 도서관(L21) 대출 표 21행 확인 코드로 드러났으나 원인을 표기 불일치로 설명 anti_join(), 미배정 기록
인구 표의 세종 중복 행 인구 표 8행, 9행 다루지 않음. 두 확인을 모두 통과 키 중복 확인, 합계 대조

응답은 좋은 응답이었다. 처리 순서를 설명했고, 확인 코드를 넣었고, 휴관한 달을 0 으로 보는 가정이 결정이라는 점과 명칭 변경이라는 실제 결함을 짚었다. 명칭 변경은 행정구역에 대한 일반 지식으로 짐작할 수 있는 결함이다. 그러나 인구 표 8행과 9행이 같은 행이라는 사실은 어떤 지식으로도 짐작할 수 없다. 파일을 보아야 안다.

AI 가 써 준 확인 코드는 AI 가 떠올린 결함만 확인한다. 그 확인을 통과했다는 것은 그 결함이 없다는 뜻이지 결과가 맞다는 뜻이 아니다. 불변량은 어떤 결함인지 몰라도 결과의 구조를 확인한다. 시도는 한 번씩 나와야 하고, 합계는 보존되어야 한다. 중복이든 누락이든 이 등식을 깬다.

응답의 코드를 최소한으로 고친다. 인구 표의 중복과 명칭을 고치고, 두 결합에 관계와 짝에 대한 가정을 적고, 새솔도서관을 빼는 결정을 코드에 드러낸다.

# 수정: 인구 표 중복 제거와 명칭 변경, 두 결합에 relationship 과 unmatched 명시,
#       기본 정보에 없는 도서관은 inner_join 으로 빼고 check_sido_rate() 에서 미배정으로 대조
sido_pop_ok <- sido_pop |>
  distinct() |>
  mutate(시도 = replace_values(시도,
    "강원도" ~ "강원특별자치도",
    "전라북도" ~ "전북특별자치도"
  ))

result_ok <- loans_long |>
  inner_join(libraries |> select(도서관ID, 시도), by = "도서관ID",
             relationship = "many-to-one", unmatched = c("drop", "error")) |>
  group_by(시도) |>
  summarise(총대출권수 = sum(대출권수, na.rm = TRUE), .groups = "drop") |>
  inner_join(sido_pop_ok, by = "시도",
             relationship = "one-to-one", unmatched = c("error", "drop")) |>
  mutate(`대출권수_1만명당` = round(총대출권수 / 인구 * 10000, 1)) |>
  arrange(desc(`대출권수_1만명당`)) |>
  select(시도, 권역, 총대출권수, 인구, `대출권수_1만명당`)

주의

AI 가 넣어 준 확인 코드를 통과했다고 끝이 아니다. 그 확인이 무엇을 확인하지 않는지 묻는다. 결측 확인은 중복을 잡지 못하고, 행 수 확인은 값이 바뀐 것을 잡지 못한다. 결과표를 받으면 적어도 키가 한 번씩 나오는지와 합계가 보존되는지는 직접 대조한다.

## 데이터의 모양 {#sec-data-shape}

변환을 시작하기 전에 표가 어떻게 생겼는지부터 정한다. 같은 정보도 여러 모양의 표에 담을 수 있고, 모양에
따라 쉬운 계산과 어려운 계산이 갈린다.


### 한 행은 무엇인가 {#sec-row-unit}

표를 받으면 먼저 **한 행이 무엇을 가리키는지** 묻는다. 이것을 **관측 단위**(unit of observation)라 한다.
`libraries` 의 한 행은 도서관 하나다. 그렇다면 도서관ID 는 행마다 달라야 하고, 서로 다른 도서관ID 의 수는 행
수와 같아야 한다.


::: {.callout-tip}
**예측해 보자**: `libraries` 는 20행, `loans_wide` 는 21행이다. 두 표 모두 한 행이 도서관 하나라면, 각 표에서
서로 다른 도서관ID 는 몇 개이겠는가? 두 표의 도서관은 같은 도서관들이겠는가?

:::


```{r row-unit}
c(행 = nrow(libraries),  도서관ID = n_distinct(libraries$도서관ID))
c(행 = nrow(loans_wide), 도서관ID = n_distinct(loans_wide$도서관ID))

```


두 표 모두 행 수와 서로 다른 도서관ID 수가 같다. 한 행이 도서관 하나라는 가정이 맞다. 그런데 대출 표에는
기본 정보에 없는 `L21` 이 있다. `setdiff(a, b)` 는 a 에는 있고 b 에는 없는 값을 돌려준다. 이 도서관은 5월에

(@sec-join-types).


::: {.callout-important}
표를 받으면 **한 행이 무엇인지** 한 문장으로 적고, 그 문장이 맞는지 행 수와 키의 수로 확인한다. 연구 가설을
세울 때 적은 관측 단위(사람인가, 지역인가, 지역과 연도의 조합인가)가 실제 표의 한 행과 같은지도 여기서 확인한다.

:::


사람이 읽기에는 편하다. 도서관 하나의 여덟 달이 한 줄에 보인다. 그런데 "월별 대출권수의 합"이나 "휴관한
달이 있는 도서관"을 구하려 하면 월 열 여덟 개를 모두 적어야 한다. 1월부터 12월까지 자료가 들어오면 열이
늘어나 코드도 고쳐야 한다. 월은 **변수의 값**인데 열 이름에 들어가 있기 때문이다.

같은 정보를 한 행에 도서관 하나와 월 하나를 담는 **긴 표**(long format)로 바꿀 수 있다.


```{r pivot-longer-first}

loans
```

`pivot_longer()` 는 `starts_with("2026")` 으로 고른 열들을 두 열로 접는다. 열 이름은 `월` 열의 값이 되고, 칸의 값은
`대출권수` 열의 값이 된다. 자세한 인수는 @sec-pivot 에서 다룬다.

이 모양을 **tidy data** 라 부른다. [Wickham(2014)](https://www.jstatsoft.org/article/view/v059i10) 이 정리한 세
원칙은 다음과 같다.

1. 변수 하나는 열 하나다.
2. 관측 하나는 행 하나다.
3. 관측 단위 하나는 표 하나다.

`loans` 에서 변수는 도서관ID, 도서관, 월, 대출권수이고 관측은 "한 도서관의 한 달"이다. dplyr 과 ggplot2 의
함수는 이 모양을 전제로 만들어졌다. 넓은 표가 틀린 것은 아니다. 보고서의 표처럼 **사람에게 보여 줄 때**는
넓은 표가, **계산할 때**는 긴 표가 편하다.


::: {.callout-tip}
**예측해 보자**: 긴 표 `loans` 는 몇 행이어야 하는가? 두 표의 대출권수 합계는 같아야 하는가?

:::


```{r pivot-invariants}

sum(loans_wide[, 3:10], na.rm = TRUE)
sum(loans$대출권수, na.rm = TRUE)

```


행은 21 × 8 = 168 이고 합계는 같다. 모양만 바꾸었으므로 **행의 구성 규칙과 합계는 보존**되어야 한다. 이렇게
변환 전후에 보존되어야 할 양을 정해 두고 대조하는 일을 이 장에서 계속 한다(@sec-verify-transform).


### 절차를 파이프로 적기 {#sec-pipe}

데이터 핸들링은 여러 단계의 변환을 차례로 적용하는 **절차**다. 파이프 연산자 `|>` 는 왼쪽의 결과를 오른쪽
함수의 첫 번째 인수로 넘긴다. `x |> f(y)` 는 `f(x, y)` 와 같다.


```{r pipe-basic}
# 안쪽부터 읽어야 하는 코드
head(arrange(filter(loans, 월 == "2026.08"), desc(대출권수)), 3)

# 위에서 아래로 읽는 코드: 같은 결과
loans |>
  filter(월 == "2026.08") |>
  arrange(desc(대출권수)) |>
  head(3)

```


두 코드의 결과는 같다. 아래 코드는 "8월 행을 고르고, 대출권수가 큰 순서로 정렬하고, 앞의 세 행을 본다"라는
절차를 **적힌 순서대로** 읽을 수 있다. 8장에서 알고리즘을 "누가 실행해도 같은 결과가 나오는 약속된 절차"라고
했다. 파이프로 적은 변환은 그 절차를 한 줄에 한 단계씩 적은 것이다.

이 강의노트는 R 에 내장된 `|>` 를 쓴다. 인터넷의 많은 코드와 이 강의의 이전 노트는 magrittr 패키지의 `%>%` 를
쓴다. 대부분 같은 뜻이지만 두 가지가 다르다.


```{r pipe-difference}
libraries %>% nrow          # %>% 는 괄호가 없어도 된다
libraries |> nrow()         # |> 는 반드시 함수 호출 형태

# 왼쪽 값을 첫 번째가 아닌 인수로 넘길 때
libraries %>% lm(열람석 ~ 1, data = .)
libraries |> lm(열람석 ~ 1, data = _)

```


`%>%` 의 자리표시자는 `.`, `|>` 의 자리표시자는 `_` 이고, `_` 는 `data = _` 처럼 **이름을 붙인 인수**에만 쓸 수
있다. 괄호를 빠뜨린 `libraries |> nrow` 는 오류다. 어느 쪽을 쓰든 한 절차 안에서는 한 가지로 통일한다.


## 행과 열 고르기 {#sec-rows-cols}

표에서 필요한 부분만 남기는 함수들이다. `filter()` 는 행을, `select()` 는 열을 고르고, `arrange()` 는 행의 순서를
바꾼다. 이 가운데 **행 수를 바꾸는 것은 `filter()` 뿐**이므로 조용히 틀리는 곳도 대부분 여기서 생긴다.


### filter(): 조건에 맞는 행 {#sec-filter}

`filter()` 는 조건이 참(`TRUE`)인 행만 남긴다. 8월 자료만 골라 보자.


```{r filter-august}
aug <- loans |> filter(월 == "2026.08")
nrow(aug)

```


21개 도서관의 8월 자료다. 이제 대출권수 3만 권을 기준으로 두 조각으로 나눈다.


::: {.callout-tip}
**예측해 보자**: 8월 21행을 `대출권수 < 30000` 과 `대출권수 >= 30000` 으로 나누었다. 두 조각의 행 수를 더하면
몇이 되겠는가?

:::

```{r filter-split}
small <- aug |> filter(대출권수 < 30000)

c(전체 = nrow(aug), 작음 = nrow(small), 큼 = nrow(large))

```


10 + 10 = 20 이다. 한 행이 어느 조각에도 들어가지 않았다.


```{r filter-lost-row}
aug |> filter(is.na(대출권수))

```


휴관 중인 여울도서관이다. 대출권수가 `NA` 이면 `NA < 30000` 도 `NA >= 30000` 도 참이 아니라 `NA` 다. 값을 모르니
크다고도 작다고도 할 수 없다. `filter()` 는 `TRUE` 인 행만 남기므로 `NA` 인 행은 **두 조건 모두에서 경고 없이
빠진다.** 조건을 뒤집어 `filter(!(대출권수 >= 30000))` 라고 써도 `!NA` 는 `NA` 이므로 결과는 같다.

"3만 권 이상인 도서관을 **빼고** 나머지를 보자"는 의도라면 dplyr 1.2.0 의 `filter_out()` 이 맞다.
`filter_out()` 은 조건이 참인 행을 **뺀다.** 조건이 `NA` 인 행은 참이 아니므로 남는다.


```{r filter-out}
aug |> filter_out(대출권수 >= 30000) |> nrow()

```


::: {.callout-important}
**조건으로 행을 나누었으면 조각들의 행 수를 더해 원래 행 수와 대조한다.** 맞지 않으면 조건 열에 결측값이 있다.
남길 행을 말하고 싶으면 `filter()`, 뺄 행을 말하고 싶으면 `filter_out()` 을 쓴다. 두 함수는 결측값을 반대로
다룬다.

:::


조건을 쉼표로 여러 개 적으면 **모두** 참인 행만 남는다(`&` 와 같다). "둘 중 하나"는 `|` 로 적는다. 여러 값
가운데 하나와 같은 행을 고를 때는 흔한 함정이 하나 있다.


::: {.callout-tip}
**예측해 보자**: 서울과 대전의 도서관(서울 3곳, 대전 2곳)을 고르려 한다. 두 코드의 결과는 같겠는가?

```r
libraries |> filter(시도 == c("서울특별시", "대전광역시"))
libraries |> filter(시도 %in% c("서울특별시", "대전광역시"))
```

:::


```{r filter-recycle}
libraries |>
  filter(시도 == c("서울특별시", "대전광역시")) |>
  select(도서관ID, 도서관, 시도)

libraries |>
  filter(시도 %in% c("서울특별시", "대전광역시")) |>
  select(도서관ID, 도서관, 시도)

```


첫 번째 코드는 5곳 가운데 2곳만 골랐고 경고도 없다. `==` 는 두 벡터를 **같은 위치끼리** 비교한다. 길이 20 인
`시도` 와 길이 2 인 벡터를 비교하면 짧은 쪽이 되풀이되어, 홀수 번째 행은 서울과, 짝수 번째 행은 대전과
비교된다. 1행(누리, 서울)과 6행(다온, 대전)만 우연히 자리가 맞았다. 행 수가 2의 배수가 아니면 경고가 나오지만
20행이라 그마저 없다. **"여러 값 가운데 하나"는 `%in%`** 이다.


### select() 와 rename(): 열 고르기 {#sec-select}

`select()` 는 열 이름으로 열을 고른다. 행 수는 바뀌지 않는다.


```{r select-basic}
libraries |> select(도서관, 시도, 열람석) |> head(3)

loans_wide |> select(도서관ID, `2026.07`, `2026.08`) |> head(3)

```


`2026.07` 처럼 숫자로 시작하거나 점이 든 이름은 역따옴표로 감싼다. 이름의 규칙으로 여러 열을 한 번에 고르는
도우미 함수도 있다.


```{r select-helpers}
loans_wide |> select(도서관, starts_with("2026.0")) |> names()

libraries |> select(where(is.numeric)) |> names()

libraries |> select(-개관일) |> names()

```


| 도우미 | 고르는 열 |
|:--|:--|
| `starts_with("a")`, `ends_with("a")`, `contains("a")` | 이름이 a 로 시작하는, a 로 끝나는, a 를 포함하는 열 |
| `where(is.numeric)` | 조건 함수가 `TRUE` 를 돌려주는 열 (여기서는 숫자 열) |
| `시작:끝` | 두 열 사이의 모든 열 |
| `-열` | 그 열을 뺀 나머지 |

: {tbl-colwidths="[42,58]"}

열 이름만 바꿀 때는 `rename(새 이름 = 옛 이름)` 을 쓴다.


```{r rename}
libraries |> rename(좌석수 = 열람석) |> names()

```


### arrange() 와 slice_*(): 정렬과 상위 행 {#sec-arrange}

`arrange()` 는 열의 값 순서로 행을 정렬한다. 내림차순은 `desc()` 로 감싼다.


::: {.callout-tip}
**예측해 보자**: 8월 대출권수를 내림차순으로 정렬하면 대출권수가 `NA` 인 여울도서관은 맨 위에 오겠는가, 맨
아래에 오겠는가?

:::


```{r arrange-na}
aug |> arrange(desc(대출권수)) |> tail(3)

```


`arrange()` 는 오름차순이든 내림차순이든 **결측값을 항상 맨 뒤**에 둔다. 내림차순으로 정렬하고 `head()` 로 상위
몇 곳을 볼 때는 결측값이 보이지 않으므로, 결측값이 있다는 사실 자체를 따로 확인해야 한다.

값이 큰 행 몇 개를 고를 때는 `slice_max()` 가 편하다. 시도별 도서관 수가 많은 두 시도를 골라 보자.


```{r slice-max-ties}
libraries |> count(시도) |> slice_max(n, n = 2)

```


`n = 2` 라고 했는데 세 행이 나왔다. 대전과 충남이 도서관 2곳으로 **동률**이기 때문이다. `slice_max()` 는 기본으로
동률을 모두 남긴다. 정확히 두 행만 원하면 `with_ties = FALSE` 를 주는데, 그러면 동률 가운데 무엇이 남을지는
표의 순서에 달린다. 동률을 어떻게 처리할지는 함수가 아니라 **분석하는 사람이 정할 일**이다.


## 열 만들고 바꾸기 {#sec-mutate}

`mutate()` 는 기존 열로 새 열을 만들거나 기존 열을 바꾼다. 행 수는 바뀌지 않지만, 값을 정하는 규칙이 틀리면
모든 행이 조용히 틀린다.


### mutate() {#sec-mutate-basic}


```{r mutate-basic}
libraries |>
  mutate(개관연도 = as.integer(format(개관일, "%Y")),
         운영연수 = 2026 - 개관연도) |>
  select(도서관, 개관일, 개관연도, 운영연수) |>
  head(3)

```


`mutate()` 안에서는 앞에서 만든 열(`개관연도`)을 바로 다음 계산에 쓸 수 있다. 계산은 열 전체에 한 번에
적용된다. 4장에서 본 벡터 연산이다.


### 조건에 따라 값 정하기: if_else() 와 case_when() {#sec-case-when}

조건이 둘이면 `if_else()`, 셋 이상이면 `case_when()` 을 쓴다. base R 에도 `ifelse()` 가 있는데, 결과의 **유형**을
다루는 방식이 다르다.


::: {.callout-tip}
**예측해 보자**: 2005년 이전에 개관한 도서관만 개관일을 남기고 나머지는 `NA` 로 두려 한다. 두 코드가 돌려주는
값의 모양은 같겠는가?

```r
early <- libraries$개관일 < as.Date("2005-01-01")
ifelse(early, libraries$개관일, NA)
if_else(early, libraries$개관일, NA)
```

:::


```{r ifelse-date}
early <- libraries$개관일 < as.Date("2005-01-01")

head(ifelse(early, libraries$개관일, NA), 3)
head(if_else(early, libraries$개관일, NA), 3)

```


`ifelse()` 는 날짜를 `12492` 같은 수로 바꾸어 버렸다. R 의 날짜는 1970년 1월 1일부터 센 날 수에 "날짜"라는
속성을 붙인 값인데, `ifelse()` 는 그 속성을 버린다. `if_else()` 는 참일 때와 거짓일 때의 값이 **같은 유형**이어야
한다는 규칙을 지키고 유형을 보존한다. 규칙에 어긋나면 결과를 만들지 않고 멈춘다.


```{r if-else-type-error}
libraries |> mutate(규모 = if_else(열람석 >= 300, "대형", 0))

```


조용히 틀린 값을 만드는 것보다 멈추는 편이 낫다. 문자와 숫자를 섞으려 했다면 대개 실수다.

`case_when()` 은 `조건 ~ 값` 을 위에서부터 차례로 검사해 **처음으로 참인 조건의 값**을 준다.


::: {.callout-tip}
**예측해 보자**: 열람석 300석 이상을 대형, 200석 이상을 중형, 나머지를 소형으로 나누려 했다. 아래 코드에서
대형은 몇 곳이 되겠는가? (열람석 300석 이상인 도서관은 5곳이다.)

```r
libraries |>
  mutate(규모 = case_when(열람석 >= 200 ~ "중형",
                          열람석 >= 300 ~ "대형",
                          .default = "소형")) |>
  count(규모)
```

:::


```{r case-when-order}
libraries |>
  mutate(규모 = case_when(열람석 >= 200 ~ "중형",
                          열람석 >= 300 ~ "대형",
                          .default = "소형")) |>
  count(규모)

```


대형은 하나도 없다. 320석인 누리도서관은 첫 조건 `열람석 >= 200` 에서 이미 참이 되어 "중형"을 받고, 두 번째
조건은 검사되지 않는다. 조건은 **좁은 것부터** 적는다.


```{r case-when-fixed}
libraries |>
  mutate(규모 = case_when(열람석 >= 300 ~ "대형",
                          열람석 >= 200 ~ "중형",
                          .default = "소형")) |>
  count(규모)

```


`.default` 는 어느 조건에도 맞지 않는 행에 줄 값이다. 그런데 모든 경우를 조건으로 적었다고 **믿는** 상황이라면
`.default` 대신 `.unmatched = "error"` 를 준다(dplyr 1.2.0). 빠뜨린 경우가 있으면 조용히 기본값을 주지 않고 멈춘다.


```{r case-when-unmatched}
libraries |>
  mutate(규모 = case_when(열람석 >= 300 ~ "대형",
                          열람석 >= 200 ~ "중형",
                          .unmatched = "error"))

```


소형 조건을 빠뜨렸다는 사실과 해당 행의 위치를 알려 준다.


### 값을 다른 값으로: recode_values() 와 replace_values() {#sec-recode}

조건이 아니라 **값 자체**를 다른 값으로 바꿀 때는 dplyr 1.2.0 의 두 함수를 쓴다.

| 함수 | 쓰임 | 짝이 없는 값 |
|:--|:--|:--|
| `recode_values()` | 모든 값을 새 값으로 옮겨 **새 변수**를 만든다 | `default` 또는 `unmatched = "error"` |
| `replace_values()` | **일부 값만** 바꾸고 나머지는 그대로 둔다 | 그대로 남음 |

: {tbl-colwidths="[24,50,26]"}

월을 분기로 묶어 보자. 여러 값을 한 값으로 옮길 때는 왼쪽에 벡터를 적는다.


```{r recode-quarter}
quarterly <- loans |>
  mutate(분기 = recode_values(월,
    c("2026.01", "2026.02", "2026.03") ~ "1분기",
    c("2026.04", "2026.05", "2026.06") ~ "2분기",
    c("2026.07", "2026.08") ~ "3분기",
    unmatched = "error"
  ))

quarterly |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE), 달 = n_distinct(월), .by = 분기)

```


`unmatched = "error"` 를 준 까닭은 `case_when()` 과 같다. 3분기에 `"2026.08"` 을 빠뜨렸다면 8월 행에 분기가 없다는
오류로 멈춘다. 9월 자료가 추가되었는데 표를 고치지 않은 경우도 여기서 드러난다. 결과표의 `달` 열도 대조
수단이다. 3분기는 7월과 8월 두 달뿐이므로 다른 분기와 합계를 그대로 비교할 수 없다.

`replace_values()` 는 @sec-join-assert 에서 시도 명칭을 고칠 때 쓴다. dplyr 1.2.0 이전의 `case_match()` 와
`recode()` 는 이 두 함수로 대체되었다.


### 여러 열에 한 번에: across() {#sec-across}

넓은 표에서 월 열 여덟 개에 같은 계산을 하려면 열 이름을 여덟 번 적어야 한다. `across()` 는 고른 열마다 같은
함수를 적용한다.


```{r across-sum}
loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(x, na.rm = TRUE)))

```


`\(x) sum(x, na.rm = TRUE)` 는 "x 를 받아 결측을 뺀 합을 돌려주는 함수"를 그 자리에서 만든 것이다. `\(x)` 는
`function(x)` 를 줄여 쓴 표기다(R 4.1 이상). 같은 방법으로 월마다 결측값 수를 셀 수 있다.


```{r across-na}
loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(is.na(x))))

```


결측값은 모두 8칸이다. 긴 표에서 `sum(is.na(loans$대출권수))` 로 센 수와 같은지 확인해 보자.

같은 월 합계를 긴 표에서 구하면 `summarise(.by = 월)` 한 줄이다(@sec-summarise). **서로 다른 방법으로 구한 같은
값을 대조**하는 것은 코드를 검증하는 좋은 방법이다.


```{r across-cross-check}
by_wide <- loans_wide |>
  summarise(across(starts_with("2026"), \(x) sum(x, na.rm = TRUE)))

by_long <- loans |>
  summarise(합계 = sum(대출권수, na.rm = TRUE), .by = 월)

all.equal(unlist(by_wide), setNames(by_long$합계, by_long$월))

```


## 집단별로 요약하기 {#sec-summarise}

`summarise()` 는 여러 행을 한 행으로 줄인다. 집단을 지정하면 집단마다 한 행이 된다. 요약은 행을 줄이므로,
**줄어든 행들이 원래 행을 빠짐없이 한 번씩 대표하는지** 확인하는 일이 중요하다.


### summarise() 와 .by {#sec-summarise-by}


```{r summarise-all}
loans |>
  summarise(총대출권수 = sum(대출권수, na.rm = TRUE),
            도서관수 = n_distinct(도서관ID))

```


집단별로 요약할 때는 `.by` 에 집단을 나누는 열을 적는다.


```{r summarise-by-month}
monthly <- loans |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE), .by = 월)

monthly

```


::: {.callout-tip}
**예측해 보자**: `monthly` 의 여덟 달 대출권수를 모두 더하면 바로 위의 총대출권수와 같아야 하는가?

:::


```{r summarise-invariant}
sum(monthly$대출권수)

```


같다. 한 행이 정확히 한 달에 속하므로 **집단 합계의 합은 전체 합계**다. 이 등식이 깨지면 어떤 행이 집단에서
빠졌거나 두 집단에 들어간 것이다.

`.by` 와 같은 일을 `group_by()` 로도 할 수 있다. 결과의 순서가 다르다. `.by` 는 표에 **처음 나온 순서**를 지키고,
`group_by()` 는 집단 값을 **정렬**한다.


```{r by-vs-group-by-order}
libraries |> summarise(도서관수 = n(), .by = 시도) |> head(3)

libraries |> group_by(시도) |> summarise(도서관수 = n()) |> head(3)

```


### group_by() 는 남는다 {#sec-group-by}

`group_by()` 와 `.by` 의 더 중요한 차이는 **집단 정보가 표에 남는가**이다. `.by` 는 그 한 번의 계산에만 집단을
적용한다. `group_by()` 는 표에 집단 정보를 붙여 두고, 풀기 전까지 뒤따르는 모든 계산이 집단마다 따로 이루어진다.


::: {.callout-tip}
**예측해 보자**: 각 도서관이 그 달 전체 대출에서 차지한 비중을 구한 뒤, 전체 월 대출권수의 평균을 구하려 한다.
마지막 줄의 결과는 몇 행이겠는가?

```r
share <- loans |>
  group_by(월) |>
  mutate(월비중 = 대출권수 / sum(대출권수, na.rm = TRUE))

share |> summarise(평균대출 = mean(대출권수, na.rm = TRUE))
```

:::


```{r group-by-persists}
share <- loans |>
  group_by(월) |>
  mutate(월비중 = 대출권수 / sum(대출권수, na.rm = TRUE))

share |> summarise(평균대출 = mean(대출권수, na.rm = TRUE))

```


한 행이 아니라 여덟 행이 나왔다. `share` 에는 `group_by(월)` 이 남아 있어 `summarise()` 도 월마다 계산했다. 표를
출력해 보면 첫머리에 집단 정보가 적혀 있다.


```{r group-by-header}
print(share, n = 3)

```


`# Groups: 월 [8]` 이 집단이 남아 있다는 표시다. `ungroup()` 으로 집단을 풀어야 전체 평균이 된다.


```{r ungroup}
share |> ungroup() |> summarise(평균대출 = mean(대출권수, na.rm = TRUE))

```


비중이 의도대로 계산되었는지도 확인한다. 월 안에서 구한 비중이면 **월마다 합이 1** 이어야 한다.


```{r share-check}
share |> summarise(비중합 = sum(월비중, na.rm = TRUE)) |> head(3)

```


한 번의 계산에만 집단이 필요하면 `mutate(..., .by = 월)` 처럼 `.by` 를 쓴다. 결과에 집단이 남지 않아 뒤의 계산이
엉뚱하게 나뉘는 일이 없다. 두 개 이상의 열로 `group_by()` 한 뒤 `summarise()` 하면 dplyr 이 메시지를 남긴다.


```{r group-by-message}
#| message: true
quarterly |>
  group_by(분기, 도서관ID) |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE))

```


결과가 아직 `분기` 로 묶여 있다는 안내다. 메시지를 지우려고 `.groups` 를 붙이기보다, 메시지가 말하는 대로
`.by = c(분기, 도서관ID)` 를 쓰는 편이 뒤탈이 없다.


### 개수 세기: n() 와 count() {#sec-count}

`n()` 은 집단의 **행 수**를 센다. 값이 있는지는 따지지 않는다. 값이 있는 행의 수는 `sum(!is.na(열))` 로 따로 센다.


```{r n-vs-non-missing}
loans |>
  summarise(행 = n(), 값있음 = sum(!is.na(대출권수)), .by = 도서관) |>
  filter(행 != 값있음)

```


세 도서관은 여덟 달 가운데 대출권수가 없는 달이 있다. 행 수를 세는 `count()` 는 `summarise(n = n(), .by = )` 를
줄여 쓴 것이다. `wt` 에 열을 주면 행 수 대신 그 열의 합을 센다.


```{r count-wt}
loans |> count(월) |> head(3)
loans |> count(월, wt = 대출권수) |> head(3)

```


::: {.callout-tip}
**예측해 보자**: 여울도서관의 분기별 대출권수와 값이 있는 달의 수를 한 번에 구하려 했다. `값있는달` 열에는 어떤
수가 나오겠는가?

```r
quarterly |>
  filter(도서관 == "여울도서관") |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE),
            값있는달 = sum(!is.na(대출권수)),
            .by = 분기)
```

:::


```{r summarise-name-reuse}
quarterly |>
  filter(도서관 == "여울도서관") |>
  summarise(대출권수 = sum(대출권수, na.rm = TRUE),
            값있는달 = sum(!is.na(대출권수)),
            .by = 분기)

```


세 분기 모두 1 이다. 여울도서관은 1분기에 석 달, 2분기에 두 달 값이 있는데도 그렇다. `summarise()` 안의 계산은
**위에서부터 차례로** 이루어지고, 앞에서 만든 열은 뒤의 계산에서 바로 쓸 수 있다(@sec-mutate-basic 의
`mutate()` 와 같다). 두 번째 줄의 `대출권수` 는 원래 열이 아니라 **첫 줄이 만든 합계 한 개**를 가리킨다. 새 열에는
원래 열과 다른 이름을 붙인다.


```{r summarise-name-fixed}
quarterly |>
  filter(도서관 == "여울도서관") |>
  summarise(합계 = sum(대출권수, na.rm = TRUE),
            값있는달 = sum(!is.na(대출권수)),
            .by = 분기)

```


### 결측과 요약 {#sec-na-summary}

바로 위 결과에서 여울도서관의 3분기 합계는 0 이다. 7월과 8월에 **한 권도 빌려주지 않았다**는 뜻일까? 두 달
모두 휴관이라 값이 **없다**. `sum()` 은 `na.rm = TRUE` 로 결측을 빼고 나면 더할 값이 하나도 없을 때 0 을 돌려준다.
0 과 "자료 없음"은 다르므로 합계 옆에 **값이 있는 달의 수**를 함께 적는다.

평균은 결측을 어떻게 다루느냐에 따라 분모가 달라진다.


::: {.callout-tip}
**예측해 보자**: 6월부터 휴관한 여울도서관과 5월에 문을 연 새솔도서관의 "월평균 대출권수"는 얼마인가? 답이
하나로 정해지는가?

:::


```{r mean-denominator}
loans |>
  summarise(평균 = mean(대출권수),
            운영한_달_평균 = mean(대출권수, na.rm = TRUE),
            여덟_달_평균 = sum(대출권수, na.rm = TRUE) / 8,
            .by = 도서관) |>
  filter(도서관 %in% c("누리도서관", "여울도서관", "새솔도서관"))

```


결측이 없는 누리도서관은 세 값이 같다. 여울도서관은 `na.rm` 을 주지 않으면 `NA`, 주면 문을 연 다섯 달의 평균
19,751권, 휴관한 달을 0 으로 보면 12,344권이다. 어느 값이 맞는지는 **질문이 정한다.** 운영 중인 도서관의 이용
수준을 보려면 운영한 달의 평균이, 주민이 1년 동안 받은 서비스의 양을 보려면 휴관을 0 으로 센 평균이 맞다.
`na.rm = TRUE` 는 결측을 "없는 셈"으로 치는 결정이다. 코드 한 줄에 숨겨 두지 말고 결과표에 분모를 적는다.


::: {.callout-important}
**요약에서 결측값을 빼는 것은 계산이 아니라 결정이다.** 합계 옆에는 값이 있는 행의 수를, 평균에는 분모를 함께
보고한다. 0 이 나왔으면 "0 이었다"인지 "값이 없었다"인지 확인한다.

:::


### 한 집단에서 여러 행: reframe() {#sec-reframe}

`summarise()` 는 집단마다 **한 행**을 돌려주어야 한다. 사분위수처럼 값이 여러 개인 요약은 dplyr 1.2.0 부터
오류다.


```{r summarise-multi-row}
loans |>
  summarise(사분위 = quantile(대출권수, c(0.25, 0.75), na.rm = TRUE),
            .by = 월)

```


집단마다 여러 행이 필요하면 `reframe()` 을 쓴다.


```{r reframe}
loans |>
  reframe(분위 = c("Q1", "Q3"),
          대출권수 = quantile(대출권수, c(0.25, 0.75), na.rm = TRUE),
          .by = 월) |>
  head(4)

```


## 표 합치기 {#sec-joins}

시도별 인구 1만 명당 대출권수를 구하려면 대출(대출 표), 소속 시도(기본 정보 표), 인구(인구 표)가 모두 필요하다.
세 정보는 서로 다른 표에 있다. 두 표를 **키**로 짝지어 한 표로 만드는 것을 **결합**(join)이라 한다. 결합은
데이터 핸들링에서 행 수가 가장 크게, 가장 조용히 바뀌는 곳이다.


### 키: 행을 식별하는 열 {#sec-keys}

**키**(key)는 표에서 한 행을 가리키는 열(또는 열의 조합)이다. 기본 정보 표의 키는 `도서관ID`, 긴 대출 표의 키는
`도서관ID` 와 `월` 의 조합, 인구 표의 키는 `시도` 다. 키라면 **같은 값이 두 번 나오지 않아야** 한다. 합치기 전에
확인한다.


::: {.callout-tip}
**예측해 보자**: 세 표의 키에서 두 번 이상 나오는 값이 있겠는가?

:::


```{r key-check}
libraries  |> count(도서관ID) |> filter(n > 1)
loans      |> count(도서관ID, 월) |> filter(n > 1)
population |> count(시도) |> filter(n > 1)

```


인구 표에 세종특별자치시가 두 번 있다.


```{r key-duplicate-rows}
population |> filter(시도 == "세종특별자치시")

```


두 행의 값이 완전히 같다. 자료를 합치는 과정에서 한 줄이 더 들어간 것으로 보인다. 이 중복이 결합에서 어떤
일을 일으키는지 보기 위해 **일단 그대로 둔다.**


### 결합의 종류 {#sec-join-types}

두 표 `x` 와 `y` 를 키로 짝지을 때, 짝이 없는 행을 어떻게 다루느냐에 따라 함수가 나뉜다.

| 함수 | 결과에 남는 행 |
|:--|:--|
| `left_join(x, y)` | `x` 의 모든 행. 짝이 없으면 `y` 에서 온 열은 `NA` |
| `inner_join(x, y)` | 짝이 있는 행만 |
| `full_join(x, y)` | 양쪽의 모든 행 |
| `semi_join(x, y)` | 짝이 있는 `x` 의 행. `y` 의 열은 붙이지 않음 |
| `anti_join(x, y)` | 짝이 **없는** `x` 의 행. `y` 의 열은 붙이지 않음 |

: {tbl-colwidths="[28,72]"}

앞의 셋은 열을 붙이고, 뒤의 둘은 짝이 있는지로 `x` 의 행을 고른다. `anti_join()` 은 **짝이 없는 행을 찾는 검사
도구**로 자주 쓴다.


::: {.callout-tip}
**예측해 보자**: 긴 대출 표(168행)에 기본 정보 표의 시도를 붙인다. `left_join()` 과 `inner_join()` 의 결과는 각각
몇 행이겠는가? 대출권수 합계는 그대로이겠는가?

:::


```{r left-vs-inner}
sido_key <- libraries |> select(도서관ID, 시도)

loans_left  <- loans |> left_join(sido_key, by = "도서관ID")
loans_inner <- loans |> inner_join(sido_key, by = "도서관ID")

c(원래 = nrow(loans), left = nrow(loans_left), inner = nrow(loans_inner))

c(원래 = sum(loans$대출권수, na.rm = TRUE),
  inner = sum(loans_inner$대출권수, na.rm = TRUE))

```


`inner_join()` 은 8행과 대출권수 33,287권을 **경고 없이** 버렸다. 버려진 행은 `anti_join()` 으로 찾는다.


```{r anti-join-loans}
loans |> anti_join(libraries, by = "도서관ID") |> distinct(도서관ID, 도서관)

```


@sec-row-unit 에서 본 새솔도서관이다. 기본 정보 표에 없으니 짝이 없다. `left_join()` 은 이 8행을 남기되 시도를
`NA` 로 채웠다. 어느 쪽이든 새솔도서관의 대출은 시도별 표에 들어가지 못한다. 차이는 **흔적이 남느냐**다.
`left_join()` 의 결과를 시도별로 요약하면 시도가 `NA` 인 집단이 보이지만, `inner_join()` 의 결과에서는 아무 흔적도
없다.

결합할 때는 `by` 에 키를 **반드시 적는다.** 적지 않으면 두 표에 같은 이름으로 있는 **모든 열**을 키로 쓴다.


```{r join-without-by}
#| message: true
loans |> left_join(libraries) |> names()

```


메시지가 알려 주듯 `도서관ID` 와 `도서관` 두 열로 짝지었다. 여기서는 두 열이 같은 뜻이라 결과가 맞지만, 이름만
같고 뜻이 다른 열(예: 한 표의 `연도` 는 대출 연도, 다른 표의 `연도` 는 개관 연도)이 있으면 짝이 거의 맞지 않는다
(연습문제 8). 반대로 `by = "도서관ID"` 만 주면 키가 아닌 같은 이름의 열이 양쪽에서 와 이름이 바뀐다.


```{r join-suffix}
loans |> left_join(libraries, by = "도서관ID") |> names()

```


`도서관.x`, `도서관.y` 가 생겼다. 필요한 열만 골라 붙이면(`select(libraries, 도서관ID, 시도)`) 이런 일이 없다.


### 결합이 행 수를 바꾸는 두 경우 {#sec-join-rows}

이제 도서관마다 시도의 인구를 붙인다.


::: {.callout-tip}
**예측해 보자**: 기본 정보 표(20행)에 인구 표를 `left_join()` 으로 붙인다. 결과는 몇 행이고, 인구가 `NA` 인 행은
몇 개이겠는가?

:::


```{r lib-pop-join}
#| warning: true
lib_pop <- libraries |> left_join(population, by = "시도")

nrow(lib_pop)

lib_pop |>
  filter(is.na(인구) | 시도 == "세종특별자치시") |>
  select(도서관ID, 도서관, 시도, 인구)

```


결합이 행 수를 바꾸는 두 경우가 한꺼번에 나타났다.

**첫째, 짝이 없는 키.** 새봄도서관과 여울도서관의 인구가 `NA` 다. 양쪽 표의 시도 이름을 비교해 보자.


```{r anti-join-sido}
libraries  |> anti_join(population, by = "시도") |> distinct(시도)
population |> anti_join(libraries, by = "시도") |> distinct(시도)

```


기본 정보 표는 **2026년 현재 명칭**(강원특별자치도, 전북특별자치도)을 쓰고 인구 표는 **이전 명칭**(강원도,
전라북도)을 쓴다. 강원도는 2023년 6월, 전라북도는 2024년 1월에 이름이 바뀌었다. 여러 해의 공공데이터를 합칠 때
흔히 만나는 문제다. 제주특별자치도는 이 자료에 도서관이 없어서 짝이 없는 것이므로 문제가 아니다.
`left_join()` 은 짝이 없는 행을 `NA` 로 남기고, `inner_join()` 이었다면 두 도서관이 결과에서 사라졌다.

**둘째, 중복된 키.** 온새미도서관이 두 행이 되었다. 인구 표에 세종특별자치시가 두 번 있으므로 두 행과 모두
짝지어졌다. 기본 정보 표는 20행인데 결과는 21행이다. dplyr 은 이 경우 "예상하지 못한 다대다 관계"라는 경고를
남긴다. 그러나 경고가 **늘 나오지는 않는다.** `x` 쪽 키가 중복 없이 한 번씩만 나오면(예: 시도별로 요약한 표에
인구를 붙이면) 경고 없이 행만 늘어난다(@sec-ai-handling).

늘어난 행은 합계를 부풀린다. 8월 대출에 시도와 인구를 차례로 붙여 보자.


```{r join-inflates-total}
aug_pop <- aug |>
  left_join(sido_key, by = "도서관ID") |>
  left_join(population, by = "시도")

c(행 = nrow(aug_pop),
  합계 = sum(aug_pop$대출권수, na.rm = TRUE),
  원래합계 = sum(aug$대출권수, na.rm = TRUE))

```


21행이 22행이 되고 8월 합계가 41,275권 늘었다. 온새미도서관의 8월 대출권수가 한 번 더 더해진 것이다.


### 가정을 코드에 적기: relationship 과 unmatched {#sec-join-assert}

결합하기 전에 우리는 두 표의 관계를 알고 있다. 도서관은 여럿이 한 시도에 속하고, 시도는 인구 표에 한 번만
나와야 한다. **다대일**(many-to-one) 관계다. 이 가정을 `relationship` 인수로 코드에 적으면, 가정이 깨질 때
결합이 멈춘다.


```{r relationship-error}
libraries |>
  left_join(population, by = "시도", relationship = "many-to-one")

```


| `relationship` | 뜻 |
|:--|:--|
| `"one-to-one"` | 양쪽 모두 키가 한 번씩만 나온다 |
| `"one-to-many"` | `x` 의 키는 한 번씩, `y` 의 키는 여러 번 나올 수 있다 |
| `"many-to-one"` | `x` 의 키는 여러 번, `y` 의 키는 한 번씩만 나온다 |
| `"many-to-many"` | 양쪽 모두 여러 번 나올 수 있다 (의도한 경우에만) |

: {tbl-colwidths="[28,72]"}

짝이 없는 행에 대한 가정은 `unmatched` 인수로 적는다. "모든 도서관의 시도가 인구 표에 있어야 한다"는 가정은
`inner_join()` 에 `unmatched = c("error", "drop")` 을 주어 적는다. 첫 번째 값은 `x`, 두 번째 값은 `y` 의 짝 없는 행을
다룬다. `x` 에 짝 없는 행이 있으면 멈추고, `y` 에만 있는 행(제주특별자치도)은 버린다.


```{r unmatched-error}
libraries |>
  inner_join(distinct(population), by = "시도",
             relationship = "many-to-one", unmatched = c("error", "drop"))

```


5행, 강원특별자치도의 새봄도서관에서 멈췄다.


::: {.callout-caution}
`left_join()` 에 `unmatched = "error"` 를 주면 **`y` 의 짝 없는 행**을 검사한다. `left_join()` 에서 버려지는 행은
`y` 쪽에만 생기기 때문이다. "`x` 의 모든 행에 짝이 있다"를 확인하려는 목적과 반대이므로, 그 목적이면 위처럼
`inner_join()` 을 쓰거나 `anti_join()` 결과가 0행인지 확인한다.

:::


두 결함을 고친다. 세종 행은 **두 행의 값이 완전히 같다는 것을 확인했으므로** `distinct()` 로 하나를 지운다. 값이
달랐다면 어느 행이 맞는지 자료를 준 기관에 확인해야 할 일이지 함수로 해결할 일이 아니다. 이전 명칭은
`replace_values()` 로 현재 명칭으로 바꾼다(@sec-recode).


```{r population-clean}
population_clean <- population |>
  distinct() |>
  mutate(시도 = replace_values(시도,
    "강원도" ~ "강원특별자치도",
    "전라북도" ~ "전북특별자치도"
  ))

lib_pop <- libraries |>
  inner_join(population_clean, by = "시도",
             relationship = "many-to-one", unmatched = c("error", "drop"))

nrow(lib_pop)

```


이번에는 멈추지 않고 20행이 나왔다. 결합 코드에 적어 둔 두 가정(시도는 인구 표에 한 번씩, 모든 도서관의 시도는
인구 표에 있다)이 **실행될 때마다 확인**된다. 다음 달 인구 표가 새로 들어와 같은 결함이 다시 생겨도 조용히
넘어가지 않는다.


### 행 붙이기: bind_rows() {#sec-bind-rows}

결합이 열을 붙인다면 `bind_rows()` 는 **행**을 붙인다. 기관에 문의해 새솔도서관의 개관일이 2026년 5월 1일임을
확인했다고 하자. 기본 정보 표에 행을 추가한다.


```{r bind-rows}
new_library <- tibble(도서관ID = "L21", 도서관 = "새솔도서관",
                      개관일 = as.Date("2026-05-01"))

bind_rows(libraries, new_library) |> tail(2)

```


`bind_rows()` 는 **열 이름**으로 짝을 맞추고, 한쪽에 없는 열(`시도`, `열람석`)은 `NA` 로 채운다. 이것도 조용한
변화다. 붙인 뒤에는 결측값이 새로 생기지 않았는지 확인한다. 같은 이름의 열인데 유형이 다르면 붙이지 않고 멈춘다.


```{r bind-rows-type-error}
bind_rows(libraries,
          tibble(도서관ID = "L21", 도서관 = "새솔도서관", 개관일 = "2026-05-01"))

```


시도를 모르는 채로 새솔도서관을 추가하면 시도별 분석에서 여전히 빠진다. 새솔도서관을 어떻게 다룰지는
@sec-verify-transform 에서 정한다.


## 모양 바꾸기 {#sec-pivot}

@sec-tidy 에서 넓은 표를 긴 표로 한 번 바꾸었다. 이 절에서는 두 방향의 변환을 자세히 보고, 모양을 바꾼 뒤 정보가
그대로인지 확인하는 방법을 다룬다.


### 넓은 표를 긴 표로: pivot_longer() {#sec-pivot-longer}

`pivot_longer()` 의 핵심 인수는 셋이다. 접을 열(`cols`), 열 이름이 들어갈 새 열의 이름(`names_to`), 칸의 값이 들어갈
새 열의 이름(`values_to`)이다. 열 이름 `"2026.01"` 에는 연도와 월 두 정보가 들어 있다. `names_to` 에 이름을 두 개
주고 `names_sep` 으로 나누는 기준을 주면 두 열로 나눌 수 있다.


::: {.callout-tip}
**예측해 보자**: 아래 코드는 열 이름을 점(`.`)에서 나누어 연도와 월 두 열을 만들려는 것이다. 결과의 첫 행에서
`연도` 와 `월` 은 무엇이겠는가?

```r
loans_wide |>
  pivot_longer(starts_with("2026"),
               names_to = c("연도", "월"), names_sep = ".",
               values_to = "대출권수")
```

:::


```{r names-sep-regex}
#| warning: true
loans_wide |>
  pivot_longer(starts_with("2026"),
               names_to = c("연도", "월"), names_sep = ".",
               values_to = "대출권수") |>
  head(3)

```


연도와 월이 모두 빈 문자열이다. 여덟 달이 같은 값이 되었으니 이 표로는 월을 구분할 수 없다. `names_sep` 은
**정규표현식**으로 해석되고, 정규표현식에서 `.` 은 "아무 글자 하나"라는 뜻이다(10장). 모든 글자가 구분자가
되어 조각이 모두 비었다. 경고가 하나 나오지만 결과는 만들어진다. 점 자체를 뜻하려면 `"\\."` 로 적는다.


```{r names-sep-fixed}
loans_ym <- loans_wide |>
  pivot_longer(starts_with("2026"),
               names_to = c("연도", "월"), names_sep = "\\.",
               names_transform = list(연도 = as.integer, 월 = as.integer),
               values_to = "대출권수")

loans_ym |> head(3)

```


`names_transform` 으로 나눈 조각을 정수로 바꾸었다. 월을 수로 다루면 정렬과 비교가 쉽다.

`values_drop_na = TRUE` 를 주면 값이 `NA` 인 칸은 행으로 만들지 않는다.


```{r values-drop-na}
loans_dropped <- loans_wide |>
  pivot_longer(starts_with("2026"), names_to = "월", values_to = "대출권수",
               values_drop_na = TRUE)

c(유지 = nrow(loans), 삭제 = nrow(loans_dropped))

loans_dropped |> count(도서관) |> filter(n < 8)

```


168행이 160행이 되었다. 합계는 달라지지 않지만 **"값이 없는 달"이 "행이 없는 달"로 바뀐다.** 이 표에서
`n()` 으로 달 수를 세면 여울도서관은 5달이고, @sec-na-summary 의 여덟 달 평균을 구하려면 분모 8 을 따로 알고
있어야 한다. 결측을 행으로 남길지는 뒤의 계산이 무엇인지 보고 정한다.


### 긴 표를 넓은 표로: pivot_wider() {#sec-pivot-wider}

`pivot_wider()` 는 반대 방향이다. `names_from` 의 값이 열 이름이 되고, `values_from` 의 값이 칸을 채운다. 사람이 읽을
표를 만들 때 쓴다.


```{r pivot-wider-quarter}
quarterly |>
  summarise(합계 = sum(대출권수, na.rm = TRUE), .by = c(도서관, 분기)) |>
  pivot_wider(names_from = 분기, values_from = 합계) |>
  head(3)

```


넓은 표의 한 칸은 **(도서관, 분기) 조합 하나**에 대응한다. 같은 조합이 긴 표에 두 번 나오면 한 칸에 두 값이
들어가야 하므로 문제가 생긴다. @sec-join-rows 에서 중복된 세종 행 때문에 행이 늘어난 표를 넓은 표로 바꾸어 보자.


```{r pivot-wider-duplicates}
#| warning: true
loans_pop <- loans |>
  left_join(sido_key, by = "도서관ID") |>
  left_join(population, by = "시도")

nrow(loans_pop)

wide_again <- loans_pop |>
  select(도서관ID, 도서관, 월, 대출권수) |>
  pivot_wider(names_from = 월, values_from = 대출권수)

```


168행이던 대출 표가 176행이 되었고(온새미도서관 8행이 두 번), `pivot_wider()` 는 칸마다 값이 하나가 아니라서
**리스트 열**(list-column)을 만들었다는 경고를 냈다. 경고는 중복을 찾는 dplyr 코드까지 알려 준다. 넓은 표로 바꾸는
단계가 **키 중복을 드러내는 검사**가 된 셈이다. 경고를 없애려고 `values_fn = sum` 을 주면 중복된 값이 더해져
경고만 사라지고 틀린 값이 남는다. 먼저 중복의 원인을 찾는다.


### 왕복 검사 {#sec-pivot-roundtrip}

11장에서 파일을 쓰고 다시 읽어 원래 객체와 비교했다. 모양 바꾸기도 같은 방법으로 검사할 수 있다. 넓은 표를
긴 표로 바꾸었다가 다시 넓은 표로 되돌리면 원래 표와 같아야 한다.


::: {.callout-tip}
**예측해 보자**: `loans` 는 `loans_wide` 를 `pivot_longer()` 로 바꾼 표다. 되돌린 표는 `loans_wide` 와
`identical()` 하겠는가?

:::


```{r roundtrip}
back <- loans |> pivot_wider(names_from = 월, values_from = 대출권수)

identical(back, loans_wide)
identical(back, as_tibble(loans_wide))

```


첫 비교는 `FALSE` 다. 값이 다른 것이 아니다. `read_csv()` 는 읽은 표에 "어떻게 읽었는지"에 대한 정보(열 유형
명세)를 속성으로 붙여 두는데, 되돌린 표에는 그 속성이 없다. `identical()` 은 속성까지 비교한다. `as_tibble()` 로
그 속성을 떼면 `TRUE` 다. 내용은 그대로라는 뜻이다. `values_drop_na = TRUE` 로 만든 긴 표도 되돌리면 빈칸이
`NA` 로 되살아나 같은 결과가 나온다.


```{r roundtrip-drop-na}
loans_dropped |>
  pivot_wider(names_from = 월, values_from = 대출권수) |>
  identical(as_tibble(loans_wide))

```


반대로 `loans_ym` 처럼 열 이름을 나누고 수로 바꾼 표는 되돌려도 원래 표가 되지 않는다.


```{r roundtrip-ym}
back_ym <- loans_ym |> pivot_wider(names_from = 월, values_from = 대출권수)

names(back_ym)

```


열 이름이 `"1"` 부터 `"8"` 이 되고 `연도` 열이 생겼다. 왕복 검사가 실패했다고 틀린 것은 아니다. **무엇이
바뀌었는지** 알고 의도한 변화인지 판단하면 된다.


### 한 열을 나누고 합치기 {#sec-separate}

값 하나에 여러 정보가 붙어 있을 때 `separate_wider_delim()` 으로 나눈다. `delim` 은 정규표현식이 아니라 **글자
그대로**의 구분자다.


```{r separate-wider}
loans_split <- loans |>
  separate_wider_delim(월, delim = ".", names = c("연도", "월"))

loans_split |> head(3)

```


나눌 값의 형식이 섞여 있으면 어떻게 될까? 점과 줄표가 섞인 두 값을 나누어 보자.


```{r separate-wider-error}
tibble(월 = c("2026.01", "2026-02")) |>
  separate_wider_delim(월, delim = ".", names = c("연도", "월"))

```


조각이 모자란 값이 있다고 멈추고, `too_few = "debug"` 로 원인을 볼 수 있다고 알려 준다. 예전 함수 `separate()` 는
같은 상황에서 경고만 내고 빈 조각을 `NA` 로 채운 결과를 돌려주었다. tidyr 1.3.0 부터 `separate()` 는
`separate_wider_delim()`, `separate_wider_position()`, `separate_wider_regex()` 로 대체되었다. 새 함수들은 **예상과 다른
값을 만나면 멈추는** 쪽을 택했다.

나눈 열을 다시 합칠 때는 `unite()` 를 쓴다.


```{r unite}
loans_split |> unite("연월", 연도, 월, sep = "-") |> head(3)

```


## 변환 절차 검증하기 {#sec-verify-transform}

지금까지 변환마다 **보존되어야 할 것**을 정하고 대조했다. 이 절에서는 그 대조를 모아 하나의 절차로 만든다.
목표는 "시도별 2026년 1~8월 총 대출권수와 인구 1만 명당 대출권수" 표다.


### 무엇이 보존되어야 하는가 {#sec-invariants}

변환에 따라 **변하지 않아야 할 양**을 불변량(invariant)이라 부른다. 이 장에서 쓴 불변량을 정리하면 다음과 같다.

| 변환 | 보존되어야 할 것 | 확인하는 방법 |
|:--|:--|:--|
| `filter()` 로 나누기 | 조각들의 행 수 합 = 원래 행 수 | `nrow()` 합 비교 (@sec-filter) |
| `mutate()`, `select()`, `arrange()` | 행 수 | 전후 `nrow()` |
| `summarise(.by = )` | 집단 합계의 합 = 전체 합계, 값이 있는 행의 수 | `sum()` 대조, `sum(!is.na())` (@sec-summarise-by) |
| 다대일 결합 | 행 수 = `x` 의 행 수, 짝 없는 행 없음 | `relationship`, `unmatched`, `anti_join()` (@sec-join-assert) |
| `pivot_longer()` | 행 수 = 원래 행 수 × 접은 열 수, 합계 | 왕복 검사 (@sec-pivot-roundtrip) |
| `bind_rows()` | 행 수 = 두 표의 행 수 합, 새 결측 없음 | `nrow()`, 결측 수 비교 |

: {tbl-colwidths="[24,40,36]"}

불변량이 깨졌다고 늘 틀린 것은 아니다. 새솔도서관처럼 **의도해서 뺀 행**이 있으면, 뺀 양을 따로 기록해 두고
"남은 것 + 뺀 것 = 원래"로 대조한다.


### 단계마다 대조하며 시도별 표 만들기 {#sec-step-checks}

요구사항을 먼저 문장으로 정한다.

- 시도별로 2026년 1월부터 8월까지의 대출권수를 합한다. 휴관한 달은 더할 대출이 없는 달로 본다.
- 인구 1만 명당 대출권수 = 총대출권수 ÷ 인구 × 10,000.
- 시도를 알 수 없는 도서관(새솔도서관)은 시도별 표에서 빼고, 뺀 대출권수를 따로 기록한다.
- 인구 표는 @sec-join-assert 에서 고친 `population_clean` 을 쓴다.


```{r step-unassigned}
# 1. 시도를 알 수 없는 도서관의 대출은 따로 기록한다
unassigned <- loans |>
  anti_join(libraries, by = "도서관ID") |>
  summarise(도서관수 = n_distinct(도서관ID),
            대출권수 = sum(대출권수, na.rm = TRUE))

unassigned

```


```{r step-join-sido}
# 2. 대출에 시도를 붙인다
#    도서관 하나는 시도 하나(다대일)
#    기본 정보의 모든 도서관은 대출 자료가 있어야 한다(y 의 짝 없는 행은 오류)
#    기본 정보에 없는 도서관(x 의 짝 없는 행)은 1단계에서 기록했으므로 뺀다
loans_sido <- loans |>
  inner_join(sido_key, by = "도서관ID",
             relationship = "many-to-one", unmatched = c("drop", "error"))

c(원래 = nrow(loans), 결합후 = nrow(loans_sido),
  뺀행 = nrow(anti_join(loans, libraries, by = "도서관ID")))

```


```{r step-summarise-rate}
# 3. 시도별로 합하고 인구를 붙인다(시도 하나에 인구 하나)
sido_rate <- loans_sido |>
  summarise(총대출권수 = sum(대출권수, na.rm = TRUE),
            도서관수 = n_distinct(도서관ID),
            .by = 시도) |>
  inner_join(population_clean, by = "시도",
             relationship = "one-to-one", unmatched = c("error", "drop")) |>
  mutate(만명당 = 총대출권수 / 인구 * 10000) |>
  arrange(desc(만명당))

sido_rate |> select(시도, 도서관수, 총대출권수, 인구, 만명당)

```


결과가 그럴듯한지 보기 전에 불변량을 대조한다.


```{r step-invariants}
c(시도_행 = nrow(sido_rate),
  기본정보_시도 = n_distinct(libraries$시도),
  도서관_합 = sum(sido_rate$도서관수))

c(시도표_합계 = sum(sido_rate$총대출권수),
  미배정 = unassigned$대출권수,
  전체 = sum(loans$대출권수, na.rm = TRUE))

```


시도는 16행으로 기본 정보의 시도 수와 같고, 도서관 수의 합은 20이다. 시도별 합계 4,808,051권과 미배정
33,287권을 더하면 전체 4,841,338권이다. 대출이 빠지거나 두 번 세어진 곳이 없다.


### 검증을 코드로 남기기 {#sec-transform-assert}

대조를 매번 눈으로 하지 않도록 함수로 만든다. 11장의 `check_loans()` 와 같은 방식이다. `stopifnot()` 에 조건마다
이름을 붙이면 실패할 때 **어느 가정이 깨졌는지** 문장으로 알려 준다.


```{r check-function}
check_sido_rate <- function(result, loans, libraries) {
  unassigned <- loans |> anti_join(libraries, by = "도서관ID")
  stopifnot(
    "시도는 한 행에 하나다" = !anyDuplicated(result$시도),
    "시도 수가 기본 정보의 시도 수와 같다" =
      nrow(result) == n_distinct(libraries$시도),
    "인구가 빠진 시도가 없다" = !anyNA(result$인구),
    "시도별 합계와 미배정 대출의 합이 전체 대출과 같다" =
      sum(result$총대출권수) + sum(unassigned$대출권수, na.rm = TRUE) ==
        sum(loans$대출권수, na.rm = TRUE)
  )
  invisible(TRUE)
}

check_sido_rate(sido_rate, loans, libraries)

```


아무것도 출력하지 않고 끝났다. 네 조건을 모두 통과했다. 이제 고치기 **전의** 인구 표로 같은 표를 만들어 함수가
결함을 잡는지 확인한다. 검증 함수도 코드이므로, 틀린 입력에서 실제로 멈추는지 확인해야 믿을 수 있다.


```{r check-function-fails}
broken <- loans_sido |>
  summarise(총대출권수 = sum(대출권수, na.rm = TRUE), .by = 시도) |>
  left_join(population, by = "시도") |>
  mutate(만명당 = 총대출권수 / 인구 * 10000)

check_sido_rate(broken, loans, libraries)

```


첫 번째 조건에서 멈췄다. `stopifnot()` 은 처음 실패한 조건만 알려 주므로, 중복을 고치면 다음 조건(인구 결측)에서
다시 멈춘다. 결함이 여러 개일 수 있다는 뜻이다.


## AI와 함께: 데이터 변환 코드의 검증 {#sec-ai-handling}

### AI 가 생성한 코드 {#sec-ai-handling-gen}

응답은 처리 순서를 여섯 단계로 먼저 설명하고 코드를 내놓았다. 코드 안에 **결과를 확인하는 줄을 두 곳** 넣었고,
끝에 세 가지를 꼭 확인하라고 조언했다.

1. 휴관한 달의 빈칸을 0 으로 보고 합산했으니 그 가정이 맞는지 확인할 것 (@sec-na-summary 의 논의와 같다).
2. 도서관ID 결합 뒤 시도가 `NA` 인 행이 없는지 확인할 것. 있다면 두 파일의 도서관ID 표기가 맞지 않는 것이다.
3. 인구 표는 다른 기관 자료이므로 시도 표기가 다를 수 있다. 특히 **강원도/강원특별자치도, 전라북도/전북특별자치도**
   처럼 최근 명칭이 바뀐 지역을 의심하고, `setdiff()` 로 찾아 맞출 것.

세 번째 조언은 앞 4행에는 보이지 않는 결함을 정확히 짐작했다. 응답 전문은
`ai-transcripts/12-data-handling/sido-loans-per-capita.md` 에 있다.

아래는 응답의 코드다. 학생의 컴퓨터에서는 파일이 작업 디렉터리에 바로 있었지만, 이 강의노트는 저장소 폴더에서
렌더되므로 **파일 경로 세 곳에 `dataset/ch12/` 만 덧붙였다.** 나머지는 그대로다. 이 코드는 `libraries`, `loans` 같은
이름을 다시 쓰므로, 이 절에서 `loans` 는 **넓은 표**를 가리킨다.


```{r ai-generated}
# 생성: Claude Sonnet 5, 2026-09-17. 파일 경로 세 곳에 dataset/ch12/ 만 덧붙였고 나머지는 그대로 수록.
library(tidyverse)

# 1. 불러오기 ----------------------------------------------------------
libraries <- read_csv("dataset/ch12/libraries.csv")
loans     <- read_csv("dataset/ch12/loans-2026.csv")
sido_pop  <- read_csv("dataset/ch12/sido-population.csv")
# 한글이 깨져서 보이면 locale = locale(encoding = "EUC-KR") 옵션을 추가해서 다시 읽어보세요.

# 2. 대출권수 wide -> long ------------------------------------------------
loans_long <- loans |>
  pivot_longer(
    cols      = starts_with("2026"),   # "2026.01" ~ "2026.08"
    names_to  = "월",
    values_to = "대출권수"
  )
# 빈칸(휴관)은 read_csv가 자동으로 NA로 읽어들입니다.

# 3. 도서관ID로 시도 붙이기 -----------------------------------------------
loans_sido <- loans_long |>
  left_join(libraries |> select(도서관ID, 시도), by = "도서관ID")

# 조인이 제대로 됐는지 확인 (아래 결과가 0행이어야 정상)
loans_sido |> filter(is.na(시도)) |> distinct(도서관ID)

# 4. 시도별 1~8월 총 대출권수 --------------------------------------------
sido_loans <- loans_sido |>
  group_by(시도) |>
  summarise(총대출권수 = sum(대출권수, na.rm = TRUE), .groups = "drop")
# na.rm = TRUE -> 휴관한 달(NA)은 0으로 보고 합산

# 5. 인구 결합 + 인구 1만 명당 대출권수 -----------------------------------
result <- sido_loans |>
  left_join(sido_pop, by = "시도") |>
  mutate(`대출권수_1만명당` = round(총대출권수 / 인구 * 10000, 1)) |>
  arrange(desc(`대출권수_1만명당`)) |>
  select(시도, 권역, 총대출권수, 인구, `대출권수_1만명당`)

# 인구를 못 찾은 시도가 있는지 확인 (아래 결과가 0행이어야 정상)
result |> filter(is.na(인구))

print(result, n = Inf)   # 시도 개수가 10개 넘으면 잘려 보이니 n = Inf로 전체 출력

```


오류도 경고도 없다. 두 확인 코드가 모두 "0행이어야 정상"인데 둘 다 행을 돌려주었으니, AI 의 기준으로도 아직 끝난
결과가 아니다.


### 검증 {#sec-ai-handling-verify}

**1단계: AI 의 확인 코드가 보여 준 것을 읽는다.**

첫 번째 확인은 `L21` 을 돌려주었다. AI 는 이런 경우를 "도서관ID 표기가 두 파일 사이에 안 맞는 것"이라고
설명했지만, @sec-row-unit 에서 보았듯 새솔도서관은 표기가 틀린 것이 아니라 **기본 정보 표에 아직 등록되지 않은
도서관**이다. 표기를 고쳐서 해결되는 문제가 아니므로 어떻게 다룰지 사람이 정해야 한다.

두 번째 확인은 세 행을 돌려주었다. 강원특별자치도와 전북특별자치도는 AI 가 짐작한 명칭 문제이고, 시도가 `NA` 인
행은 새솔도서관의 대출이다.

**2단계: 학생이 AI 의 조언대로 고친다.**

학생은 조언대로 `setdiff()` 로 다른 표기를 찾아 인구 표의 명칭을 바꾸고, 시도를 알 수 없는 행은 뺐다. 나머지
코드는 그대로 두었다.


```{r ai-student-fix}
setdiff(unique(libraries$시도), unique(sido_pop$시도))

sido_pop_fixed <- sido_pop |>
  mutate(시도 = replace_values(시도,
    "강원도" ~ "강원특별자치도",
    "전라북도" ~ "전북특별자치도"
  ))

result_student <- sido_loans |>
  left_join(sido_pop_fixed, by = "시도") |>
  mutate(`대출권수_1만명당` = round(총대출권수 / 인구 * 10000, 1)) |>
  arrange(desc(`대출권수_1만명당`)) |>
  select(시도, 권역, 총대출권수, 인구, `대출권수_1만명당`) |>
  filter(!is.na(시도))

result_student |> filter(is.na(인구))

```


인구를 못 찾은 시도가 없다. AI 가 준 확인을 모두 통과했다.

**3단계: 불변량으로 대조한다.**

@sec-transform-assert 의 `check_sido_rate()` 는 결과표에 `시도`, `총대출권수`, `인구` 열이 있으면 쓸 수 있다. AI 코드의
결과표도 같은 이름을 쓴다. 대출 표는 AI 코드의 긴 표 `loans_long` 을 넘긴다.


```{r ai-check-fails}
check_sido_rate(result_student, loans_long, libraries)

```


첫 번째 조건에서 멈췄다. 어느 시도가 두 번 나오는지, 합계는 얼마나 다른지 확인한다.


```{r ai-find-duplicate}
result_student |> count(시도) |> filter(n > 1)

c(결과표_합계 = sum(result_student$총대출권수),
  전체_대출 = sum(loans_long$대출권수, na.rm = TRUE),
  미배정 = sum(loans_long$대출권수[loans_long$도서관ID == "L21"], na.rm = TRUE))

```


결과표 맨 위의 세종특별자치시가 **두 행**이다. 인구 표의 세종 중복 행이 시도별 요약표와 결합되면서 한 행이 더
생겼다. 결과표의 합계는 5,129,797권으로, 전체 대출에서 미배정분을 뺀 4,808,051권보다 세종의 총대출권수
321,746권만큼 많다. 표를 위에서부터 읽으면 1위와 2위가 같은 값이라 눈에 띌 법도 하지만, 순위표에서는
"공동 1위"처럼 보여 지나치기 쉽다.

이 결함은 왜 AI 의 두 확인을 통과했을까? 두 확인은 모두 **결측값을 찾는** 확인이다. 중복된 행은 결측값을 만들지
않는다. 그리고 @sec-join-rows 에서 본 것처럼, `x` 쪽 키(시도별 요약표의 시도)가 한 번씩만 나오면 dplyr 은 행이
늘어나도 경고하지 않는다.


### AI 가 보지 못한 부분 {#sec-ai-handling-gaps}

| 자료의 결함 | 파일에서의 위치 | AI 응답 | 드러낸 대조 |
|:--|:--|:--|:--|
| 인구 표의 이전 명칭(강원도, 전라북도) | 인구 표 11행, 14행 | 명칭 변경 가능성을 짚고 확인 코드를 줌 | 인구 결측 확인, `anti_join()` |
| 기본 정보에 없는 신규 도서관(L21) | 대출 표 21행 | 확인 코드로 드러났으나 원인을 표기 불일치로 설명 | `anti_join()`, 미배정 기록 |
| 인구 표의 세종 중복 행 | 인구 표 8행, 9행 | 다루지 않음. 두 확인을 모두 통과 | 키 중복 확인, 합계 대조 |

: {tbl-colwidths="[27,20,29,24]"}

응답은 좋은 응답이었다. 처리 순서를 설명했고, 확인 코드를 넣었고, 휴관한 달을 0 으로 보는 가정이 **결정**이라는
점과 명칭 변경이라는 실제 결함을 짚었다. 명칭 변경은 행정구역에 대한 **일반 지식**으로 짐작할 수 있는 결함이다.
그러나 인구 표 8행과 9행이 같은 행이라는 사실은 어떤 지식으로도 짐작할 수 없다. **파일을 보아야** 안다.

AI 가 써 준 확인 코드는 AI 가 떠올린 결함만 확인한다. 그 확인을 통과했다는 것은 **그 결함이 없다**는 뜻이지 결과가
맞다는 뜻이 아니다. 불변량은 어떤 결함인지 몰라도 결과의 **구조**를 확인한다. 시도는 한 번씩 나와야 하고, 합계는
보존되어야 한다. 중복이든 누락이든 이 등식을 깬다.

응답의 코드를 최소한으로 고친다. 인구 표의 중복과 명칭을 고치고, 두 결합에 관계와 짝에 대한 가정을 적고, 새솔도서관을
빼는 결정을 코드에 드러낸다.


```{r ai-fixed}
# 수정: 인구 표 중복 제거와 명칭 변경, 두 결합에 relationship 과 unmatched 명시,
#       기본 정보에 없는 도서관은 inner_join 으로 빼고 check_sido_rate() 에서 미배정으로 대조
sido_pop_ok <- sido_pop |>
  distinct() |>
  mutate(시도 = replace_values(시도,
    "강원도" ~ "강원특별자치도",
    "전라북도" ~ "전북특별자치도"
  ))

result_ok <- loans_long |>
  inner_join(libraries |> select(도서관ID, 시도), by = "도서관ID",
```
