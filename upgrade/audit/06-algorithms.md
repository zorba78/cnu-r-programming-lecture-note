## A. 치명 — 코드가 본문과 반대로 동작

### A-1. `1:5*n` 연산자 우선순위 — Big-O 예제 3개의 정답이 전부 틀림

**줄** 407, 457, 497 (`bigo_case2`, `bigo_case3`, `bigo_case5`) · **초안** 해소됨

R에서 `:`가 `*`보다 우선하므로 `1:5*n`은 `(1:5)*n`, 즉 **길이 5짜리 벡터**다. `1:(5*n)`이 아니다.

```
bigo_case2 실제 반복: n=10 → 5회,  n=100 → 5회,  n=1000 → 5회
  본문 주장: O(5n) = O(n)          실제: 5회 고정 = O(1)
bigo_case5 실제 반복: n=10 → 50회, n=100 → 500회
  본문 주장: O(n × 5n) = O(n²)     실제: O(n)
```

계수 법칙·합의 법칙·곱의 법칙 세 절의 예제가 모두 이 코드에 의존하므로, **Big-O 규칙을 가르치는 절 전체의 결론이 거짓**이다. 하필 이 장이 "연산 횟수를 세어 복잡도를 판단한다"를 가르치는 장이라는 점에서 특히 나쁘다.

**수정**: `for (i in 1:(5 * n))`. 나아가 이 버그 자체를 새 6장(정확성·디버깅·검증)의 교재로 쓸 것을 권한다. 괄호 하나가 복잡도를 O(n)에서 O(1)로 바꾸는 실물 사례다.

### A-2. `rbinary_search()`가 입력의 절반을 찾지 못함

**줄** 827–847 (특히 831) · **초안** 해소됨

탈출 조건 `if (maxL <= minL) return(NULL)`이 **원소 하나 남은 구간을 검사 없이 버린다**. `maxL < minL`이어야 한다.

```
벡터 seq(1, 40, by = 3), 14개 원소 중 7개를 못 찾음: 4, 10, 16, 22, 28, 34, 40
실패율 50%
```

같은 절의 반복문 버전 `binary_search()`는 `while (minL <= maxL)`로 올바르다. 즉 **같은 절 안에서 두 구현이 서로 다른 알고리즘**이다.

**가장 위험한 점**: 본문 예제가 `set.seed(2)`로 k=13을 뽑는데 이 값이 우연히 홀수 위치라 성공한다. 렌더된 노트에서는 버그가 보이지 않는다. 예제가 통과했다는 것이 정확성의 근거가 될 수 없음을 보여주는 사례다.

**수정**: `if (maxL < minL) return(NULL)`.

### A-3. `newton_raphson()` — 정의되지 않은 객체 참조와 죽은 경고

**줄** 1497–1538 · **초안** 해소됨

세 결함이 겹쳐 있다.

1. 첫 `gap`이 잔차가 아니라 $x_1$ 값 자체다(1509줄). `while` 조건이 해의 크기를 검사하므로, 해가 0 근처면 루프가 한 번도 돌지 않고 1524줄에서 `object 'x_new' not found` 오류로 죽는다.
2. 루프 조건이 `iters < max_iters`이므로 종료 후 `iters > max_iters`는 **결코 참이 될 수 없다**. "최대 반복까지 해를 찾지 못했습니다" 경고는 구조상 절대 발동하지 않는 죽은 코드다.
3. 본문 1478줄은 "초기값이 범위를 벗어나면 함수 종료"라고 명시하지만 구현에 그 검사가 없다. 대신 매 반복마다 해를 범위로 클램프해 경계에 가둔다.

**수정**: 초안처럼 도함수를 인수로 받고, 잔차 `abs(f(x))`로 수렴을 판정하며, 수렴 여부와 사유를 함께 반환하는 구조로 재작성.

### A-4. Big Θ를 "평균"이라고 설명

**줄** 235–238 · **초안** 해소됨(해당 서술 삭제)

> 예: Big $\Omega$ (하한), Big $\Theta$ notation (평균)

Θ는 평균이 아니라 **상한과 하한이 동시에 성립하는 조임 한계**다. 평균 사례 분석과 점근 표기법은 서로 독립된 축이다. 점근 표기법을 처음 배우는 학생에게 정의 자체를 틀리게 가르치는 문장이다.

**수정**: "Big Θ(상한과 하한이 같은 경우)". 또는 초안처럼 Ω·Θ 언급을 빼고 O 하나에 집중.

### A-5. 복잡도 비교 표의 수치·표기 오류

**줄** 305–333 · **초안** 해소됨(표 삭제, 연산 횟수 직접 세기로 대체)

- 지수 표기가 깨짐: `1.27E10+30`, `9.33E10+157` (E와 +가 겹침, 각각 `1.27E+30`, `9.33E+157`이어야 함)
- `n log n` 열이 자연로그 기준(N=100일 때 461)인데 본문의 다른 절은 모두 $\log_2$를 쓴다. $\log_2$ 기준이면 664다.
- N=1 열의 여러 칸이 부정확

### A-6. 나눗셈 연산자를 역슬래시로 표기

**줄** 141 · **초안** 해소됨

> 사칙연산(`+`, `-`, `*`, `\`)

`\`가 아니라 `/`다. 게다가 R 4.1부터 `\(x)`는 익명 함수 단축 표기이므로, 입문자에게 혼동을 일으킨다.

### A-7. 자모 오타 5건

**줄** 153, 183, 217, 778, 1301 · **초안** 해당 없음

재햘당→재할당, 내에세→내에서, 상상→항상, 측소→축소, 끈→큰.

### A-8. 닫히지 않은 따옴표

**줄** 254 · **초안** 해당 없음

`$f(x)$은 $g(x)$의 **big-oh"** 라고 읽는다` — 여는 따옴표가 없어 마크다운 강조가 깨진다.

| 뉴턴-랩슨 인수 검증(`tol=0`, `max_iter=0`) | 정상 오류 |

**치명 버그 패턴 잔존 검사**: `1:5*n` 0건, `maxL <= minL` 0건, Θ=평균 0건, 지수 표기 오타 0건, 죽은 외부 링크 0건. 전부 해소.

**초안이 잘한 점**

- `binary_search`가 입력을 검증하고 `NULL` 대신 `NA_integer_`를 반환한다.
- 정렬 결과를 `identical(insertion_sort(x), sort(x))`로 대조한다. 원본에 없던 검증 습관이다.
- 불변식(invariant) 개념을 도입해 "왜 올바른가"를 설명한다.
- 이진 탐색의 고전적 오프바이원 오류를 `rmdcaution`으로 명시한다.
- 뉴턴-랩슨 절이 "실행되었다 ≠ 의도한 해를 찾았다"를 직접 가르치고, `uniroot()`와 교차 검증한다.
- 외부 링크 의존을 제거했다.

**초안에 남은 항목**

1. **정렬 함수의 NA 처리** (B-11 부분). `insertion_sort(c(1, NA, 2))`가 `missing value where TRUE/FALSE needed`로 죽는다. `binary_search`는 입력 검증을 넣었으므로 정렬에도 같은 처리를 하면 일관된다. 다만 NA 처리를 연습문제로 남기는 것도 교육적으로 타당하다.
2. **정렬 2종 선택**은 삽입 + 병합으로 확정됐다. 재구성안의 "4종 → 2종" 방침에 맞고, 조합도 합리적이다. 삽입은 불변식과 최선/최악 대비를, 병합은 분할정복과 O(n log n)을 가르친다. 버블은 삽입과 교육 내용이 겹치고, 퀵은 무작위 피벗 때문에 복잡도 설명이 까다롭다.

## F. 작업 순서

1. **현 6장의 치명 버그 3건(A-1·A-2·A-3)을 지금 고친다.** 초안이 본문에 반영되기 전까지 공개 사이트에 그대로 남아 있고, 학생이 지금 읽고 있을 수 있다. 각 20분 이내.

4. D 항목(다른 장으로 번지는 문제)은 장별 감사 때 일괄 처리한다.
5. 초안의 NA 처리 방침을 정한다(구현에 넣을지, 연습문제로 남길지).

## G. 이 감사가 남긴 교재

발견 자체가 새 6장(정확성·디버깅·검증)의 실물 교재가 된다. 특히 **A-2**는 이상적이다. 예제가 `set.seed(2)` 덕분에 우연히 통과해 렌더된 노트에서 정상으로 보이지만, 전수 검사를 하면 입력의 절반에서 실패한다. "예제가 통과했다"와 "코드가 맞다"가 다른 말임을 이보다 잘 보여주는 사례를 만들어 내기 어렵다. **A-1**은 괄호 하나가 복잡도를 O(n)에서 O(1)로 바꾸는 사례로, 코드를 읽을 때 무엇을 의심해야 하는지 가르친다.
