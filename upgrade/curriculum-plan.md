# 교과 재구성안 — 프로그래밍 입문 강화

작성 2026-09-10 · 대상 학부 2학년 정보통계학과 · 상태 **제안(미확정)**

## 1. 문제 제기 (강사)

> 지금 내용들은 기초적인 구문 내용이 많아서 과거에 R을 처음 접하는 학생들에게 많은 도움을 줄 수 있었던 내용들이었으나, 지금은 학생들이 이것들을 굳이 알아야 할까라는 의문도 생김. 그리고 학부 2학년 대상 강의라서 프로그래밍에 대한 기초 개념(대부분 학생이 이 강의를 통해 프로그래밍에 입문함) 부분을 강화할 필요가 있음.

## 2. 진단

노트 전체 21,411줄, 코드 청크 814개. 분포를 보면 문제가 드러난다.

| 장                   | 줄 수 | 청크 | 성격                        |
|----------------------|------:|-----:|-----------------------------|
| 02 R 객체            | 4,162 |  185 | R 자료구조 **문법 사전**    |
| 11 데이터 시각화     | 3,903 |  167 | 함수·파라미터 **전수 나열** |
| 10 데이터 핸들링     | 2,530 |   98 | dplyr 동사 사전             |
| 07 시뮬레이션        | 1,934 |   51 | 개념 중심                   |
| 06 알고리즘          | 1,575 |   25 | 개념 중심                   |
| 03 문자열·정규표현식 | 1,301 |   59 | 문자열 함수 사전            |
| 05 제어문·함수       | 1,232 |   59 | 개념 + 문법 혼재            |

반대편을 세어 보면 이렇다. 노트 전체에서 **디버깅 2회, `traceback` 0회, `tryCatch` 0회, `testthat` 0회**. 오류를 읽고 고치는 방법, 코드가 맞는지 확인하는 방법이 사실상 없다.

즉 지금 노트에서 "기초"라고 불리는 것의 대부분은 **개념이 아니라 문법 레퍼런스**다. 프로그래밍 개념(이름과 값, 평가, 추상화, 상태, 정확성)은 문법 설명 사이에 흩어져 있거나 아예 없다.

**따라서 "구문을 줄이는 것"과 "개념을 강화하는 것"은 대립하지 않는다.** 같은 작업의 양면이다. 문법 사전을 본문에서 걷어내면 그 자리가 개념 자리가 된다.

## 3. 핵심 판단

**LLM이 대체한 것은 "구문을 기억하는 일"이지 "코드가 무엇을 하는지 이해하는 일"이 아니다.**

- `paste()`의 인수 순서를 외우는 일은 이제 가치가 없다. AI가 즉시 채운다.
- 그런데 AI가 만든 코드를 받아들일지 말지 판단하려면 개념 이해가 **더** 필요하다. `group_by()` 뒤에 `ungroup()`이 빠졌는지, `NA`가 조용히 전파됐는지, 벡터 재활용 규칙이 의도치 않게 작동했는지는 개념을 모르면 보이지 않는다.
- /2학년 입문자가 막히는 지점은 함수 이름이 아니다. 변수가 무엇인지, 왜 함수를 만드는지, 왜 결과가 예상과 다른지다.

동시에 이런 학생들에게 가장 흔한 실제 행위는 **코드를 쓰는 것이 아니라 읽는 것**이다. AI가 생성한 코드를 읽고 판단한다. 지금 노트는 쓰는 법만 가르친다.

## 4. 설계 원칙: PRIMM을 축으로

각 절을 **예측 → 실행 → 조사 → 수정 → 제작** 순서로 구성한다. 컴퓨터과학 교육에서 검증된 입문자 교수법(PRIMM)이고, **AI 코드를 검증하는 동작과 정확히 같다.** 하나의 장치로 두 목표를 동시에 만족시킨다.

| 단계 | 학생 활동 | 이 강의에서의 의미 |
|------------------------|------------------------|------------------------|
| 예측(Predict) | 실행 전에 결과를 적는다 | 개념 이해를 강제. 가장 싸고 효과가 큰 장치 |
| 실행(Run) | 돌려서 예측과 대조 | 틀린 예측이 학습의 출발점 |
| 조사(Investigate) | 왜 그런지 추적한다 | 오류 메시지 읽기, 값 확인, 최소 재현 |
| 수정(Modify) | 조건을 바꿔 본다 | 경계 사례, 반례 |
| 제작(Make) | 명세로부터 새로 만든다 | 여기서 AI를 써도 좋다. 단 검증 필수 |

기존 노트의 청크는 대부분 "코드 → 출력 → 설명" 순서다. 이를 "질문 → 예측 → 코드 → 대조 → 설명"으로 바꾸는 것이 개정의 기본 동작이다.
