# 새 13장 데이터 시각화 (data-visualization) 결정 사항과 가정

강사 지시 (2026-10-16): "데이터 시각화 및 기초통계 분석 강의노트 업데이트 및 발표 슬라이드 생성. 노트 및 발표 슬라이드 모두에서 추상적인 표현은 하지 말 것." 작업 규칙 11(멋 부린 표현 금지)은 이 장의 모든 산출물에서 반려 사유다.

## 오케스트레이터가 정한 가정

- 장 번호와 제목은 재구성안 5절 표를 따른다: 새 13장 데이터 시각화, 출처 현행 `11-data-visualization.Rmd`.

- 감사(1단계)의 강사 확인 9건에 대해 설계 단계는 다음 가정으로 진행한다. 강사가 다르게 정하면 설계서와 원고를 고친다.
  1. 현 11장 핫픽스는 하지 않는다(8·9·12장과 같이 새 장 공개로 갈음). 치명 3건은 새 장의 예측·버그 찾기 문항으로 쓴다.
  2. COVID-19 확장 예제(2020-06 스냅샷, OWID 저장소 보관 처리)는 새 장에 싣지 않는다. 통합 사례는 Gapminder 로 바꾼다.
  3. Gapminder 는 12장과 정의를 맞춰 `dataset/ch12/` 의 파일(2000~2020)을 그대로 쓴다. `dataset/gapminder/gapminder_filter.csv` 는 쓰지 않는다.
  4. 노트 분량은 2,400줄 안팎을 목표로 기본 그래픽 본문을 줄인다. `par()` 해부, 도형 함수, 수식 표현은 부록 B 몫으로 두고 이번에는 설계서에 목록만 남긴다(부록 파일은 만들지 않는다).
  5. `ggarrange()` 는 `patchwork` 로 바꾼다.
  6. 그림 글자는 한국어 라벨을 쓰되 글꼴 패키지(`showtext`, `ragg`)는 도입하지 않는다. 렌더 환경의 기본 글꼴로 한글이 깨지면 그때 결정한다.
  7. 신뢰구간 시뮬레이션 예제는 새 9장 참조로 대체한다.
  8. "AI 와 함께" 절 과제는 감사 G-6 의 1번(Gapminder 2015년 거품 그림)으로 한다.
  9. `palmerpenguins` 는 도입하지 않는다. 결측 행 검증은 `airquality` 와 Gapminder 로 한다.

### 1단계 감사에서 (2026-10-16, `upgrade/audit/11-data-visualization.md`)

1. **공개 사이트(현 장, 사이트 10장)의 치명 3건을 지금 고칠지.** A-1 정규분포 곡선의 σ 표기(1485·1491·1497, 실제 표준편차 √2·√3), A-2 COVID 기준 불일치(본문 2,000명 이상, 코드 `> 1000`, 순위 그림 24개 중 11개가 기준 밖), A-3 "모분산을 안다"는 신뢰구간이 표본 표준편차와 z 분위수를 섞음(이론 포함률 94.0%). A-3 은 수치 영향이 작아 B 로 낮출 수 있다. 다시 렌더하면 2065–2069 청크가 추적 파일 `figures/save-example.png` 를 다시 쓸 수 있다.
2. **COVID-19 확장 예제(3614–3893)를 남길지.** 자료는 2020-06-01 스냅샷이고 OWID 저장소는 2026-03-24 보관 처리되었다(마지막 갱신 2024-08-19). 남기면 시점을 명시하고 "그래프 검증 통합 사례"(기준 불일치, 겹친 막대, 92번 겹친 글자, 0 대체 후 제외)로 쓴다. 바꾸면 12장 Gapminder 통합 사례를 그림으로 잇는다.
3. **Gapminder 자료를 무엇으로 할지.** 현 장은 `dataset/gapminder/gapminder_filter.csv`(1950–2020, 생성 스크립트 없음, `dataset.zip` 에 없음), 새 12장은 `dataset/ch12/gapminder-*.csv`(2000–2020, `make-gapminder-data.R`). 1950년부터의 기대수명 추세선 예제를 살리려면 12장 추출 범위를 넓히거나 13장 자료 스크립트를 따로 둔다.
4. **기본 그래픽의 본문 분량.** 제안은 약 560줄(도입·장치 140, 고수준 함수 300, 덧그리기·그래픽 상태 200, 저장 일부)이고 `par()` 파라미터 해부, `arrows`·`rect`·`mtext` 해부, 수식 표·그리스 문자는 부록 B 로 옮긴다. 장 전체 제안 합계는 약 2,520줄로 목표 2,400줄보다 120줄 많다.
5. **여러 그림 배치 패키지.** 현 장은 `ggpubr::ggarrange()` 14회. `patchwork`(1.3.2 설치 확인)로 바꿀지.
6. **한글 글꼴 방식.** 현 장의 `par(family = "nanumgothic")` 은 운영체제마다 다르게 동작한다(이 리눅스 png 에서는 정상, pdf 장치 경고 33건, Windows 는 등록 필요[추론]). `showtext` 와 `ragg`+`systemfonts` 중 하나를 정해 학생 Windows·Positron 환경 안내를 한 곳에 둔다.
7. **신뢰구간 시뮬레이션(2822–2860)을 13장에 둘지.** 9장 `#sec-ci-meaning` 과 같은 주제라 참조로 대체하고 13장에는 `geom_linerange()`/`geom_pointrange()` 사용법만 남기는 안을 제안했다.
8. **"AI와 함께" 과제 후보 선택.** (1) Gapminder 2015 거품 그림(로그 축, 면적 비례 크기), (2) iris 세 종 분포 겹쳐 그리기(기본 쌓기), (3) COVID 대륙별 일일 확진자(쌓기 대 겹치기). 흔한 오류는 실제 응답으로 확인한 뒤에만 싣는다.
9. **`palmerpenguins` 도입 여부.** 결측과 종 간 겹침이 있어 "빠진 행"과 쌓기 교재로 쓸 수 있다(설치 확인). 내장 자료만 쓸지 정한다.

5. **car·vioplot 미사용.** `car::scatterplot`·`scatterplotMatrix` 는 `plot()` 산점도 행렬로, `vioplot` 은 `geom_violin()` 으로 대신한다(이전 판의 모의 자료는 살림). 가정: 빼기.

### 3단계 집필에서 (묶음 1: 머리, 1~3절, 2026-10-16, `13-data-visualization.qmd`)

1. **3.2 소절이 187줄이다**(설계 약 80줄, 설계서의 소절 상한 100줄). 설계서가 정한 내용(영역 그림 2개, 여백 순서, `mfrow` 제목 예측과 `mfcol` 대조, 한 청크 오류 재현, 새 장치 대조, 이전 판 사례, `op`/`on.exit()`)을 모두 넣으면 100줄 안에 들어가지 않는다. 제안: "3.2 그림 영역과 칸 나누기 `{#sec-plot-regions}`"(영역, 여백, `mfrow`/`mfcol`)와 "3.3 그래픽 상태 `{#sec-graphics-state}`"(화이트보드 예, 오류 재현, 되돌리기)로 나눈다. 앵커 `#sec-graphics-state` 는 그대로 남는다. 가정: 구조를 바꾸지 않고 설계대로 둠. 2.1(122줄)도 상한을 넘는다.
2. **분량.** 머리~3절이 약 1,000줄이다(설계 약 670줄). 청크 앞뒤 빈 줄 두 줄은 12장 서식을 따랐고 빈 줄 비율(32%)은 12장(38%)보다 낮다. 같은 비율이면 장 전체가 목표 2,430줄을 넘을 수 있다. 가정: 내용을 빼지 않음.
3. **이전 판 코드의 철자.** 3.2 의 `mfrow` 예측 문항은 이전 판 코드를 그대로 실었고, 제목 문자열의 철자 "Muptiple" 만 "Multiple" 로 고쳐 본문에 밝혔다. 버그 대상인 `mfrow = c(2, 3)` 과 되돌리지 않는 `par()` 는 원문 그대로다.
4. **모자이크 그림의 바꾼 점.** 타이타닉 성별·생존 그림은 `shade = TRUE`(로그선형모형 잔차 색, 설명 콜아웃을 옮기지 않기로 함) 대신 고정 색을 쓰고, 이전 판이 손으로 좌표를 넣던 빈도 글자 대신 표를 출력한다. UC Berkeley 학과별 그림은 표를 전치해 가로 폭이 성별 지원자 수, 세로 높이가 합격 비율이 되게 했다(이전 판은 합격 여부가 먼저).
5. **그림 속 자료 값.** 축 제목·그림 제목은 한국어로 썼으나 자료에 든 수준 이름(Male/Female, Yes/No, Admitted/Rejected, setosa 등)과 `plot(lm)` 의 패널 제목은 영어로 남았다. 가정: 자료 값은 바꾸지 않음.
6. **points() 예제.** 대응표의 "points() (cars, iris) → 3.1, legend() 예와 합쳐 하나로"를 iris 한 예로 합쳤다. cars 의 `points()` 예는 싣지 않았다.

### 3단계 집필에서 (묶음 2: 4~5절, 2026-10-16)

1. **3.2 를 나눴다**(오케스트레이터 지시). "3.2 그림 영역과 칸 나누기 `{#sec-plot-regions}`"(113줄)와 "3.3 그래픽 상태 `{#sec-graphics-state}`"(80줄). 슬라이드의 절 번호도 3.2/3.3 으로 맞춘다.
2. **4.1 예측 문항의 답을 출력에 맞춰 고쳤다.** 설계서는 "VC 2 mg 평균 26.14 도 범위 위라 잘린다"고 했으나, `plot()` 이 y 범위에 4% 여유를 더해 `par("usr")` 가 12.72~26.57 이므로 26.14 는 범위 안이다. 잘리는 것은 0.5 mg 쪽(7.98)뿐이다.
3. **4.4 소절이 123줄이다.** 자료 준비 청크 `gm-prepare`(대응표 22행 포함 약 40줄)가 이 소절에 있기 때문이다. 가정: 설계대로 두고, 나눈다면 "자료 준비"를 4.4 앞의 짧은 소절로 뺀다.
4. **5.1 의 차급별 시내 연비 평균 막대(`geom_col()`)는 따로 싣지 않았다.** `geom_col()` 과 가로 막대(`aes(y = )`)는 2015년 지역별 1인당 GDP 중앙값 그림 하나로 보였다(분량 상한 660줄).
5. **오케스트레이터 필수 항목 중 mpg 실린더 점 33개(설계 6.3)와 iris 히스토그램 쌓기·밀도판 넓이 3(설계 6.2)은 설계서대로 6절(묶음 3)에 둔다.** `after_stat(density)` 와 이전 판 `..density..` 코드의 경고는 5.2 에 실었고, 이전 판 iris 그림 자체는 6.2 에서 보인다.

### 3단계 집필 재개 (6~9절·연습문제, 2026-10-16, Codex)

1. **작성 주체.** Claude 세션 중단 이후 Codex가 기존 1~5절을 보존하고 남은 6~9절과 연습문제를 작성했다. Claude 모델을 호출하거나 응답 출처를 바꾸지 않았다. AI 절은 별도 4단계로 남겼다.
2. **히스토그램의 빈 구간.** 실행 결과 `sum(ymin > 0)`은 높이 0인 빈 구간까지 세어 23이다. 실제 높이가 있는 쌓인 막대 3개를 세도록 `ymin > 0 & count > 0`을 사용했다. 밀도 막대 넓이 합은 3이다.
3. **연습 W2의 답.** 시내 연비 `ylim(10, 25)`는 13행을 제외하지만 모든 차급 중앙값은 그대로이다. 문항에 "없으면 없음"을 덧붙여 중앙값 변화가 있어야 한다는 전제를 없앴다. 본문의 고속도로 연비 제한은 29행을 제외하며 midsize 27→26, suv 17.5→18을 확인했다.
